

# 🧠 `<Link>` in React Router

## 📌 정의

`<Link>`는 React Router에서 **클라이언트 사이드에서 페이지 이동을 수행하는 컴포넌트**입니다. 전통적인 `<a href="...">`와 달리, 페이지 전체를 새로고침하지 않고 `history.pushState()`를 통해 URL을 변경하며 라우트를 전환합니다.

```jsx
import { Link } from 'react-router-dom';

<Link to="/about">About</Link>
```

---

## ⚙️ 내부 작동 방식

### 🔗 1. `to` prop

* 이동할 경로를 지정합니다.
* 문자열 또는 객체를 전달할 수 있습니다.

```jsx
<Link to="/products/123" />
<Link to={{ pathname: "/products/123", search: "?q=abc", hash: "#top" }} />
```

→ 내부적으로 `navigate(to)` 함수를 호출하여 `history.push()` 또는 `history.replace()`를 실행합니다.

---

## 📥 `<a>` 태그와의 차이점

| 항목      | `<a>` 태그     | `<Link>`                     |
| ------- | ------------ | ---------------------------- |
| 페이지 리로딩 | 있음 (서버 요청)   | 없음 (SPA 내부 전환)               |
| 히스토리 관리 | 브라우저에 위임     | React Router의 History API 사용 |
| 성능      | 느림 (전체 리렌더링) | 빠름 (뷰만 바뀜)                   |
| 상태 유지   | 불가           | 가능 (ex. `useState` 유지됨)      |

---

## 📂 내부 코드 구조 (개념적)

React Router DOM의 `<Link>`는 다음과 같은 형태로 작동합니다:

```tsx
function Link({ to, replace = false, state, ...rest }) {
  const navigate = useNavigate(); // NavigationContext로부터 가져옴

  const handleClick = (e) => {
    e.preventDefault();
    navigate(to, { replace, state });
  };

  return (
    <a href={createHref(to)} onClick={handleClick} {...rest} />
  );
}
```

> 이처럼 `<Link>`는 실제로는 `<a>` 태그를 출력하지만, `onClick` 이벤트를 가로채어 **React Router의 `navigate()`를 통해 SPA 방식으로 라우팅**을 처리합니다.

---

## 📌 주요 Props 정리

| 속성                   | 설명                                                      |
| -------------------- | ------------------------------------------------------- |
| `to`                 | 이동할 경로 (문자열 또는 `{ pathname, search, hash, state }` 객체)  |
| `replace`            | `true`일 경우 `history.replace()` 사용 (`뒤로 가기` 히스토리에 남지 않음) |
| `state`              | `location.state`로 함께 전달할 객체                             |
| `reloadDocument`     | `true`면 기본 `<a>` 동작으로 리로드 수행                            |
| `target`             | `_blank`, `_self` 등 링크 동작 방식 지정 가능                      |
| `preventScrollReset` | 페이지 전환 후 스크롤 유지 여부 설정 (v6.4+)                           |

---

## 🔀 예제: state와 함께 이동하기

```jsx
<Link
  to="/profile"
  state={{ fromDashboard: true }}
>
  Go to Profile
</Link>
```

```jsx
// Profile.jsx
const location = useLocation();
console.log(location.state); // { fromDashboard: true }
```

## 🧩 고급 기능

### ✅ `replace` 사용 예

```jsx
<Link to="/login" replace />
```

* `history.replace()`를 호출하므로, "뒤로 가기" 시 로그인 이전 페이지로 돌아가지 않게 함.
* 인증 후 리디렉션할 때 유용.

### ✅ 객체 형태의 `to`

```jsx
<Link
  to={{
    pathname: "/search",
    search: "?q=react",
    hash: "#results",
    state: { from: "home" }
  }}
>
  Search
</Link>
```

## 🚫 잘못된 사용 예

```jsx
<a href="/about">About</a> // ❌ 전체 페이지 새로고침 발생
```

→ SPA의 장점을 무시하고 서버에 직접 요청하므로 비효율적.

---

## 🧠 내부 흐름: 클릭 → 라우팅

1. 사용자가 `<Link to="/about" />` 클릭
2. 기본 `<a>` 동작을 \*\*preventDefault()\*\*로 차단
3. `navigate("/about")` 호출
4. React Router의 `history.pushState()` 수행
5. `location` 변경 → `<Routes>`가 매칭된 `<Route>` 트리 렌더링
6. 이전 상태를 유지한 채 새 컴포넌트가 뷰에 렌더링됨

---

## 🔄 `useNavigate`와의 관계

* `<Link>`는 선언적 방식
* `useNavigate()`는 명령형 방식

```jsx
const navigate = useNavigate();
<button onClick={() => navigate("/about")}>Go</button>
```

둘은 내부적으로 동일한 navigate 함수를 사용합니다.

| ----- | -------------------------------------------------------------- |

## 📦 마무리

`<Link>`는 단순한 링크가 아니라 **React Router가 클라이언트 측 라우팅을 효율적으로 관리하기 위한 핵심 UI 컴포넌트**입니다. 내부적으로 `navigate()` 함수와 `history.pushState()`를 통해 앱의 URL과 뷰 상태를 동기화하며, React의 SPA 원칙에 맞는 부드러운 사용자 경험을 제공합니다.
