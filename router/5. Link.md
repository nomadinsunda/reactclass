# `<Link>` in React Router

## 새로고침 없이 URL과 화면을 전환하는 SPA Navigation

React Router의 `<Link>`는 React 애플리케이션 내부에서 **클라이언트 사이드 Navigation**을 수행하기 위한 컴포넌트입니다.

가장 기본적인 사용법은 다음과 같습니다.

```jsx
<Link to="/about">About</Link>
```

사용자가 이 링크를 클릭하면 일반적인 SPA 내부 navigation에서는 새로운 HTML Document를 서버에서 다시 받아오는 대신 React Router가 navigation을 처리합니다.

전체 흐름은 다음과 같습니다.

```text
<Link to="/about">
        │
        │ click
        ▼
React Router Navigation
        │
        ▼
History / Location 변경
        │
        ▼
URL
/about
        │
        ▼
<Routes>
Route Matching
        │
        ▼
<Route path="/about">
        │
        ▼
<About />
        │
        ▼
React Rendering
        │
        ▼
화면 변경
```

따라서 `<Link>`를 한 문장으로 정의하면 다음과 같습니다.

> **`<Link>`는 새로운 HTML Document를 다시 로드하지 않고 React Router의 클라이언트 사이드 navigation을 실행하여 URL과 React UI를 전환하는 컴포넌트입니다.**

---

# 1. 왜 `<Link>`가 필요한가?

먼저 일반 HTML의 `<a>`와 비교해보겠습니다.

## 일반 HTML `<a>`

```html
<a href="/about">About</a>
```

일반적인 링크 navigation은 브라우저의 Document navigation을 발생시킵니다.

```text
사용자
   │
   │ click
   ▼
<a href="/about">
   │
   ▼
Browser Navigation
   │
   ▼
GET /about
   │
   ▼
Server
   │
   ▼
HTML Document
   │
   ▼
새 Document 로드
   │
   ▼
화면 표시
```

브라우저는 `/about`이라는 새로운 문서를 요청합니다.

따라서 기존 Document가 새로운 Document로 교체됩니다.

React SPA라면 결과적으로 React 애플리케이션 역시 다시 시작될 수 있습니다.

단, CSS, JavaScript, 이미지 등의 리소스가 항상 네트워크에서 전부 다시 다운로드되는 것은 아닙니다.

브라우저 캐시가 존재한다면 기존 리소스가 재사용될 수 있습니다.

중요한 차이는:

> **새로운 Document navigation이 발생한다.**

는 것입니다.

---

# 2. SPA의 Navigation

SPA에서는 일반적으로 최초 접속 시 애플리케이션에 필요한 HTML과 JavaScript를 로드합니다.

```text
Browser
   │
   ▼
index.html
   │
   ▼
JavaScript
   │
   ▼
React 실행
   │
   ▼
React Application
```

이후 애플리케이션 내부에서:

```text
/
/about
/products
/products/10
```

등으로 이동할 때마다 새로운 HTML Document를 서버에서 다시 받을 필요는 없습니다.

대신:

```text
현재 React App
      │
      ▼
URL 변경
      │
      ▼
Route Matching
      │
      ▼
React UI 변경
```

방식을 사용할 수 있습니다.

바로 이 Navigation을 사용자에게 **링크 형태로 제공하는 컴포넌트**가 `<Link>`입니다.

---

# 3. `<Link>`의 기본 사용법

```jsx
import {
  BrowserRouter,
  Routes,
  Route,
  Link
} from 'react-router-dom';

function App() {
  return (
    <BrowserRouter>

      <nav>
        <Link to="/">Home</Link>
        <Link to="/about">About</Link>
      </nav>

      <Routes>
        <Route
          path="/"
          element={<Home />}
        />

        <Route
          path="/about"
          element={<About />}
        />
      </Routes>

    </BrowserRouter>
  );
}
```

현재 URL이:

```text
/
```

인 상태에서:

```jsx
<Link to="/about">
  About
</Link>
```

을 클릭한다고 해보겠습니다.

# 4. `<Link>` 클릭 시 전체 동작

이 부분이 `<Link>`를 이해하는 데 가장 중요합니다.

```text
사용자
   │
   │ click
   ▼
<Link to="/about">
   │
   ▼
React Router가
내부 Navigation 처리
   │
   ▼
Browser History /
Router Location 변경
   │
   ▼
URL
/about
   │
   ▼
<Routes>
   │
   ▼
Route Matching
   │
   ▼
<Route
 path="/about"
 element={<About />}
/>
   │
   ▼
<About />
   │
   ▼
React Rendering
   │
   ▼
화면 변경
```

여기서 중요한 것은:

```text
새로운 HTML Document 요청
          X

React App 종료
          X

URL 변경
          O

Route Matching
          O

React Rendering
          O
```

이라는 것입니다.

# 5. `<Link>`는 실제로 링크인가?

그렇습니다.

`<Link>`는 사용자에게 **Navigation 링크의 의미를 제공**하고 최종적으로 브라우저에서는 anchor 기반의 링크로 동작하도록 설계되어 있습니다.

개념적으로:

```jsx
<Link to="/about">
  About
</Link>
```

은 브라우저에서 링크 역할을 수행합니다.

하지만 일반적인 내부 링크 클릭에서는 React Router가 브라우저의 기본 Document navigation 대신 **클라이언트 사이드 navigation**을 수행합니다.

따라서:

```text
HTML <a>
     │
     ▼
Browser Document Navigation
```

과:

```text
React Router <Link>
     │
     ▼
Router Navigation
     │
     ▼
SPA UI 변경
```

의 차이가 발생합니다.

---

# 6. `<a>`와 `<Link>` 비교

| 구분                    | `<a href>`             | `<Link to>`                   |
| --------------------- | ---------------------- | ----------------------------- |
| 주요 목적                 | 일반적인 문서/리소스 navigation | React Router 내부 navigation    |
| 새 Document navigation | 일반적으로 발생               | 일반적인 내부 이동에서는 발생하지 않음         |
| React Runtime         | 새 문서가 로드되면 다시 시작       | 유지                            |
| React State           | 새 앱 실행 시 초기화될 수 있음     | 일반적으로 유지                      |
| URL 변경                | 브라우저가 처리               | Router navigation과 연동         |
| History               | 브라우저 navigation        | React Router가 History API와 연동 |
| 대표 사용                 | 외부 문서, 다운로드 등          | SPA 내부 Route 이동               |

따라서 일반적인 기준은:

```text
같은 React Router App 내부
          │
          ▼
       <Link>


외부 문서 / 일반 URL 이동
          │
          ▼
         <a>
```

입니다.

---

# 7. `to`

`<Link>`에서 가장 중요한 prop은 `to`입니다.

```jsx
<Link to="/users">
  Users
</Link>
```

`to`는 **어디로 이동할 것인지**를 정의합니다.

---

# 8. 절대 경로

```jsx
<Link to="/products">
  Products
</Link>

<Link to="/products/10">
  Product 10
</Link>
```

앞에 `/`가 있으므로 root 기준으로 해석됩니다.

```text
to="/products"
       ↓
/products


to="/products/10"
       ↓
/products/10
```

---

# 9. 상대 경로

`to`에는 상대 경로도 사용할 수 있습니다.

```jsx
<Link to="settings">
  Settings
</Link>
```

특히 Nested Route에서 중요합니다.

Route 구조가:

```jsx
<Route
  path="dashboard"
  element={<Dashboard />}
>
  <Route
    path="stats"
    element={<Stats />}
  />

  <Route
    path="settings"
    element={<Settings />}
  />
</Route>
```

라고 하겠습니다.

`Dashboard`에서:

```jsx
<Link to="stats">Stats</Link>

<Link to="settings">Settings</Link>
```

를 사용할 수 있습니다.

개념적으로:

```text
/dashboard
    │
    ├── to="stats"
    │       ↓
    │  /dashboard/stats
    │
    └── to="settings"
            ↓
       /dashboard/settings
```

이 방식의 장점은 부모 Route 구조가 변경되더라도 자식 링크가 부모의 전체 URL을 직접 반복하지 않아도 된다는 것입니다.

---

# 10. Location 객체 형태의 `to`

`to`에는 객체 형태의 location 정보를 전달할 수도 있습니다.

```jsx
<Link
  to={{
    pathname: '/search',
    search: '?q=react&sort=latest',
    hash: '#top'
  }}
>
  Search
</Link>
```

각각의 역할은:

```text
pathname
   │
   └── /search

search
   │
   └── ?q=react&sort=latest

hash
   │
   └── #top
```

입니다.

최종 URL:

```text
/search?q=react&sort=latest#top
```

따라서 URL을 구조적으로 구성할 때 유용합니다.

---

# 11. `replace`

기본적인 `<Link>` navigation은 새로운 History entry를 추가합니다.

예를 들어:

```text
/
↓
/products
↓
/products/10
```

으로 이동했다면 History는 개념적으로:

```text
[ / ]
[ /products ]
[ /products/10 ] ← 현재
```

와 같습니다.

따라서 Back 버튼을 누르면:

```text
/products
```

로 돌아갈 수 있습니다.

`replace`를 사용하면:

```jsx
<Link
  to="/login"
  replace
>
  Login
</Link>
```

현재 History entry를 새로운 location으로 교체하는 navigation을 수행합니다.

개념적으로:

```text
기본 Link

A
│
▼
B

History
[A][B]


replace

A
│
▼
B

History
[B]
```

따라서 사용자가 이전 location으로 돌아가기를 원하지 않는 특정 navigation에서 사용할 수 있습니다.

---

# 12. `state`

URL에 포함시키지 않고 navigation과 함께 추가 데이터를 전달할 수도 있습니다.

```jsx
<Link
  to="/checkout"
  state={{
    from: 'cart',
    coupon: 'SPRING10'
  }}
>
  Checkout
</Link>
```

대상 컴포넌트에서는 `useLocation()`을 사용합니다.

```jsx
import { useLocation } from 'react-router-dom';

function Checkout() {
  const location = useLocation();

  console.log(location.state);

  return <h1>Checkout</h1>;
}
```

결과:

```js
{
  from: 'cart',
  coupon: 'SPRING10'
}
```

전체 구조는:

```text
<Link>
   │
   ├── to="/checkout"
   │
   └── state={...}
           │
           ▼
       Navigation
           │
           ▼
      /checkout
           │
           ▼
     useLocation()
           │
           ▼
    location.state
```

입니다.

---

# 13. `state`와 URL Parameter는 목적이 다르다

예를 들어 상품 ID처럼 URL 자체를 표현하는 데이터라면:

```text
/products/10
```

처럼 URL에 넣는 것이 자연스럽습니다.

```jsx
<Link to="/products/10" />
```

반면 navigation 과정의 부가적인 정보라면:

```jsx
<Link
  to="/checkout"
  state={{ from: 'cart' }}
/>
```

처럼 `state`를 사용할 수 있습니다.

즉:

```text
URL 자체를 구성하는 정보
        │
        ▼
pathname / params / search


Navigation 부가 정보
        │
        ▼
state
```

라고 구분할 수 있습니다.

`state`는 URL에 보이지 않는다고 해서 보안 저장소가 되는 것은 아닙니다.

비밀번호, 인증 토큰 같은 민감한 정보를 저장하는 용도로 사용하면 안 됩니다.

---

# 14. `reloadDocument`

특별한 경우에는 React Router의 클라이언트 navigation 대신 브라우저의 Document navigation을 사용하고 싶을 수도 있습니다.

```jsx
<Link
  to="/about"
  reloadDocument
>
  About
</Link>
```

이 경우 일반적인 `<Link>` navigation과 달리 Document navigation이 수행됩니다.

```text
일반 Link

click
  ↓
Router Navigation
  ↓
SPA 화면 변경


reloadDocument

click
  ↓
Browser Navigation
  ↓
Document 요청
  ↓
새 Document 로드
```

일반적인 SPA 내부 이동에서는 자주 필요하지 않습니다.

# 15. `<Link>`와 Dynamic Route

Route가 다음과 같다고 하겠습니다.

```jsx
<Route
  path="/posts/:postId"
  element={<PostDetail />}
/>
```

게시글 목록에서는:

```jsx
function PostList({ posts }) {
  return (
    <ul>
      {posts.map(post => (
        <li key={post.id}>
          <Link to={`/posts/${post.id}`}>
            {post.title}
          </Link>
        </li>
      ))}
    </ul>
  );
}
```

처럼 사용할 수 있습니다.

예를 들어:

```text
post.id = 10
      │
      ▼
<Link to="/posts/10">
      │
      ▼
/posts/10
      │
      ▼
<Route path="/posts/:postId">
      │
      ▼
postId = "10"
      │
      ▼
<PostDetail />
```

입니다.

# 16. `<Link>`와 `<Outlet>`의 관계

Nested Route에서는 `<Link>`와 `<Outlet>`이 함께 등장하는 경우가 많습니다.

```jsx
function Dashboard() {
  return (
    <>
      <nav>
        <Link to="stats">
          Stats
        </Link>

        <Link to="settings">
          Settings
        </Link>
      </nav>

      <Outlet />
    </>
  );
}
```

현재 URL:

```text
/dashboard
```

에서:

```text
<Link to="settings">
```

를 클릭하면:

```text
/dashboard/settings
```

으로 이동합니다.

Route Matching 결과:

```text
/dashboard
    │
    └── settings
```

렌더링 결과:

```text
<Dashboard>
     │
     ├── Navigation
     │
     └── <Outlet />
             │
             ▼
        <Settings />
```

가 됩니다.

# 17. `<Link>`와 `useNavigate()`

두 기능은 모두 Router navigation을 수행하지만 사용 목적이 다릅니다.

## `<Link>`

사용자가 직접 클릭할 수 있는 navigation UI에 적합합니다.

```jsx
<Link to="/profile">
  Profile
</Link>
```

예:

```text
메뉴
탭
상품 제목
Breadcrumb
Navigation 링크
```

---

## `useNavigate()`

프로그램 로직의 결과로 이동해야 할 때 사용합니다.

```jsx
const navigate = useNavigate();

async function handleSubmit() {
  const success = await login();

  if (success) {
    navigate('/dashboard');
  }
}
```

즉:

```text
사용자가 링크 클릭
       │
       ▼
     <Link>


프로그램 로직이 이동 결정
       │
       ▼
 useNavigate()
```

라고 구분하면 이해하기 쉽습니다.

# 18. `<Link>`와 `<NavLink>`

Navigation 메뉴에서는 현재 어느 페이지에 있는지 표시해야 하는 경우가 많습니다.

예를 들어:

```text
Home
About     ← 현재 페이지
Products
```

이럴 때 `<NavLink>`를 사용할 수 있습니다.

```jsx
<NavLink
  to="/about"
  className={({ isActive }) =>
    isActive
      ? 'active'
      : undefined
  }
>
  About
</NavLink>
```

`NavLink`는 기본적인 navigation 기능에 더해 **현재 location과의 매칭 상태**를 활용할 수 있습니다.

개념적으로:

```text
Link
 │
 └── Navigation


NavLink
 │
 ├── Navigation
 │
 └── Active 상태 정보
```

따라서:

```text
일반 링크
    ↓
<Link>


현재 Route 표시가 필요한 Navigation
    ↓
<NavLink>
```

라고 구분할 수 있습니다.

# 19. Link인가 Button인가?

UI 모양과 HTML의 의미를 구분해야 합니다.

다음 UI가 있다고 해보겠습니다.

```text
[ 결제하기 ]
```

버튼처럼 생겼더라도 클릭의 의미가:

```text
현재 상태 변경
```

이 아니라:

```text
/checkout으로 이동
```

이라면 Link가 의미상 적절할 수 있습니다.

```jsx
<Link
  to="/checkout"
  className="button"
>
  결제하기
</Link>
```

반대로:

```text
수량 증가
Modal 열기
데이터 삭제
Form 제출
```

처럼 현재 화면에서 동작을 수행하는 것이 목적이라면 `<button>`이 더 적절합니다.

따라서:

```text
Navigation
    │
    ▼
   Link


Action
    │
    ▼
  Button
```

이라고 구분하는 것이 좋습니다.

# 20. 내부 링크와 외부 링크

React Router의 `<Link>`는 주로 React Router가 관리하는 애플리케이션 내부 navigation에 사용합니다.

```jsx
<Link to="/about">
  About
</Link>
```

외부 문서로 이동하는 일반적인 경우에는 HTML anchor를 사용하는 것이 의미상 명확합니다.

```html
<a
  href="https://example.com"
  target="_blank"
  rel="noreferrer"
>
  External Site
</a>
```

따라서 일반적인 기준은:

```text
React Router 내부 Route
          │
          ▼
        Link


외부 문서 / 외부 사이트
          │
          ▼
          a
```

입니다.

---

# 21. 흔한 실수 — Route와 `to`가 다른 경우

Route:

```jsx
<Route
  path="/products/:id"
  element={<ProductDetail />}
/>
```

그런데 Link를:

```jsx
<Link to="/product/10">
  Product 10
</Link>
```

으로 작성했다고 하겠습니다.

Route는:

```text
/products/:id
```

인데 Link는:

```text
/product/10
```

입니다.

따라서 원하는 Route와 매칭되지 않습니다.

```text
Link
/product/10
     │
     ▼
Routes
     │
     ├── /products/:id   X
     │
     └── *               O
                           │
                           ▼
                       NotFound
```

경로 이름을 일관되게 관리하는 것이 중요합니다.

---

# 22. `<Link>`는 무엇을 하지 않는가?

`<Link>` 자체가 어떤 화면을 렌더링할지 결정하는 것은 아닙니다.

역할을 분리해야 합니다.

```text
<Link>
"어디로 이동할 것인가?"
        │
        ▼
Navigation


<Routes>
"현재 URL에 어떤 Route가 맞는가?"
        │
        ▼
Route Matching


<Route>
"이 URL Pattern에 어떤 UI를 사용할 것인가?"
        │
        ▼
element
```

따라서:

```jsx
<Link to="/about">
```

과:

```jsx
<Route
  path="/about"
  element={<About />}
/>
```

은 서로 다른 역할을 합니다.

---

# 23. 전체 동작 흐름

앞에서 배운 `BrowserRouter`, `Routes`, `Route`, `Link`를 하나로 연결하면 다음과 같습니다.

```text
사용자
   │
   │ click
   ▼
<Link to="/users/10">
   │
   │ Navigation 요청
   ▼
React Router
   │
   ▼
History / Location 변경
   │
   ▼
URL
/users/10
   │
   ▼
BrowserRouter가 관리하는
Router 상태
   │
   ▼
<Routes>
   │
   │ Route Matching
   ▼
Matched Route Branch
   │
   ▼
<Route path="users/:userId">
   │
   ▼
<UserDetail />
   │
   ▼
React Rendering
   │
   ▼
UI
```

이 과정이 `<Link>`를 이해하는 핵심입니다.

---

# 24. `<Link>`의 핵심 역할

`<Link>`를 단순히:

> React에서 사용하는 `<a>`

라고 이해하면 핵심을 놓치게 됩니다.

더 정확하게는:

> **사용자가 링크를 통해 React Router navigation을 시작할 수 있도록 하는 선언형 Navigation 컴포넌트**

라고 이해하는 것이 좋습니다.

구조적으로:

```text
<Link>
│
├── to
│    └── 목적지
│
├── replace
│    └── History 교체
│
├── state
│    └── Navigation state
│
└── reloadDocument
     └── Document navigation 사용
```

과 같은 역할을 담당합니다.

---

# 25. 주요 구성 요소 역할 비교

| 구성 요소           | 핵심 역할                               |
| --------------- | ----------------------------------- |
| `BrowserRouter` | Browser History와 Router location 관리 |
| `Link`          | 사용자의 클라이언트 사이드 navigation 시작        |
| `Routes`        | 현재 location과 Route Tree 매칭          |
| `Route`         | URL pattern과 UI의 관계 정의              |
| `Outlet`        | 자식 Route element 렌더링 위치             |
| `NavLink`       | Link + active 상태                    |
| `useNavigate()` | 프로그램 방식 navigation                  |

전체 관계를 연결하면:

```text
<Link>
   │
   │ Navigation
   ▼
Router Location
   │
   ▼
<Routes>
   │
   │ Matching
   ▼
<Route>
   │
   │ element
   ▼
React UI
```

입니다.

---

# 최종 정의

`<Link>`를 한 문장으로 정리하면 다음과 같습니다.

> **`<Link>`는 사용자의 링크 클릭을 React Router의 클라이언트 사이드 navigation으로 연결하여, 새로운 HTML Document를 다시 로드하지 않고 Router location을 변경하고 그 결과 새로운 Route UI가 렌더링되도록 하는 선언형 Navigation 컴포넌트입니다.**

더 짧게 압축하면:

> **`<Link>` = 사용자 클릭 → Router Navigation → URL 변경 → Route Matching → React UI 변경**

그리고 지금까지 배운 React Router 구성 요소를 하나로 연결하면:

```text
                 사용자
                   │
                   ▼
                 Link
                   │
             Navigation
                   │
                   ▼
             BrowserRouter
                   │
               location
                   │
                   ▼
                Routes
                   │
            Route Matching
                   │
                   ▼
                 Route
                   │
                element
                   │
                   ▼
                 Outlet
                   │
                   ▼
                React UI
```

이 구조를 이해하면 `<Link>`가 단순히 `<a>`를 React식으로 바꾼 컴포넌트가 아니라, **사용자 인터랙션과 React Router의 Route Matching 시스템을 연결하는 Navigation 진입점**이라는 점을 명확하게 이해할 수 있습니다.
