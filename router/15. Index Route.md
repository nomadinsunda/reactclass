# React Router Index Route

## — 부모 URL에 기본으로 보여줄 Child Route 만들기

Nested Route를 이해했다면 다음으로 자연스럽게 나오는 개념이 **Index Route**입니다.

예를 들어 다음과 같은 Route 구조가 있다고 하겠습니다.

```jsx
<Routes>
  <Route path="/dashboard" element={<DashboardLayout />}>
    <Route path="profile" element={<Profile />} />
    <Route path="settings" element={<Settings />} />
  </Route>
</Routes>
```

이 구조에서:

```text
/dashboard/profile
```

로 이동하면 `Profile`이,

```text
/dashboard/settings
```

로 이동하면 `Settings`가 자식 Route로 매칭됩니다.

그렇다면 사용자가 그냥:

```text
/dashboard
```

로 이동하면 어떻게 될까요?

바로 이 문제를 해결하는 것이 **Index Route**입니다.

---

# 1. Index Route란?

한 문장으로 정의하면:

> **Index Route는 부모 Route의 URL 자체가 매칭되었을 때 기본으로 렌더링되는 자식 Route입니다.**

예를 들어:

```jsx
<Route path="/dashboard" element={<DashboardLayout />}>
  <Route index element={<DashboardHome />} />
  <Route path="profile" element={<Profile />} />
  <Route path="settings" element={<Settings />} />
</Route>
```

여기에서:

```jsx
<Route index element={<DashboardHome />} />
```

가 Index Route입니다.

URL별 결과는 다음과 같습니다.

```text
/dashboard
→ DashboardHome

/dashboard/profile
→ Profile

/dashboard/settings
→ Settings
```

즉 `index`는 부모 Route의 **기본 자식 Route**라고 생각하면 됩니다.

---

# 2. 왜 Index Route가 필요한가?

다음 Nested Route를 보겠습니다.

```jsx
<Route path="/dashboard" element={<DashboardLayout />}>
  <Route path="profile" element={<Profile />} />
  <Route path="settings" element={<Settings />} />
</Route>
```

Route Tree는 다음과 같습니다.

```text
Dashboard
│
├── Profile
└── Settings
```

사용자가:

```text
/dashboard/profile
```

로 이동하면:

```text
Dashboard
   │
   ▼
Profile
```

이라는 Route Branch가 만들어집니다.

하지만:

```text
/dashboard
```

만 입력하면 자식 Route의 `profile`, `settings` 중 어느 것도 추가로 매칭되지 않습니다.

즉 개념적으로:

```text
/dashboard
     │
     ▼
Dashboard
     │
     ▼
Child Route 없음
```

이 됩니다.

부모 Layout에 `<Outlet />`이 있다면 그 위치에 넣을 자식 element가 없는 것입니다.

```text
DashboardLayout
│
├── Header
├── Sidebar
│
└── Outlet
      │
      └── 렌더링할 Child Route 없음
```

그래서 부모 URL 자체에 기본 화면이 필요하면 **Index Route를 정의합니다.**

---

# 3. Index Route를 추가해보자

다음과 같이 작성합니다.

```jsx
<Routes>
  <Route
    path="/dashboard"
    element={<DashboardLayout />}
  >
    <Route
      index
      element={<DashboardHome />}
    />

    <Route
      path="profile"
      element={<Profile />}
    />

    <Route
      path="settings"
      element={<Settings />}
    />
  </Route>
</Routes>
```

Route Tree는:

```text
/dashboard
DashboardLayout
│
├── index
│   └── DashboardHome
│
├── profile
│   └── Profile
│
└── settings
    └── Settings
```

가 됩니다.

이제 `/dashboard` 자체에 들어오면:

```text
/dashboard
     │
     ▼
Dashboard Route
     │
     ▼
Index Route
     │
     ▼
DashboardHome
```

이 선택됩니다.

---

# 4. 실제 화면에서는 어떻게 보일까?

`DashboardLayout`이 다음과 같다고 하겠습니다.

```jsx
import { Outlet } from "react-router-dom";

function DashboardLayout() {
  return (
    <div>
      <header>Dashboard</header>

      <nav>
        Profile | Settings
      </nav>

      <main>
        <Outlet />
      </main>
    </div>
  );
}
```

URL이:

```text
/dashboard
```

이면:

```text
DashboardLayout
      │
      ├── Header
      ├── Navigation
      │
      └── Outlet
            │
            ▼
      DashboardHome
```

가 됩니다.

최종 화면:

```text
┌──────────────────────────────┐
│ Dashboard                    │
├──────────────────────────────┤
│ Profile | Settings           │
├──────────────────────────────┤
│                              │
│       Dashboard Home         │
│                              │
└──────────────────────────────┘
```

---

# 5. `/dashboard/profile`에서는?

같은 Route Tree에서 URL이:

```text
/dashboard/profile
```

이면 Index Route가 아니라 `profile` Route가 선택됩니다.

```text
/dashboard/profile
        │
        ▼
Dashboard Route
        │
        ▼
Profile Route
        │
        ▼
<Profile />
```

렌더링 구조:

```text
DashboardLayout
      │
      ├── Header
      ├── Navigation
      │
      └── Outlet
            │
            ▼
          Profile
```

즉 Index Route는 항상 렌더링되는 것이 아닙니다.

> **부모 Route는 매칭되었지만 더 구체적인 자식 path가 없는 경우에 기본 자식으로 사용됩니다.**

---

# 6. Index Route에는 왜 `path`가 없을까?

다음 코드를 보겠습니다.

```jsx
<Route index element={<DashboardHome />} />
```

일반 Route와 달리:

```jsx
path="..."
```

가 없습니다.

왜냐하면 Index Route는 별도의 URL segment를 추가하지 않기 때문입니다.

일반 자식 Route:

```jsx
<Route path="profile" element={<Profile />} />
```

는:

```text
/dashboard
+
profile
=
/dashboard/profile
```

이 됩니다.

하지만 Index Route는:

```jsx
<Route index element={<DashboardHome />} />
```

이므로:

```text
/dashboard
+
추가 path 없음
=
/dashboard
```

입니다.

즉:

> **Index Route는 부모 URL을 그대로 사용합니다.**

---

# 7. `index`는 사실 무엇을 의미하는가?

`index`를 직관적으로 해석하면:

> **"이 부모 Route의 기본 화면으로 사용해라."**

입니다.

예를 들어 파일 시스템을 떠올리면 이해하기 쉽습니다.

```text
dashboard/
├── index
├── profile
└── settings
```

개념적으로:

```text
/dashboard
→ index

/dashboard/profile
→ profile

/dashboard/settings
→ settings
```

와 비슷합니다.

이 때문에 이름도 `Index Route`입니다.

---

# 8. Index Route와 일반 Child Route 비교

다음 두 Route를 비교해보겠습니다.

```jsx
<Route index element={<DashboardHome />} />

<Route path="profile" element={<Profile />} />
```

차이는 다음과 같습니다.

| 구분             | Index Route | 일반 Child Route  |
| -------------- | ----------- | --------------- |
| `path`         | 없음          | 있음              |
| 추가 URL segment | 없음          | 있음              |
| 매칭 URL         | 부모 URL 자체   | 부모 + child path |
| 역할             | 기본 자식 화면    | 특정 하위 화면        |

예:

```text
Parent
/dashboard
```

일 때:

```text
Index Route
→ /dashboard
```

반면:

```text
path="profile"
→ /dashboard/profile
```

입니다.

---

# 9. `path=""`와 같은 것인가?

입문자가 자주 생각하는 방식이 있습니다.

```jsx
<Route path="" element={<DashboardHome />} />
```

를 쓰면 Index Route와 같은 것 아니냐는 것입니다.

비슷한 결과를 떠올릴 수 있지만 **개념적으로는 Index Route를 사용할 때 `index`를 명시하는 것이 더 정확합니다.**

```jsx
<Route index element={<DashboardHome />} />
```

라고 작성하면 코드 자체가:

> **"이 Route는 부모의 기본 자식이다."**

라는 의도를 명확하게 표현합니다.

즉 Index Route는 단순한 빈 문자열 path가 아니라 **부모 Route의 기본 자식이라는 의미를 갖는 Route**입니다.

---

# 10. Index Route는 자식 Route인가?

네.

아주 중요한 포인트입니다.

```jsx
<Route path="/dashboard" element={<DashboardLayout />}>
  <Route index element={<DashboardHome />} />
</Route>
```

여기에서 `DashboardHome`은 부모 Route의 element가 아닙니다.

부모는:

```text
Dashboard Route
element = <DashboardLayout />
```

이고,

Index Route는 그 아래의:

```text
Child Route
element = <DashboardHome />
```

입니다.

구조:

```text
Dashboard Route
│
├── element
│   └── DashboardLayout
│
└── Index Child Route
    └── DashboardHome
```

따라서 렌더링도:

```text
DashboardLayout
      │
      ▼
    Outlet
      │
      ▼
DashboardHome
```

형태가 됩니다.

---

# 11. 이것이 중요한 이유

다음 두 코드는 구조적으로 다릅니다.

## 방식 A

```jsx
<Route
  path="/dashboard"
  element={<DashboardHome />}
/>
```

이 경우 `/dashboard`의 Route element 자체가 `DashboardHome`입니다.

```text
/dashboard
    │
    ▼
DashboardHome
```

---

## 방식 B

```jsx
<Route
  path="/dashboard"
  element={<DashboardLayout />}
>
  <Route
    index
    element={<DashboardHome />}
  />
</Route>
```

이 경우:

```text
/dashboard
     │
     ▼
DashboardLayout
     │
     ▼
Index Route
     │
     ▼
DashboardHome
```

입니다.

즉 방식 B에서는 Layout과 Page의 역할이 분리됩니다.

```text
DashboardLayout
→ 공통 UI

DashboardHome
→ 기본 Content
```

실무에서 Nested Route를 사용하는 중요한 이유 중 하나입니다.

# 12. 실전 예제 — 쇼핑몰 Products

다음 URL을 만들어보겠습니다.

```text
/products
/products/100
/products/200
```

원하는 화면 구조:

```text
/products
→ ProductList

/products/100
→ ProductDetail

/products/200
→ ProductDetail
```

Route는 다음처럼 구성할 수 있습니다.

```jsx
<Routes>
  <Route
    path="/products"
    element={<ProductsLayout />}
  >
    <Route
      index
      element={<ProductList />}
    />

    <Route
      path=":productId"
      element={<ProductDetail />}
    />
  </Route>
</Routes>
```

Route Tree:

```text
ProductsLayout
│
├── index
│   └── ProductList
│
└── :productId
    └── ProductDetail
```

---

# 13. `/products`로 이동하면

URL:

```text
/products
```

Route Branch:

```text
Products
   │
   ▼
index
```

렌더링:

```text
ProductsLayout
      │
      ▼
    Outlet
      │
      ▼
 ProductList
```

---

# 14. `/products/100`으로 이동하면

URL:

```text
/products/100
```

이번에는 Index Route가 아니라:

```text
:productId
```

가 매칭됩니다.

```text
Products
   │
   ▼
:productId
   │
   ▼
ProductDetail
```

그리고:

```jsx
const { productId } = useParams();
```

를 사용하면:

```text
productId = "100"
```

을 얻을 수 있습니다.

렌더링:

```text
ProductsLayout
      │
      ▼
    Outlet
      │
      ▼
 ProductDetail
```

즉 같은 `<Outlet />` 위치에 URL에 따라:

```text
/products
→ ProductList

/products/100
→ ProductDetail
```

이 들어갑니다.

---

# 15. Index Route와 Outlet의 관계

Index Route도 결국 Child Route이므로 부모 Layout 안에서 렌더링되려면 `<Outlet />`이 필요합니다.

예:

```jsx
function ProductsLayout() {
  return (
    <>
      <h1>Products</h1>

      <Outlet />
    </>
  );
}
```

그리고:

```jsx
<Route path="/products" element={<ProductsLayout />}>
  <Route index element={<ProductList />} />
  <Route path=":productId" element={<ProductDetail />} />
</Route>
```

URL이 `/products`이면:

```text
ProductsLayout
      │
      ▼
   <Outlet />
      │
      ▼
 ProductList
```

입니다.

즉 Index Route 자체가 Outlet을 대체하는 것이 아닙니다.

역할을 구분하면:

```text
Index Route
→ 어떤 Child Route를 기본으로 선택할지 결정

Outlet
→ 선택된 Child Route element가
  부모 UI 어디에 렌더링될지 결정
```

입니다.

---

# 16. Index Route를 사용하지 않으면?

다음 Route에서:

```jsx
<Route path="/products" element={<ProductsLayout />}>
  <Route path=":productId" element={<ProductDetail />} />
</Route>
```

Index Route가 없습니다.

사용자가:

```text
/products
```

로 이동하면:

```text
Products Route
     │
     ▼
ProductsLayout
     │
     ▼
Outlet
     │
     ▼
매칭된 Child Route 없음
```

이 됩니다.

따라서 `ProductsLayout`의 공통 UI만 보이고 Outlet에는 별도 내용이 나타나지 않을 수 있습니다.

```text
┌───────────────────────────┐
│ Products                  │
├───────────────────────────┤
│                           │
│        빈 영역            │
│                           │
└───────────────────────────┘
```

이것이 의도된 화면이라면 Index Route가 필요하지 않습니다.

하지만 `/products`에서 목록을 보여주고 싶다면:

```jsx
<Route index element={<ProductList />} />
```

가 필요합니다.

---

# 17. Index Route가 항상 필요한 것은 아니다

Index Route는 Nested Route를 사용한다고 무조건 만드는 것이 아닙니다.

예를 들어:

```text
/admin
```

에 들어오면 별도의 콘텐츠를 보여주지 않고,

```text
/admin/users
/admin/settings
```

중 하나를 반드시 선택하게 만들 수도 있습니다.

그렇다면:

```jsx
<Route path="/admin" element={<AdminLayout />}>
  <Route path="users" element={<Users />} />
  <Route path="settings" element={<Settings />} />
</Route>
```

처럼 Index Route가 없어도 됩니다.

즉 Index Route가 필요한 기준은:

> **부모 URL 자체에서도 보여줄 기본 Child UI가 필요한가?**

입니다.

---

# 18. Index Route와 Redirect는 다르다

여기서 또 하나 자주 혼동하는 패턴이 있습니다.

`/dashboard`로 들어오면 기본 화면을:

```text
DashboardHome
```

으로 보여줄 수도 있지만,

아예 URL을:

```text
/dashboard/profile
```

로 이동시키고 싶을 수도 있습니다.

이 둘은 다릅니다.

## Index Route로 UI 렌더링

```jsx
<Route
  index
  element={<DashboardHome />}
/>
```

URL:

```text
/dashboard
```

그대로 유지됩니다.

화면만:

```text
DashboardHome
```

이 나타납니다.

---

## Redirect

```jsx
<Route
  index
  element={
    <Navigate
      to="profile"
      replace
    />
  }
/>
```

이 경우:

```text
/dashboard
```

로 들어와도 실제 URL이:

```text
/dashboard/profile
```

로 변경됩니다.

즉:

```text
Index Route
→ 기본 Child UI

Navigate
→ 다른 URL로 이동
```

입니다.

이 차이는 중요합니다.

---

# 19. 언제 Index Route를 사용하고 언제 Redirect할까?

예를 들어 Dashboard에 독립적인 Home 화면이 있다면:

```text
/dashboard
→ DashboardHome
```

이 자연스럽습니다.

```jsx
<Route index element={<DashboardHome />} />
```

를 사용합니다.

반면 `/dashboard` 자체에 별도의 의미가 없고 무조건 Profile을 기본 페이지로 사용한다면:

```text
/dashboard
→ /dashboard/profile
```

로 Redirect하는 것도 가능합니다.

```jsx
<Route
  index
  element={<Navigate to="profile" replace />}
/>
```

따라서 질문은:

```text
"부모 URL 자체를 유지하면서
 기본 화면을 보여줄 것인가?"

        또는

"특정 Child URL로
 실제 이동시킬 것인가?"
```

입니다.

# 20. 여러 단계 Nested Route에서도 Index Route를 사용할 수 있다

다음 Route를 보겠습니다.

```jsx
<Routes>
  <Route path="/admin" element={<AdminLayout />}>

    <Route
      index
      element={<AdminHome />}
    />

    <Route
      path="users"
      element={<UsersLayout />}
    >
      <Route
        index
        element={<UserList />}
      />

      <Route
        path=":userId"
        element={<UserDetail />}
      />
    </Route>

  </Route>
</Routes>
```

Route Tree:

```text
Admin
│
├── index
│   └── AdminHome
│
└── Users
    │
    ├── index
    │   └── UserList
    │
    └── :userId
        └── UserDetail
```

URL별 결과:

```text
/admin
→ AdminHome

/admin/users
→ UserList

/admin/users/100
→ UserDetail
```

즉:

> **Nested Route의 각 부모는 자신의 Index Route를 가질 수 있습니다.**

---

# 21. Route Branch 관점에서 이해하면 더 쉽다

다음 URL을 보겠습니다.

```text
/admin/users
```

Route Tree:

```text
Admin
│
├── index
│
└── Users
    │
    ├── index
    └── :userId
```

현재 URL에 해당하는 Branch는:

```text
Admin
   │
   ▼
Users
   │
   ▼
index
```

입니다.

따라서 렌더링 구조는:

```text
AdminLayout
    │
    ▼
  Outlet
    │
    ▼
UsersLayout
    │
    ▼
  Outlet
    │
    ▼
 UserList
```

가 됩니다.

이것을 이해하면 Index Route가 단순한 옵션이 아니라 **Route Tree 안에 존재하는 실제 Child Route**라는 점이 분명해집니다.

---

# 22. 흔한 실수 ① Index Route에 `path` 작성

다음과 같이 작성하지 않습니다.

```jsx
<Route
  index
  path="home"
  element={<Home />}
/>
```

Index Route는 부모 URL 자체에 대응하므로 별도의 `path`를 갖지 않습니다.

올바른 형태:

```jsx
<Route
  index
  element={<Home />}
/>
```

특정 URL segment가 필요하다면 일반 Child Route를 사용합니다.

```jsx
<Route
  path="home"
  element={<Home />}
/>
```

---

# 23. 흔한 실수 ② Index Route를 Parent Route라고 생각

다음 구조에서:

```jsx
<Route path="/dashboard" element={<DashboardLayout />}>
  <Route index element={<DashboardHome />} />
</Route>
```

`DashboardHome`이 `/dashboard`에 표시되기 때문에 부모 element라고 착각하기 쉽습니다.

하지만 구조는:

```text
Parent Route
Dashboard
│
└── Child Route
    index
```

입니다.

렌더링 역시:

```text
DashboardLayout
      │
      ▼
    Outlet
      │
      ▼
DashboardHome
```

입니다.

# 24. 흔한 실수 ③ Index Route가 모든 Child Route와 함께 렌더링된다고 생각

Index Route는:

```text
기본 자식
```

이지:

```text
항상 렌더링되는 자식
```

이 아닙니다.

예를 들어:

```text
/dashboard
→ index

/dashboard/profile
→ profile
```

입니다.

따라서 `/dashboard/profile`에서는:

```text
DashboardHome + Profile
```

가 아니라:

```text
Profile
```

이 Outlet에 렌더링됩니다.

# 26. Index Route의 진짜 핵심

Index Route를 단순히:

> "`path`가 없는 Route"

라고 외우면 부족합니다.

핵심은:

```text
Parent Route가 매칭됨
        │
        ▼
추가 Child Path 없음
        │
        ▼
Index Route가 있는가?
        │
     ┌──┴──┐
    YES    NO
     │      │
     ▼      ▼
Index      Outlet에
Element    기본 Child 없음
```

입니다.

즉:

> **부모 Route 자체가 최종 URL일 때 어떤 Child Route를 기본으로 사용할 것인지를 정의하는 것이 Index Route입니다.**

---

# 27. 한 문장 정의

입문자용으로는:

> **Index Route는 부모 URL 자체에 접속했을 때 기본으로 보여주는 자식 Route입니다.**

조금 더 정확하게 표현하면:

> **Index Route는 Nested Route 구조에서 부모 Route가 매칭되고 추가적인 자식 path segment가 없을 때 기본으로 매칭되는 Child Route입니다.**

# 28. 최종 정리

Index Route의 구조:

```jsx
<Route
  path="/dashboard"
  element={<DashboardLayout />}
>
  <Route
    index
    element={<DashboardHome />}
  />

  <Route
    path="profile"
    element={<Profile />}
  />
</Route>
```

핵심 관계:

```text
/dashboard
    │
    ▼
Dashboard
    │
    ▼
Index Route
    │
    ▼
DashboardHome
```

반면:

```text
/dashboard/profile
        │
        ▼
Dashboard
        │
        ▼
Profile Route
        │
        ▼
Profile
```

입니다.

따라서 세 개념을 함께 기억하면 좋습니다.

```text
Nested Route
────────────────────────
Route에 부모-자식
계층 관계를 만든다.


Index Route
────────────────────────
부모 URL 자체에서
기본 Child Route를 선택한다.


Outlet
────────────────────────
선택된 Child Route의 element가
부모 UI 어디에 렌더링될지 지정한다.
```

마지막으로 한 문장으로 정리하면:

> **Nested Route가 부모와 자식의 Route 구조를 만들고, Index Route가 부모 URL의 기본 자식을 결정하며, `<Outlet />`이 그 자식 element가 부모 Layout 안에 렌더링될 위치를 제공합니다.**
