# React Router Nested Route

## — URL 구조와 UI 구조를 부모-자식 Route로 표현하기

React Router에서 애플리케이션이 커지기 시작하면 다음과 같은 URL 구조를 자주 만나게 됩니다.

```text
/products
/products/100
/products/200

/users
/users/10
/users/20

/dashboard
/dashboard/profile
/dashboard/settings
```

여기서 중요한 특징이 있습니다.

```text
/dashboard
/dashboard/profile
/dashboard/settings
```

세 URL은 완전히 독립적인 URL처럼 보이지만 실제 애플리케이션 구조에서는 서로 관련되어 있습니다.

```text
dashboard
│
├── profile
└── settings
```

React Router에서는 이러한 **계층적인 URL과 UI 관계를 Route의 부모-자식 구조로 표현할 수 있습니다.**

이것이 **Nested Route(중첩 라우트)**입니다.

---

# 1. Nested Route란?

한 문장으로 정의하면:

> **Nested Route는 `<Route>` 안에 다른 `<Route>`를 배치하여 Route 사이에 부모-자식 계층 관계를 만드는 라우팅 구조입니다.**

예를 들어:

```jsx
<Routes>
  <Route path="/dashboard" element={<Dashboard />}>
    <Route path="profile" element={<Profile />} />
    <Route path="settings" element={<Settings />} />
  </Route>
</Routes>
```

Route 구조만 보면:

```text
Route path="/dashboard"
│
├── Route path="profile"
│
└── Route path="settings"
```

입니다.

React Router는 이것을 하나의 **Route Tree**로 구성합니다.

```text
/dashboard
│
├── profile
│
└── settings
```

그리고 부모와 자식의 `path`를 조합하여 다음 URL을 표현할 수 있습니다.

```text
/dashboard
/dashboard/profile
/dashboard/settings
```

즉 Nested Route의 첫 번째 핵심은:

> **Route를 계층적으로 구성할 수 있다는 것입니다.**

---

# 2. 왜 Route를 중첩하는가?

다음 애플리케이션을 생각해보겠습니다.

```text
Dashboard
│
├── Profile
├── Settings
└── Statistics
```

화면 구조는 다음과 같다고 하겠습니다.

```text
┌─────────────────────────────────┐
│ Dashboard                       │
├────────────┬────────────────────┤
│            │                    │
│ Menu       │   Content          │
│            │                    │
│ Profile    │                    │
│ Settings   │                    │
│ Statistics │                    │
│            │                    │
└────────────┴────────────────────┘
```

사용자가 어떤 메뉴를 선택하더라도:

```text
Dashboard 제목
Menu
전체 Layout
```

은 그대로 유지하고,

오른쪽 Content 부분만:

```text
Profile
Settings
Statistics
```

중 하나로 바꾸고 싶습니다.

URL도 다음과 같이 만들고 싶습니다.

```text
/dashboard/profile
/dashboard/settings
/dashboard/statistics
```

여기에는 명확한 계층 관계가 있습니다.

```text
Dashboard
    │
    ├── Profile
    ├── Settings
    └── Statistics
```

따라서 Route도 같은 구조로 표현하는 것이 자연스럽습니다.

```text
Dashboard Route
    │
    ├── Profile Route
    ├── Settings Route
    └── Statistics Route
```

이것이 Nested Route가 필요한 가장 중요한 이유입니다.

---

# 3. Nested Route를 사용하지 않는다면?

물론 모든 Route를 평평하게 작성할 수도 있습니다.

```jsx
<Routes>
  <Route
    path="/dashboard"
    element={<Dashboard />}
  />

  <Route
    path="/dashboard/profile"
    element={<Profile />}
  />

  <Route
    path="/dashboard/settings"
    element={<Settings />}
  />

  <Route
    path="/dashboard/statistics"
    element={<Statistics />}
  />
</Routes>
```

Route Tree는 사실상 다음과 같은 형태입니다.

```text
Routes
│
├── /dashboard
│
├── /dashboard/profile
│
├── /dashboard/settings
│
└── /dashboard/statistics
```

URL 문자열에는 `/dashboard`가 반복되지만 Route 자체의 부모-자식 관계는 코드에서 드러나지 않습니다.

하지만 실제 UI 구조는:

```text
Dashboard
│
├── Profile
├── Settings
└── Statistics
```

일 수 있습니다.

즉 **URL과 UI는 계층적인데 Route 정의는 평평한 구조**가 됩니다.

---

# 4. Nested Route로 바꾸면

다음처럼 작성할 수 있습니다.

```jsx
<Routes>
  <Route
    path="/dashboard"
    element={<Dashboard />}
  >
    <Route
      path="profile"
      element={<Profile />}
    />

    <Route
      path="settings"
      element={<Settings />}
    />

    <Route
      path="statistics"
      element={<Statistics />}
    />
  </Route>
</Routes>
```

이제 JSX 구조 자체가:

```text
Dashboard
│
├── Profile
├── Settings
└── Statistics
```

라는 관계를 표현합니다.

즉:

```text
URL 구조

/dashboard
    ├── /profile
    ├── /settings
    └── /statistics


Route 구조

Dashboard
    ├── Profile
    ├── Settings
    └── Statistics


UI 구조

Dashboard Layout
    ├── Profile Content
    ├── Settings Content
    └── Statistics Content
```

가 서로 대응하기 시작합니다.

---

# 5. 부모 Route와 자식 Route

Nested Route에서는 반드시 두 가지 개념을 구분해야 합니다.

```jsx
<Route path="/dashboard" element={<Dashboard />}>
  <Route path="profile" element={<Profile />} />
</Route>
```

여기서:

```jsx
<Route
  path="/dashboard"
  element={<Dashboard />}
/>
```

는 **Parent Route**입니다.

그리고:

```jsx
<Route
  path="profile"
  element={<Profile />}
/>
```

는 **Child Route**입니다.

구조:

```text
Parent Route
/dashboard
    │
    └── Child Route
        profile
```

React Router는 이 계층 관계를 이용하여 전체 URL 경로를 구성합니다.

```text
/dashboard
+
profile

↓

/dashboard/profile
```

---

# 6. 자식 Route의 path에는 왜 `/`가 없는가?

Nested Route를 처음 배우면 가장 많이 궁금해하는 부분입니다.

```jsx
<Route path="/dashboard">
  <Route path="profile" />
</Route>
```

왜 자식 Route를:

```jsx
path="/dashboard/profile"
```

이라고 하지 않고:

```jsx
path="profile"
```

이라고 작성할까요?

자식 Route의 상대 `path`는 **부모 Route의 경로를 기준으로 해석되기 때문입니다.**

```text
Parent

/dashboard
     │
     ▼
Child

profile
```

React Router가 계층을 따라 조합하면:

```text
/dashboard + profile
        ↓
/dashboard/profile
```

이 됩니다.

마찬가지로:

```jsx
<Route path="/dashboard">
  <Route path="settings" />
</Route>
```

는:

```text
/dashboard/settings
```

를 표현합니다.

---

# 7. 이것이 Relative Route의 핵심이다

자식 Route에서:

```jsx
path="profile"
```

처럼 부모 경로를 기준으로 작성하는 것을 **Relative Path** 관점에서 이해할 수 있습니다.

```text
Parent Route
/dashboard
│
├── profile
├── settings
└── statistics
```

각 자식이 자신의 전체 URL을 반복해서 알 필요가 없습니다.

```text
❌ /dashboard/profile
❌ /dashboard/settings
❌ /dashboard/statistics
```

대신 부모 아래에서 자신의 부분만 표현합니다.

```text
✓ profile
✓ settings
✓ statistics
```

이 구조의 장점은 부모 경로가 바뀌었을 때 더 명확합니다.

예를 들어:

```text
/dashboard
```

를:

```text
/admin
```

으로 변경한다고 하겠습니다.

Nested Route라면 부모만:

```jsx
<Route path="/admin" element={<Dashboard />}>
```

로 변경할 수 있습니다.

자식은 그대로입니다.

```jsx
<Route path="profile" element={<Profile />} />
<Route path="settings" element={<Settings />} />
```

결과:

```text
/admin/profile
/admin/settings
```

---

# 8. Nested Route는 단순한 문자열 결합이 아니다

여기서 한 단계 더 정확하게 이해해야 합니다.

Nested Route를 단순히:

```text
"/dashboard" + "/profile"
```

이라는 문자열 합치기 기능으로 생각하면 부족합니다.

React Router가 만드는 것은 **Route 계층 구조**입니다.

```text
Route Tree

Dashboard
│
├── Profile
├── Settings
└── Statistics
```

URL이:

```text
/dashboard/profile
```

이라면 React Router는 Route Tree를 따라 현재 URL에 해당하는 **Route Branch**를 찾습니다.

개념적으로:

```text
Route Tree

Root
│
└── Dashboard        ← match
    │
    ├── Profile      ← match
    ├── Settings
    └── Statistics
```

따라서 현재 매칭된 Branch는:

```text
Root
 ↓
Dashboard
 ↓
Profile
```

입니다.

이 개념이 Nested Route에서 매우 중요합니다.

---

# 9. URL 하나가 여러 Route와 매칭될 수 있다

일반적인 Route를 처음 배우면 다음처럼 생각하기 쉽습니다.

```text
URL 하나
   ↓
Route 하나
   ↓
Component 하나
```

예:

```text
/about
   ↓
About Route
   ↓
<About />
```

하지만 Nested Route에서는 조금 다릅니다.

URL:

```text
/dashboard/profile
```

은 계층적으로:

```text
/dashboard
       ↓
Dashboard Route

/dashboard/profile
       ↓
Profile Route
```

와 연결됩니다.

즉 현재 Route Branch는:

```text
Dashboard Route
      │
      ▼
Profile Route
```

가 됩니다.

이것이 Nested Route를 이해하는 핵심적인 변화입니다.

> **중첩 라우팅에서는 현재 URL이 Route Tree의 한 경로(branch)를 선택한다고 생각하면 좋습니다.**

---

# 10. Route Tree와 Route Branch

다음 Route가 있다고 하겠습니다.

```jsx
<Routes>
  <Route path="/dashboard" element={<Dashboard />}>
    <Route path="profile" element={<Profile />} />
    <Route path="settings" element={<Settings />} />
  </Route>
</Routes>
```

Route Tree:

```text
Dashboard
├── Profile
└── Settings
```

URL이:

```text
/dashboard/profile
```

이면 선택되는 Branch:

```text
Dashboard
   │
   ▼
Profile
```

URL이:

```text
/dashboard/settings
```

이면:

```text
Dashboard
   │
   ▼
Settings
```

입니다.

따라서 Route Tree 전체를 매번 렌더링하는 것이 아닙니다.

현재 URL과 일치하는 **Branch를 선택**합니다.

---

# 11. 그런데 여기서 중요한 문제가 생긴다

URL이:

```text
/dashboard/profile
```

이고 다음 두 Route가 매칭되었습니다.

```text
Dashboard
   │
   ▼
Profile
```

각 Route에는 `element`가 있습니다.

```jsx
<Route
  path="/dashboard"
  element={<Dashboard />}
/>

<Route
  path="profile"
  element={<Profile />}
/>
```

그러면 React Router는 개념적으로:

```text
Dashboard element
+
Profile element
```

를 렌더링해야 합니다.

그런데 여기서 중요한 질문이 생깁니다.

> **`<Profile />`은 `<Dashboard />` 화면의 정확히 어디에 들어가야 할까요?**

---

# 12. React Router는 부모 컴포넌트의 Layout을 마음대로 알 수 없다

예를 들어 `Dashboard`가 다음과 같다고 하겠습니다.

```jsx
function Dashboard() {
  return (
    <div>
      <header>Dashboard</header>

      <nav>
        Profile | Settings
      </nav>

      <main>
        ???
      </main>
    </div>
  );
}
```

우리는 자식 페이지를:

```html
<main>
```

안에 넣고 싶습니다.

```text
┌────────────────────────────┐
│ Dashboard                  │
├────────────────────────────┤
│ Profile | Settings         │
├────────────────────────────┤
│                            │
│       Profile Page         │
│                            │
└────────────────────────────┘
```

하지만 React Router는 `Dashboard` 컴포넌트의 JSX를 보고 임의로:

> "`<main>`이 있으니 여기에 Profile을 넣어야겠다."

라고 판단하지 않습니다.

어디에 자식 Route의 element를 넣을지는 **개발자가 지정해야 합니다.**

바로 여기에서 `Outlet`이 필요해집니다.

---

# 13. Nested Route와 Outlet의 관계

전체 관계를 먼저 보면:

```text
URL
/dashboard/profile
        │
        ▼
Route Matching
        │
        ▼
Route Branch

Dashboard
   │
   ▼
Profile
```

React Router는:

```text
Dashboard element
+
Profile element
```

를 알고 있습니다.

하지만 화면을 구성하려면:

```text
Dashboard
┌───────────────────────────┐
│ Header                    │
│ Navigation                │
│                           │
│  ┌─────────────────────┐  │
│  │ Profile은 어디에?   │  │
│  └─────────────────────┘  │
│                           │
└───────────────────────────┘
```

이라는 문제가 남습니다.

이 문제를 해결하는 것이:

```jsx
<Outlet />
```

입니다.

개념적으로:

```text
Dashboard
│
├── Header
├── Navigation
└── <Outlet />
       │
       ▼
현재 매칭된 Child Route
       │
       ▼
     Profile
```

입니다.

---

# 14. 하지만 지금은 Outlet보다 Nested Route가 먼저다

여기서 학습 순서가 중요합니다.

`Outlet`부터 배우면:

> "`Outlet`은 자식 컴포넌트를 보여주는 곳인가?"

정도로 이해하기 쉽습니다.

하지만 실제 흐름은 반대입니다.

먼저:

```text
Route가 부모-자식으로 중첩된다.
        ↓
현재 URL에 따라
Route Branch가 결정된다.
        ↓
부모 Route와 자식 Route가
동시에 매칭될 수 있다.
        ↓
부모 element 안에
자식 element를 렌더링해야 한다.
        ↓
그런데 어디에?
        ↓
<Outlet />
```

입니다.

즉:

> **Outlet 때문에 Nested Route가 존재하는 것이 아니라, Nested Route의 자식 element를 부모 UI 안에 배치해야 하기 때문에 Outlet이 필요합니다.**

---

# 15. 조금 더 현실적인 Route 구조

쇼핑몰의 마이페이지를 생각해보겠습니다.

URL:

```text
/mypage
/mypage/orders
/mypage/profile
/mypage/address
```

UI:

```text
MyPage
│
├── Orders
├── Profile
└── Address
```

Route:

```jsx
<Routes>
  <Route
    path="/mypage"
    element={<MyPage />}
  >
    <Route
      path="orders"
      element={<Orders />}
    />

    <Route
      path="profile"
      element={<Profile />}
    />

    <Route
      path="address"
      element={<Address />}
    />
  </Route>
</Routes>
```

Route Tree:

```text
MyPage (/mypage)
│
├── Orders  (orders)
├── Profile (profile)
└── Address (address)
```

최종 URL:

```text
/mypage/orders
/mypage/profile
/mypage/address
```

입니다.

이제 URL이:

```text
/mypage/orders
```

라면 Branch는:

```text
MyPage
  ↓
Orders
```

가 됩니다.

따라서 최종 화면 역시 개념적으로:

```text
MyPage Layout
     │
     └── Orders Content
```

가 되어야 합니다.

---

# 16. Nested Route는 UI 계층과 잘 맞는다

React 애플리케이션 자체도 컴포넌트 트리를 가지고 있습니다.

```text
App
│
└── Dashboard
    │
    ├── Sidebar
    ├── Header
    └── Profile
```

Route도 비슷하게:

```text
Root Route
│
└── Dashboard Route
    │
    └── Profile Route
```

URL도:

```text
/
└── dashboard
    └── profile
```

처럼 계층적입니다.

따라서 Nested Route를 사용하면:

```text
URL 계층
     ↕
Route 계층
     ↕
UI 계층
```

을 서로 대응시킬 수 있습니다.

이것이 Nested Route의 가장 중요한 설계상의 의미입니다.

---

# 17. 여러 단계로 중첩할 수도 있다

Nested Route는 한 단계만 가능한 것이 아닙니다.

예:

```jsx
<Routes>
  <Route path="/admin" element={<Admin />}>
    <Route path="users" element={<Users />}>
      <Route
        path=":userId"
        element={<UserDetail />}
      />
    </Route>
  </Route>
</Routes>
```

Route Tree:

```text
Admin
 │
 └── Users
      │
      └── UserDetail
```

URL:

```text
/admin/users/100
```

Route Branch:

```text
Admin
  ↓
Users
  ↓
UserDetail
```

그리고:

```text
userId = "100"
```

이라는 Path Parameter도 얻을 수 있습니다.

즉 이전에 배운 `useParams()`와 Nested Route도 자연스럽게 연결됩니다.

---

# 18. URL을 분해해서 보면 더 쉽다

URL:

```text
/admin/users/100
```

Route 정의:

```text
Parent
/admin

Child
users

Grand Child
:userId
```

계층:

```text
/admin
   │
   └── users
         │
         └── :userId
```

최종적으로:

```text
/admin/users/:userId
```

라는 Route Pattern이 됩니다.

실제 URL:

```text
/admin/users/100
```

이 들어오면:

```text
/admin       → Admin
/users       → Users
/100         → UserDetail

params
userId = "100"
```

로 이해할 수 있습니다.

---

# 19. Nested Route의 핵심은 Layout 재사용에도 있다

Nested Route가 실무에서 많이 사용되는 가장 큰 이유 중 하나가 **Layout 재사용**입니다.

예를 들어 Dashboard에서:

```text
Header
Sidebar
```

는 계속 유지하고 싶습니다.

변하는 것은:

```text
Profile
Settings
Statistics
```

뿐입니다.

```text
/dashboard/profile

┌───────────────────────────┐
│ Header                    │
├─────────┬─────────────────┤
│ Sidebar │ Profile         │
│         │                 │
└─────────┴─────────────────┘
```

그리고:

```text
/dashboard/settings

┌───────────────────────────┐
│ Header                    │
├─────────┬─────────────────┤
│ Sidebar │ Settings        │
│         │                 │
└─────────┴─────────────────┘
```

즉:

```text
고정
──────
Header
Sidebar


변경
──────
Profile
Settings
Statistics
```

입니다.

Nested Route는 이러한 **공통 Layout + 변경되는 Child Page** 구조를 Route 계층으로 표현하기에 매우 적합합니다.

---

# 20. 일반 React의 `children`과는 다른 개념이다

여기서 React의 `children`과 혼동할 수 있습니다.

일반 React에서는:

```jsx
<Dashboard>
  <Profile />
</Dashboard>
```

라고 하면:

```jsx
function Dashboard({ children }) {
  return (
    <main>
      {children}
    </main>
  );
}
```

처럼 `children`을 사용할 수 있습니다.

하지만 Nested Route는 JSX에서 직접:

```jsx
<Dashboard>
  <Profile />
</Dashboard>
```

를 작성한 것이 아닙니다.

우리가 작성한 것은:

```jsx
<Route
  path="/dashboard"
  element={<Dashboard />}
>
  <Route
    path="profile"
    element={<Profile />}
  />
</Route>
```

입니다.

즉:

```text
Route의 자식
```

과:

```text
React Component의 children
```

은 같은 개념이 아닙니다.

이 차이를 반드시 구분해야 합니다.

---

# 21. 가장 흔한 오해

Nested Route를 처음 배우면 다음처럼 생각하기 쉽습니다.

```jsx
<Route path="/dashboard" element={<Dashboard />}>
  <Route path="profile" element={<Profile />} />
</Route>
```

그러면 React가 이것을 자동으로:

```jsx
<Dashboard>
  <Profile />
</Dashboard>
```

로 바꿔준다고 생각할 수 있습니다.

하지만 그렇게 이해하면 안 됩니다.

Route Tree는:

```text
Dashboard Route
      │
      └── Profile Route
```

라는 **라우팅 계층**입니다.

그리고 현재 URL을 기반으로:

```text
어떤 Route Branch가 매칭되는가?
```

를 결정합니다.

매칭된 Child Route의 element를 부모 컴포넌트 내부 어디에 렌더링할지는 별도의 메커니즘이 필요합니다.

그 역할이 다음 장에서 배울:

```jsx
<Outlet />
```

입니다.

# 22. Nested Route 전체 흐름

다음 Route를 기준으로 전체 과정을 정리해보겠습니다.

```jsx
<Routes>
  <Route
    path="/dashboard"
    element={<Dashboard />}
  >
    <Route
      path="profile"
      element={<Profile />}
    />

    <Route
      path="settings"
      element={<Settings />}
    />
  </Route>
</Routes>
```

사용자가:

```text
/dashboard/profile
```

로 이동합니다.

React Router의 개념적인 흐름:

```text
Browser URL
/dashboard/profile
        │
        ▼
React Router
        │
        ▼
Route Tree 확인
        │
        ▼
Dashboard Route Match
        │
        ▼
Profile Route Match
        │
        ▼
Route Branch 결정

Dashboard
   │
   ▼
Profile
```

이제 React Router가 알고 있는 것은:

```text
Parent Element
<Dashboard />

Child Element
<Profile />
```

입니다.

그리고 마지막 문제가 남습니다.

```text
<Dashboard />

┌───────────────────────────┐
│ Header                    │
│ Menu                      │
│                           │
│   Profile을 어디에?       │
│                           │
└───────────────────────────┘
```

이 문제를 해결하는 것이 바로 다음 장의 주제입니다.

# `<Outlet />`

---

# 23. Nested Route를 한 문장으로 정의한다면

가장 간단하게는:

> **Nested Route는 Route를 부모-자식 구조로 중첩하여 계층적인 URL과 UI 구조를 표현하는 React Router의 라우팅 방식입니다.**

조금 더 정확하게 표현하면:

> **Nested Route는 `<Route>` 내부에 Child `<Route>`를 정의하여 Route Tree를 만들고, 현재 URL에 따라 부모 Route부터 자식 Route까지 하나의 매칭된 Route Branch를 구성하는 방식입니다.**

---

# 24. 핵심 정리

Nested Route에서 반드시 기억해야 할 것은 다음입니다.

```text
Nested Route
     │
     ├── Route에 부모-자식 관계를 만든다
     │
     ├── Parent path를 기준으로
     │   Child path를 상대적으로 작성할 수 있다
     │
     ├── 계층적인 URL을 표현한다
     │
     ├── Route Tree를 만든다
     │
     ├── 현재 URL에 따라
     │   Route Branch가 결정된다
     │
     └── 공통 Layout + Child Page
         구조를 표현하기 좋다
```

그리고 가장 중요한 흐름은:

```text
URL
/dashboard/profile
        │
        ▼
Route Tree
        │
        ▼
Matching
        │
        ▼
Route Branch

Dashboard
   │
   ▼
Profile
```

입니다.

하지만 아직 하나의 질문이 남아 있습니다.

```text
Dashboard Route
      │
      ▼
<Dashboard />

Profile Route
      │
      ▼
<Profile />
```

두 Route가 모두 매칭되었다면,

> **`<Profile />`은 `<Dashboard />`의 정확히 어디에 렌더링되어야 할까요?**

React Router가 부모 컴포넌트의 JSX에서 그 위치를 임의로 결정할 수는 없습니다.

따라서 개발자가 **자식 Route의 element가 렌더링될 위치를 명시적으로 지정해야 합니다.**

그 위치를 표시하는 컴포넌트가 바로:

```jsx
<Outlet />
```

입니다.

따라서 학습 흐름은 다음과 같습니다.

```text
Nested Route
     │
     ▼
Route Tree
     │
     ▼
Route Matching
     │
     ▼
Route Branch
     │
     ▼
Parent + Child Route가 매칭됨
     │
     ▼
"Child element를
 Parent UI 어디에 렌더링하지?"
     │
     ▼
<Outlet />
```

**다음 장에서는 이 `<Outlet />`이 Nested Route의 매칭 결과를 실제 UI 구조로 어떻게 연결하는지 살펴봅니다.**
