`Route Object`는 `createBrowserRouter()`를 이해할 때 핵심입니다.

한 문장으로 정리하면:

> **Route Object는 "특정 URL이 매칭되었을 때 어떤 UI를 렌더링하고, 어떤 데이터를 읽고, 어떤 데이터를 변경하고, 어떤 에러를 처리할지"를 선언하는 라우팅 설정 객체입니다.**

예를 들어:

```jsx
const router = createBrowserRouter([
  {
    path: "/products",
    element: <Products />,
  },
]);
```

여기서:

```jsx
{
  path: "/products",
  element: <Products />,
}
```

이 객체 하나가 바로 **Route Object**입니다.

## Route Object의 기본 구조

가장 단순한 형태는 다음과 같습니다.

```jsx
{
  path: "/about",
  element: <About />,
}
```

의미는 아주 단순합니다.

```text
URL: /about
      ↓
Route Matching
      ↓
<About />
```

즉 `path`는 **어떤 URL에 매칭할지**, `element`는 **매칭되었을 때 무엇을 렌더링할지** 정의합니다.

하지만 Data Router에서는 Route Object가 훨씬 더 많은 역할을 합니다.

```jsx
{
  path,
  element,
  children,
  index,
  loader,
  action,
  errorElement,
  lazy,
  shouldRevalidate,
  ...
}
```

---

## 가장 중요한 속성들

| 속성                 | 역할                    |
| ------------------ | --------------------- |
| `path`             | URL 경로 정의             |
| `element`          | 렌더링할 React Element    |
| `children`         | 중첩 Route 정의           |
| `index`            | 부모 Route의 기본 자식 Route |
| `loader`           | Route 진입 전에 데이터 로딩    |
| `action`           | 데이터 생성/수정/삭제 처리       |
| `errorElement`     | Route 에러 처리 UI        |
| `lazy`             | Route 모듈을 지연 로딩       |
| `shouldRevalidate` | loader 재실행 여부 제어      |

---

## 1. path

`path`는 Route가 매칭될 URL 패턴을 정의합니다.

```jsx
{
  path: "/products",
  element: <Products />,
}
```

그러면:

```text
/products
    ↓
Products Route
```

가 됩니다.

동적 파라미터도 사용할 수 있습니다.

```jsx
{
  path: "/products/:id",
  element: <ProductDetail />,
}
```

예를 들어:

```text
/products/10
```

이면:

```text
id = "10"
```

으로 매칭됩니다.

컴포넌트에서는:

```jsx
const { id } = useParams();
```

로 사용할 수 있습니다.

---

## 2. element

`element`는 해당 Route가 매칭되었을 때 렌더링할 React Element입니다.

```jsx
{
  path: "/products",
  element: <Products />,
}
```

여기서 중요한 점은:

```jsx
element: Products
```

가 아니라 일반적으로:

```jsx
element: <Products />
```

처럼 **React Element를 넣는다는 점**입니다.

즉:

```text
Route Matching
      ↓
element
      ↓
<Products />
```

입니다.

---

## 3. children

`children`은 중첩 Route를 만들 때 사용합니다.

```jsx
{
  path: "/",
  element: <RootLayout />,
  children: [
    {
      path: "products",
      element: <Products />,
    },
    {
      path: "about",
      element: <About />,
    },
  ],
}
```

구조적으로:

```text
/
└─ RootLayout
   ├─ /products
   │   └─ Products
   └─ /about
       └─ About
```

가 됩니다.

부모의 `element` 안에는 보통 `<Outlet>`이 필요합니다.

```jsx
function RootLayout() {
  return (
    <>
      <Header />
      <Outlet />
      <Footer />
    </>
  );
}
```

`/products`라면:

```text
RootLayout
├─ Header
├─ Outlet
│   └─ Products
└─ Footer
```

로 렌더링됩니다.

---

## 4. index

`index`는 부모 Route의 기본 자식 Route를 정의합니다.

```jsx
{
  path: "/",
  element: <RootLayout />,
  children: [
    {
      index: true,
      element: <Home />,
    },
  ],
}
```

이 경우:

```text
/
```

로 들어가면 자식 경로를 추가하지 않아도:

```text
Home
```

이 렌더링됩니다.

즉:

```text
부모 Route 기본 화면
```

이라고 이해하면 됩니다.

`index: true`인 Route에는 일반적으로 별도의 `path`를 두지 않습니다.

---

## 5. loader

`loader`는 Route에 필요한 데이터를 가져오는 함수입니다.

```jsx
{
  path: "/products",
  element: <Products />,
  loader: async () => {
    const response = await fetch("/api/products");
    return response.json();
  },
}
```

흐름은:

```text
/products 이동
      ↓
Route Matching
      ↓
loader()
      ↓
fetch()
      ↓
데이터 반환
      ↓
Router가 loaderData 저장
      ↓
Products 렌더링
```

컴포넌트에서는:

```jsx
const products = useLoaderData();
```

로 받습니다.

이 부분은 Data Router의 중요한 특징입니다.

전통적인 방식:

```jsx
useEffect(() => {
  fetch(...);
}, []);
```

에서는 컴포넌트가 먼저 렌더링된 뒤 요청이 시작됩니다.

하지만 `loader`를 쓰면 **navigation 과정 자체에서 데이터를 준비**할 수 있습니다.

---

## 6. action

`action`은 데이터 변경 작업을 담당합니다.

예:

```jsx
{
  path: "/products/new",
  element: <NewProduct />,
  action: async ({ request }) => {
    const formData = await request.formData();

    return fetch("/api/products", {
      method: "POST",
      body: formData,
    });
  },
}
```

대개:

```text
POST
PUT
PATCH
DELETE
```

같은 변경 작업과 연결됩니다.

흐름은:

```text
<Form> submit
      ↓
Router
      ↓
action()
      ↓
POST /api/products
      ↓
데이터 변경
      ↓
필요한 loader revalidation
      ↓
UI 갱신
```

즉:

```text
loader = 읽기
action = 변경
```

이라고 이해하면 좋습니다.

---

## 7. errorElement

`errorElement`는 해당 Route에서 발생한 오류를 처리하는 UI입니다.

```jsx
{
  path: "/products",
  element: <Products />,
  loader: productsLoader,
  errorElement: <ProductsError />,
}
```

예를 들어 `loader`에서 오류가 발생하면:

```text
loader 실행
   ↓
에러 발생
   ↓
errorElement
   ↓
<ProductsError />
```

로 처리됩니다.

컴포넌트에서는:

```jsx
const error = useRouteError();
```

를 사용할 수 있습니다.

---

## 8. lazy

`lazy`는 Route 관련 코드를 나중에 로딩할 때 사용할 수 있습니다.

즉 초기 번들에 모든 Route 코드를 넣는 대신, 해당 Route가 필요해질 때 로드하는 구조를 만들 수 있습니다.

개념적으로:

```text
앱 시작
  ↓
Home 코드만 로딩

/products 이동
  ↓
Products Route 코드 로딩
```

이런 방식입니다.

큰 애플리케이션에서는 코드 분할에 유용합니다.

---

## 9. shouldRevalidate

Data Router는 navigation이나 action 이후 loader를 다시 실행할 수 있습니다.

`shouldRevalidate`는 이 재실행 여부를 세밀하게 제어할 때 사용합니다.

개념적으로:

```text
action 실행
   ↓
데이터 변경
   ↓
loader 다시 실행해야 할까?
   ↓
shouldRevalidate()
   ↓
true / false
```

입니다.

즉 불필요한 재요청을 줄이거나 특별한 데이터 갱신 정책을 만들 때 사용할 수 있습니다.

---

# Route Object는 단순 URL 매핑 객체가 아니다

초보 단계에서는 보통 다음처럼 생각합니다.

```text
URL
 ↓
Component
```

예를 들어:

```jsx
{
  path: "/about",
  element: <About />,
}
```

하지만 `createBrowserRouter`에서 Route Object의 실제 개념은 훨씬 넓습니다.

```text
Route Object
│
├─ URL 매칭
│    └─ path
│
├─ UI
│    └─ element
│
├─ 계층 구조
│    ├─ children
│    └─ index
│
├─ 데이터 읽기
│    └─ loader
│
├─ 데이터 변경
│    └─ action
│
├─ 에러 처리
│    └─ errorElement
│
└─ 고급 제어
     ├─ lazy
     └─ shouldRevalidate
```

따라서 Route Object를 가장 정확하게 표현하면:

> **Route Object는 하나의 URL 경로에 대한 UI, 데이터, 에러, 중첩 구조, navigation 동작을 함께 선언하는 라우팅 단위입니다.**

## 전체 예제

```jsx
const router = createBrowserRouter([
  {
    path: "/",
    element: <RootLayout />,
    errorElement: <RootError />,
    children: [
      {
        index: true,
        element: <Home />,
      },
      {
        path: "products",
        element: <Products />,
        loader: productsLoader,
      },
      {
        path: "products/:id",
        element: <ProductDetail />,
        loader: productDetailLoader,
      },
      {
        path: "products/new",
        element: <NewProduct />,
        action: createProductAction,
      },
    ],
  },
]);
```

이 설정을 구조로 보면:

```text
Route Object[]
      │
      ▼
/
RootLayout
│
├─ errorElement → RootError
│
├─ index
│    └─ Home
│
├─ products
│    ├─ Products
│    └─ loader
│
├─ products/:id
│    ├─ ProductDetail
│    └─ loader
│
└─ products/new
     ├─ NewProduct
     └─ action
```

그리고 이 모든 Route Object들을:

```jsx
createBrowserRouter(routes)
```

에 전달하면 Router 객체가 생성됩니다.

최종적으로:

```text
Route Object[]
      ↓
createBrowserRouter()
      ↓
Router
      ↓
RouterProvider
      ↓
React UI
```

가 됩니다.

핵심만 다시 정리하면, **Route Object는 단순한 `path → component` 매핑 객체가 아니라, 하나의 Route에 필요한 UI·데이터 로딩·데이터 변경·에러 처리·중첩 관계까지 한곳에 선언하는 설정 단위**입니다.
