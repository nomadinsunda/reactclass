# ♿ A11y란?

> **A11y**는 **Accessibility**의 약어로,
> “접근성”이란 뜻의 **Accessibility**에서 중간 11개의 알파벳을 생략하고 만든 **축약 표현**입니다.

```text
Accessibility → A + 11 characters + y → A11y
```

> ✅ A11y = **"모든 사용자가 콘텐츠와 기능에 접근할 수 있게 하는 것"**

---

## ✅ 목적

> **장애가 있거나**, **특수한 환경을 가진 사용자**들도
> 웹을 **동등하게 사용**할 수 있도록 하는 것이 목적입니다.

| 접근이 어려운 사용자 유형 | 예시                    |
| -------------- | --------------------- |
| 시각 장애인         | 화면을 보지 못함 (스크린 리더 사용) |
| 청각 장애인         | 오디오 콘텐츠 접근 불가         |
| 지체 장애인         | 마우스 사용 불가 (키보드 접근 필요) |
| 인지 장애          | 복잡한 UI/텍스트 이해 어려움     |
| 저사양 기기 사용      | 느린 네트워크, 구형 브라우저 등    |

---

## 🌐 웹 접근성(A11y)의 핵심 원칙 (WCAG 기준)

| 원칙                         | 의미                                      |
| -------------------------- | --------------------------------------- |
| **Perceivable** (인지 가능)    | 콘텐츠를 사용자가 인식할 수 있어야 함 (예: 텍스트 대체, 캡션 등) |
| **Operable** (조작 가능)       | 키보드로 조작 가능해야 함 (탭 이동, 포커스 관리 등)         |
| **Understandable** (이해 가능) | UI/내용이 명확하고 예측 가능해야 함                   |
| **Robust** (강건성)           | 다양한 보조 기술/브라우저에서도 동작해야 함                |

→ 이 4가지 원칙은 [WCAG 2.x (Web Content Accessibility Guidelines)](https://www.w3.org/WAI/WCAG21/quickref/) 표준입니다.

# 🛠️ 실전에서의 A11y 구현 요소

| 요소         | 설명                    | 예시                            |
| ---------- | --------------------- | ----------------------------- |
| `alt` 속성   | 이미지 설명 제공             | `<img src="..." alt="사과 사진">` |
| 키보드 접근성    | Tab/Enter로 탐색 및 작동 가능 | `<button>`, `<a>`, `tabIndex` |
| 스크린 리더 지원  | 시각 장애인을 위한 텍스트 출력     | `aria-label`, 시맨틱 태그          |
| 명확한 포커스 표시 | 현재 위치를 시각적으로 표시       | `:focus-visible` 스타일          |
| 색상 대비      | 텍스트와 배경의 충분한 명도 차이    | WCAG 기준: 최소 4.5:1             |
| 라이브 영역     | 동적으로 변경되는 정보 표시       | `aria-live`, `role="status"`  |

# 📘 React에서 A11y 고려사항

| 항목          | 설명                                | 예시                                               |
| ----------- | --------------------------------- | ------------------------------------------------ |
| 시맨틱 태그 사용   | `<button>`, `<nav>` 등 의미 있는 태그 사용 | `<button>` vs `<div onClick>`                    |
| `aria-*` 속성 | 접근성 속성 지정                         | `aria-label="닫기"`                                |
| 키보드 이벤트 처리  | `onKeyDown` 등으로 키보드 조작 지원         | 스페이스바/엔터 대응                                      |
| focus trap  | 모달 등에서는 포커스를 내부에 유지해야 함           | `focus-trap-react` 라이브러리 등                       |
| label 연결    | 폼 요소와 레이블 연결                      | `<label htmlFor="name">` + `<input id="name" />` |

## 🧪 접근성 테스트 도구

| 도구                               | 용도                  |
| -------------------------------- | ------------------- |
| **Lighthouse** (Chrome DevTools) | 접근성 점수 측정 (100점 만점) |
| **axe DevTools**                 | WCAG 위반 항목 실시간 탐지   |
| **VoiceOver** (macOS)            | 스크린 리더              |
| **NVDA** (Windows)               | 무료 스크린 리더           |
| **tab** 키 테스트                    | 키보드 탐색 여부 확인        |

# 🧾 요약

| 항목    | 설명                                    |
| ----- | ------------------------------------- |
| 정의    | 장애인 및 모든 사용자가 웹을 동등하게 사용할 수 있도록 만드는 것 |
| 축약어   | Accessibility → A11y (a + 11 + y)     |
| 핵심 원칙 | 인지 가능, 조작 가능, 이해 가능, 강건성 (WCAG)       |
| 중요 이유 | 윤리적 책임, 법적 기준, UX 품질, SEO 연계          |
| 개발 방법 | 시맨틱 마크업, 키보드 지원, 스크린 리더 대응 등          |

---

## 🎯 A11y는 왜 중요한가?

| 이유         | 설명                                   |
| ---------- | ------------------------------------ |
| 📈 UX 향상   | 모든 사용자에게 유리 (장애인 포함)                 |
| ⚖️ 법적 준수   | 일부 국가에서는 법적 의무 (미국 ADA, 한국 웹접근성지침 등) |
| 🌍 포용성     | 모든 사람에게 열린 웹                         |
| 🔎 SEO와 연관 | 시맨틱 구조는 검색 엔진 최적화에도 도움               |
