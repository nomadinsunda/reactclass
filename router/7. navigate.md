# React Router의 `navigate()`
React Router에서 `navigate()`는 **JavaScript 코드에서 Navigation을 실행하는 함수**입니다.

쉽게 말하면:

> `navigate()`는 React Router에게 **“이 경로로 이동해라”**라고 요청하는 함수입니다.

예를 들어:

```jsx
navigate('/about');
```

를 실행하면 브라우저 전체 페이지를 새로 요청하는 전통적인 페이지 이동과 달리, React Router가 현재 SPA 안에서 새로운 Location으로 이동하고 그에 맞는 화면을 렌더링합니다.

```text
navigate('/about')
        │
        ▼
React Router Navigation
        │
        ▼
URL / Location 변경
        │
        ▼
Route Matching
        │
        ▼
새로운 UI 렌더링
```

---

## 1. `navigate`는 어디서 오는가?

React Router v6에서는 `useNavigate()` Hook을 호출하여 `navigate` 함수를 얻습니다.

```jsx
import { useNavigate } from 'react-router-dom';

function Example() {
  const navigate = useNavigate();

  // ...
}
```

여기서 중요한 것은 `useNavigate`와 `navigate`를 구분하는 것입니다.

```text
useNavigate()
     │
     │ Hook 호출
     ▼
navigate
     │
     │ Navigation 함수
     ▼
navigate('/about')
```

즉:

> `useNavigate()`는 Hook이고, `navigate()`는 그 Hook이 반환하는 Navigation 함수입니다.

---

## 2. 기본 사용법

가장 기본적인 형태는 다음과 같습니다.

```jsx
import { useNavigate } from 'react-router-dom';

function Home() {
  const navigate = useNavigate();

  const handleClick = () => {
    navigate('/about');
  };

  return (
    <button onClick={handleClick}>
      About으로 이동
    </button>
  );
}
```

버튼을 클릭하면:

```text
현재 URL

/
    │
    │ navigate('/about')
    ▼

/about
```

으로 이동합니다.

그리고 `/about`에 해당하는 Route가 있다면:

```jsx
<Route
  path="/about"
  element={<About />}
/>
```

React Router가 해당 Route를 매칭하여 `<About />`을 화면에 렌더링합니다.

---

# 3. 왜 `navigate()`가 필요한가?

React Router에는 이미 `<Link>`가 있습니다.

```jsx
<Link to="/about">
  About
</Link>
```

그렇다면 왜 `navigate()`가 필요할까요?

두 방식은 **Navigation이 필요한 이유**가 다릅니다.

`<Link>`는 사용자가 링크를 클릭하여 이동할 때 사용합니다.

```text
사용자
  │
  │ 클릭
  ▼
<Link>
  │
  ▼
Navigation
```

반면 `navigate()`는 **프로그램의 로직에 의해 이동해야 할 때** 사용합니다.

```text
이벤트 / 조건 / 작업 결과
          │
          ▼
      navigate()
          │
          ▼
      Navigation
```

예를 들어 로그인 성공 후 자동으로 Dashboard로 이동해야 한다면 화면에 `<Link>`를 보여줄 이유가 없습니다.

```jsx
const success = await login();

if (success) {
  navigate('/dashboard');
}
```

이런 상황이 `navigate()`의 대표적인 사용 사례입니다.

---

# 4. `<Link>`와 `navigate()`의 핵심 차이

다음 두 코드는 모두 `/about`으로 이동할 수 있습니다.

```jsx
<Link to="/about">
  About
</Link>
```

```jsx
navigate('/about');
```

하지만 목적이 다릅니다.

| 구분      | `<Link>`       | `navigate()`   |
| ------- | -------------- | -------------- |
| 종류      | React 컴포넌트     | 함수             |
| 사용 목적   | 사용자에게 이동 링크 제공 | 프로그램 로직에서 이동   |
| 대표 상황   | 메뉴, 네비게이션      | 로그인 성공, 저장 완료  |
| 사용자 클릭  | 일반적으로 필요       | 반드시 필요하지 않음    |
| 선언적/명령적 | 선언적 Navigation | 명령적 Navigation |

따라서 다음 기준으로 구분하면 쉽습니다.

> 사용자가 클릭할 **링크 자체가 UI에 존재해야 한다면 `<Link>`**, 어떤 작업의 결과로 코드가 이동을 결정한다면 **`navigate()`**를 사용합니다.

---

# 5. `navigate()`가 필요한 대표적인 상황

## 로그인 성공 후 이동

```jsx
const handleLogin = async () => {
  const success = await login();

  if (success) {
    navigate('/dashboard');
  }
};
```

흐름:

```text
로그인 버튼 클릭
      │
      ▼
API 요청
      │
      ▼
로그인 성공
      │
      ▼
navigate('/dashboard')
      │
      ▼
Dashboard
```

---

## 데이터 저장 후 이동

```jsx
const handleSave = async () => {
  await saveData();

  navigate('/success');
};
```

예를 들어 게시글 작성이 완료된 후 목록 페이지나 상세 페이지로 이동할 수 있습니다.

```jsx
const post = await createPost(data);

navigate(`/posts/${post.id}`);
```

---

## 버튼 클릭에 따라 이동

```jsx
const handleClick = () => {
  navigate('/products');
};
```

```jsx
<button onClick={handleClick}>
  상품 목록으로 이동
</button>
```

버튼이 링크 역할 자체를 하는 것이라면 `<Link>`가 더 자연스러울 수 있지만, 버튼 클릭 과정에서 추가 로직을 실행한 후 이동해야 한다면 `navigate()`가 유용합니다.

---

# 6. 동적 경로로 이동

`navigate()`에는 문자열을 조합하여 동적인 URL을 전달할 수도 있습니다.

```jsx
const userId = 10;

navigate(`/users/${userId}`);
```

결과:

```text
/users/10
```

Route가:

```jsx
<Route
  path="/users/:userId"
  element={<UserDetail />}
/>
```

라면:

```text
navigate('/users/10')
        │
        ▼
/users/:userId
        │
        ▼
userId = "10"
        │
        ▼
<UserDetail />
```

처럼 연결됩니다.

---

# 7. Query Parameter와 함께 이동

Query String이 포함된 URL도 전달할 수 있습니다.

```jsx
navigate('/products?page=2&sort=latest');
```

결과:

```text
/products?page=2&sort=latest
```

즉 `navigate()`의 목적지는 단순한 pathname에 제한되지 않습니다.

---

# 8. Hash가 포함된 경로도 가능하다

```jsx
navigate('/guide#installation');
```

결과:

```text
/guide#installation
```

따라서 Navigation 목적지는 개념적으로:

```text
pathname
   +
search
   +
hash
```

를 포함할 수 있습니다.

---

# 9. 상대 경로 Navigation

`navigate()`는 절대 경로뿐 아니라 상대 경로도 사용할 수 있습니다.

```jsx
navigate('edit');
```

또는:

```jsx
navigate('../settings');
```

React Router가 현재 라우팅 문맥을 기준으로 목적지를 해석합니다.

```text
'../settings'
      │
      ▼
React Router
Path Resolution
      │
      ▼
최종 목적지
      │
      ▼
Navigation
```

이 부분은 앞에서 살펴본 `useResolvedPath()`의 상대 경로 개념과 연결됩니다.

---

# 10. 뒤로 가기와 앞으로 가기

`navigate()`에는 URL 대신 숫자를 전달할 수도 있습니다.

```jsx
navigate(-1);
```

이는 History에서 한 단계 뒤로 이동하라는 의미입니다.

```text
History

A
↓
B
↓
C  ← 현재

navigate(-1)

A
↓
B  ← 현재
↓
C
```

앞으로 이동하려면:

```jsx
navigate(1);
```

을 사용할 수 있습니다.

```text
navigate(-1)  → 한 단계 뒤로
navigate(-2)  → 두 단계 뒤로

navigate(1)   → 한 단계 앞으로
navigate(2)   → 두 단계 앞으로
```

따라서 `navigate()`는 새로운 URL로 이동하는 것뿐 아니라 **History Stack을 기준으로 이동하는 역할**도 수행할 수 있습니다.

---

# 11. 기본 Navigation은 History에 새로운 Entry를 추가한다

다음 코드를 실행한다고 하겠습니다.

```jsx
navigate('/about');
```

일반적인 브라우저 환경에서는 새로운 History Entry가 만들어집니다.

```text
Before

/home  ← 현재


navigate('/about')


After

/home
  ↓
/about ← 현재
```

따라서 사용자가 브라우저의 뒤로 가기를 누르면 `/home`으로 돌아갈 수 있습니다.

개념적으로 브라우저의 History API에서 `pushState()`와 연결되는 동작입니다.

---

# 12. `replace` 옵션

때로는 새로운 History Entry를 추가하고 싶지 않을 수 있습니다.

그럴 때:

```jsx
navigate('/dashboard', {
  replace: true
});
```

를 사용합니다.

개념적으로:

```text
push

/home
  ↓
/dashboard


replace

/home
  │
  │ 교체
  ▼
/dashboard
```

입니다.

대표적인 사용 사례는 로그인 화면입니다.

```text
/login
   │
   │ 로그인 성공
   ▼
/dashboard
```

로그인 성공 후 다시 뒤로 가기를 눌렀을 때 `/login`으로 돌아갈 필요가 없다면:

```jsx
navigate('/dashboard', {
  replace: true
});
```

를 고려할 수 있습니다.

---

# 13. `state` 전달

Navigation하면서 추가 데이터를 전달할 수도 있습니다.

```jsx
navigate('/product/10', {
  state: {
    from: 'product-list'
  }
});
```

이 데이터는 목적지 컴포넌트에서 `useLocation()`을 통해 읽을 수 있습니다.

```jsx
const location = useLocation();

console.log(location.state);
```

결과:

```js
{
  from: 'product-list'
}
```

전체 흐름:

```text
navigate()
   │
   │ state 전달
   ▼
새 Location
   │
   ├── pathname
   ├── search
   ├── hash
   └── state
          │
          ▼
    useLocation()
```

---

# 14. `navigate()`를 렌더링 중 직접 호출하면 안 된다

다음과 같은 코드는 피해야 합니다.

```jsx
function ProtectedPage() {
  const navigate = useNavigate();

  if (!isLoggedIn) {
    navigate('/login');
  }

  return <Page />;
}
```

컴포넌트 함수가 실행되는 **Render 과정에서 Navigation이라는 Side Effect를 발생시키기 때문**입니다.

이벤트의 결과로 이동한다면 이벤트 핸들러에서 실행하는 것이 자연스럽습니다.

```jsx
const handleLogin = async () => {
  const success = await login();

  if (success) {
    navigate('/dashboard');
  }
};
```

상태 변화에 반응하여 명령형 Navigation이 꼭 필요하다면 Effect에서 처리할 수도 있습니다.

```jsx
useEffect(() => {
  if (!isLoggedIn) {
    navigate('/login');
  }
}, [isLoggedIn, navigate]);
```

다만 단순한 라우팅 기반 Redirect라면 React Router가 제공하는 선언적 Redirect 방식이나 Data Router의 redirect 기능이 더 적절한 경우도 있습니다.

---

# 15. `navigate()`의 내부 동작을 이해해보자

다음 코드가 실행됐다고 하겠습니다.

```jsx
navigate('/about');
```

개념적인 흐름은 다음과 같습니다.

```text
navigate('/about')
        │
        ▼
React Router
Navigation 요청
        │
        ▼
새 Location 계산
        │
        ▼
Browser History 갱신
        │
        ▼
Router State 변경
        │
        ▼
Route Matching
        │
        ▼
새로운 Route 결과
        │
        ▼
React Rendering
        │
        ▼
필요한 DOM 변경
```

여기서 중요한 점은 **Document 전체를 새로 요청하는 전통적인 페이지 이동이 아니라는 것**입니다.

# 16. History API와의 관계

브라우저 환경에서 React Router의 Navigation은 History API와 연결됩니다.

대표적인 브라우저 API는:

```js
history.pushState(state, '', url);

history.replaceState(state, '', url);
```

입니다.

개념적으로:

```text
navigate('/about')
       │
       ▼
Push Navigation
       │
       ▼
History Entry 추가
```

그리고:

```jsx
navigate('/about', {
  replace: true
});
```

는:

```text
navigate(..., { replace: true })
              │
              ▼
      Replace Navigation
              │
              ▼
      현재 History Entry 교체
```

와 연결됩니다.

다만 `navigate()`를 단순히 `history.pushState()`의 별칭으로 이해하면 안 됩니다.

`navigate()`는 **React Router의 Navigation API**이고, 브라우저 History 갱신은 그 Navigation 과정의 일부입니다.

---

# 17. `navigate()`와 `pushState()`의 차이

직접 다음 코드를 호출하는 것과:

```js
history.pushState(
  null,
  '',
  '/about'
);
```

React Router에서:

```jsx
navigate('/about');
```

를 호출하는 것은 개념적으로 다릅니다.

`navigate()`는 React Router에게 Navigation을 요청하기 때문에 Router의 상태 변경과 Route Matching 과정까지 자연스럽게 연결됩니다.

```text
navigate()
    │
    ▼
React Router
    │
    ├── Location 처리
    ├── History 처리
    ├── Route Matching
    └── Router State 갱신
            │
            ▼
      React Rendering
```

따라서 React Router 앱에서는 직접 History API를 조작하기보다 Router가 제공하는 Navigation API를 사용하는 것이 기본입니다.

---

# 18. `<Link>`와 내부 동작 관계

`<Link>`와 `navigate()`는 모두 React Router의 Navigation 시스템을 사용합니다.

```text
<Link>
   │
   │ 사용자 클릭
   ▼
React Router
Navigation
```

그리고:

```text
이벤트 / 로직
     │
     ▼
 navigate()
     │
     ▼
React Router
Navigation
```

따라서 `<Link>`를 단순히 "`navigate()`를 호출하는 컴포넌트"라고 외우기보다는:

> **`<Link>`와 `navigate()` 모두 React Router의 Navigation 시스템을 이용하지만, `<Link>`는 선언적인 링크 UI이고 `navigate()`는 명령형 Navigation 함수이다.**

라고 이해하는 것이 더 정확합니다.

---

# 19. `navigate()`와 관련 Hook의 관계

React Router의 주요 Hook을 Navigation 관점에서 정리하면:

| Hook                | 역할                    |
| ------------------- | --------------------- |
| `useNavigate()`     | `navigate` 함수 얻기      |
| `useLocation()`     | 현재 Location 읽기        |
| `useParams()`       | Path Parameter 읽기     |
| `useSearchParams()` | Query Parameter 읽기/변경 |
| `useMatch()`        | Path Pattern 매칭       |
| `useResolvedPath()` | 목적지 Path 해석           |

흐름으로 연결하면:

```text
현재 어디인가?
      │
      ▼
 useLocation()


URL Parameter는?
      │
      ▼
  useParams()


이 상대 경로는 어디인가?
      │
      ▼
useResolvedPath()


그곳으로 이동하라
      │
      ▼
  navigate()
```

# 20. `navigate()`의 핵심

`navigate()`를 단순히:

> URL을 변경하는 함수

라고 설명할 수 있지만, 이것만으로는 역할을 충분히 설명하지 못합니다.

더 정확하게는:

> **`navigate()`는 React Router에 프로그래밍 방식의 Navigation을 요청하여 새로운 Location으로 이동하게 만드는 함수입니다.**

즉:

```text
Event / Logic
     │
     ▼
 navigate(to)
     │
     ▼
React Router
Navigation
     │
     ▼
Location 변경
     │
     ▼
Route Matching
     │
     ▼
React Rendering
```

입니다.

따라서 `navigate()`의 본질은 **“주소창 문자열을 직접 수정하는 것”이 아니라 “React Router의 Navigation을 코드에서 명령형으로 실행하는 것”**이라고 이해하는 것이 가장 정확합니다.
