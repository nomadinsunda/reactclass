`createBrowserRouter`는 React Router를 제대로 이해하려면 꽤 중요한 지점입니다. 특히 기존에 다룬 **`BrowserRouter → History API → location → Routes`** 흐름에서 한 단계 발전해, **라우팅 자체뿐 아니라 loader/action/error 처리까지 Router가 관리하는 Data Router 구조**를 만드는 함수입니다.

# createBrowserRouter란?

`createBrowserRouter()`는 React Router에서 **브라우저 History API를 사용하는 Router 객체를 생성하는 함수**입니다.

가장 기본적인 형태는 다음과 같습니다.

```jsx
import { createBrowserRouter } from "react-router-dom";

const router = createBrowserRouter([
  {
    path: "/",
    element: <Home />,
  },
  {
    path: "/products",
    element: <Products />,
  },
]);
```

그리고 생성한 `router`를 `RouterProvider`에 전달합니다.

```jsx
import { RouterProvider } from "react-router-dom";

function App() {
  return <RouterProvider router={router} />;
}
```

전체 구조는 다음과 같습니다.

```text
createBrowserRouter()
        │
        │ Route 설정
        ▼
┌────────────────────────────┐
│       Router 객체          │
│                            │
│ routes                     │
│ location                   │
│ navigation                 │
│ loader/action 상태         │
│ errors                     │
│ history 연동               │
└──────────────┬─────────────┘
               │
               │ router
               ▼
       <RouterProvider>
               │
               ▼
        React Component
```

핵심은 이것입니다.

> **`createBrowserRouter()` = Route 설정을 받아 브라우저 History와 연결된 Data Router 객체를 생성하는 함수**

---

# 1. BrowserRouter와 무엇이 다른가?

기존에는 보통 다음처럼 작성했습니다.

```jsx
<BrowserRouter>
  <Routes>
    <Route path="/" element={<Home />} />
    <Route path="/products" element={<Products />} />
  </Routes>
</BrowserRouter>
```

구조적으로 보면:

```text
<BrowserRouter>
      │
      ▼
   <Routes>
      │
      ▼
   <Route>
```

반면 `createBrowserRouter()`에서는 Route를 **객체 형태의 Route Configuration**으로 먼저 정의합니다.

```jsx
const router = createBrowserRouter([
  {
    path: "/",
    element: <Home />,
  },
  {
    path: "/products",
    element: <Products />,
  },
]);
```

그리고:

```jsx
<RouterProvider router={router} />
```

를 사용합니다.

```text
Route Object[]
      │
      ▼
createBrowserRouter()
      │
      ▼
 Router 객체
      │
      ▼
<RouterProvider>
      │
      ▼
React UI
```

따라서 둘의 가장 큰 구조적 차이는 다음과 같습니다.

```text
BrowserRouter

JSX가 Route 구조를 정의
       ↓
<BrowserRouter>
       ↓
<Routes>
       ↓
<Route>


createBrowserRouter

Route Object가 Route 구조를 정의
       ↓
createBrowserRouter()
       ↓
Router 객체
       ↓
<RouterProvider>
```

---

# 2. createBrowserRouter의 반환값

여기가 매우 중요합니다.

```jsx
const router = createBrowserRouter([...]);
```

여기서 `router`는 **React Component가 아닙니다.**

즉:

```jsx
<router />
```

처럼 사용하는 것이 아닙니다.

`createBrowserRouter()`는 **Router 객체**를 반환합니다.

개념적으로 보면:

```text
createBrowserRouter(routes)
           │
           ▼
       Router Object
```

이 Router 객체는 단순히 URL만 가지고 있는 것이 아니라 Router가 동작하는 데 필요한 상당한 상태와 기능을 관리합니다.

개념적으로:

```text
Router
│
├─ routes
│
├─ state
│   ├─ location
│   ├─ matches
│   ├─ navigation
│   ├─ loaderData
│   ├─ actionData
│   └─ errors
│
├─ navigate()
├─ subscribe()
├─ fetch()
└─ ...
```

이 객체를 React와 연결하는 것이:

```jsx
<RouterProvider router={router} />
```

입니다.

---

# 3. createBrowserRouter의 Route Object

예를 들어:

```jsx
const router = createBrowserRouter([
  {
    path: "/",
    element: <Home />,
  },
  {
    path: "/about",
    element: <About />,
  },
]);
```

배열 안의 객체 하나하나가 **Route Object**입니다.

```text
Route Object

{
  path: "/about",
  element: <About />
}
```

의 의미는:

```text
URL
/about
   │
   ▼
Route Matching
   │
   ▼
<About />
```

입니다.

하지만 `createBrowserRouter`가 중요한 이유는 Route Object가 단순히 `path`와 `element`만 가지는 것이 아니기 때문입니다.

대표적으로:

```jsx
{
  path,
  element,
  children,
  loader,
  action,
  errorElement,
  index,
  lazy,
  shouldRevalidate,
  ...
}
```

같은 기능을 Route 단위로 정의할 수 있습니다.

---

# 4. 중첩 Route

`children`을 사용하면 중첩 Route를 만들 수 있습니다.

```jsx
const router = createBrowserRouter([
  {
    path: "/",
    element: <RootLayout />,
    children: [
      {
        index: true,
        element: <Home />,
      },
      {
        path: "products",
        element: <Products />,
      },
      {
        path: "about",
        element: <About />,
      },
    ],
  },
]);
```

구조는:

```text
/
│
└─ RootLayout
     │
     ├─ index
     │    └─ Home
     │
     ├─ products
     │    └─ Products
     │
     └─ about
          └─ About
```

`RootLayout`에서는 `<Outlet>`을 사용합니다.

```jsx
function RootLayout() {
  return (
    <>
      <Header />
      <Outlet />
      <Footer />
    </>
  );
}
```

`/products`로 이동하면:

```text
RootLayout
│
├─ Header
│
├─ Outlet
│    └─ Products
│
└─ Footer
```

가 됩니다.

즉 `<Outlet>`은 **매칭된 자식 Route의 `element`가 렌더링되는 자리**입니다.

---

# 5. loader

여기서부터 `createBrowserRouter`의 진짜 장점이 나타납니다.

Route에 데이터를 가져오는 코드를 붙일 수 있습니다.

```jsx
const router = createBrowserRouter([
  {
    path: "/products",
    element: <Products />,
    loader: async () => {
      const response = await fetch("/api/products");
      return response.json();
    },
  },
]);
```

컴포넌트에서는:

```jsx
import { useLoaderData } from "react-router-dom";

function Products() {
  const products = useLoaderData();

  return (
    <div>
      {products.map((product) => (
        <p key={product.id}>{product.name}</p>
      ))}
    </div>
  );
}
```

전체 흐름은:

```text
/products 이동
      │
      ▼
Route Matching
      │
      ▼
loader 실행
      │
      ▼
fetch("/api/products")
      │
      ▼
데이터 반환
      │
      ▼
Router가 loaderData 관리
      │
      ▼
useLoaderData()
      │
      ▼
<Products />
```

따라서 전통적인:

```jsx
useEffect(() => {
  fetch(...)
}, []);
```

방식과 상당히 다른 구조를 만들 수 있습니다.

핵심은:

> **컴포넌트가 렌더링된 다음 데이터를 요청하는 것이 아니라, Route navigation 과정 자체에 데이터 로딩을 포함시킬 수 있습니다.**

---

# 6. action

`loader`가 **읽기(Read)** 쪽이라면 `action`은 데이터 변경 작업을 처리할 때 사용합니다.

예를 들어:

```jsx
{
  path: "/products/new",
  element: <NewProduct />,
  action: async ({ request }) => {
    const formData = await request.formData();

    return fetch("/api/products", {
      method: "POST",
      body: formData,
    });
  },
}
```

컴포넌트에서는 React Router의 `<Form>` 등을 사용할 수 있습니다.

```jsx
<Form method="post">
  <input name="name" />
  <button type="submit">등록</button>
</Form>
```

흐름은 대략:

```text
<Form> submit
      │
      ▼
Router
      │
      ▼
해당 Route의 action()
      │
      ▼
POST /api/products
      │
      ▼
action 결과
      │
      ▼
필요한 loader revalidation
      │
      ▼
UI 업데이트
```

이 때문에 `createBrowserRouter`를 단순한 **URL → Component 매핑 도구**로 이해하면 부족합니다.

---

# 7. errorElement

Route에서 발생하는 에러 처리도 Route 설정에 넣을 수 있습니다.

```jsx
{
  path: "/products",
  element: <Products />,
  loader: productsLoader,
  errorElement: <ErrorPage />,
}
```

예를 들어 `loader`에서 문제가 발생하면:

```text
loader()
   │
   ├─ 성공
   │    ↓
   │  Products
   │
   └─ 실패
        ↓
    errorElement
        ↓
     ErrorPage
```

이렇게 **Route 단위 Error Boundary 구조**를 만들 수 있습니다.

---

# 8. URL이 변경되면 내부적으로 무슨 일이 일어나는가?

이 부분이 `createBrowserRouter`를 이해하는 핵심입니다.

예를 들어:

```jsx
<Link to="/products">Products</Link>
```

를 클릭했다고 하겠습니다.

개념적인 흐름은 다음과 같습니다.

```text
<Link> 클릭
    │
    ▼
navigate("/products")
    │
    ▼
Router가 navigation 시작
    │
    ├───────────────┐
    │               │
    ▼               ▼
History 변경     Route Matching
                    │
                    ▼
              loader 확인/실행
                    │
                    ▼
               데이터 준비
                    │
                    ▼
              Router State 변경
                    │
                    ▼
             RouterProvider 감지
                    │
                    ▼
              React 업데이트
                    │
                    ▼
               화면 변경
```

따라서 `createBrowserRouter`에서는 **Router가 navigation 상태 머신에 가까운 역할**을 합니다.

# 9. History API와의 관계

이름에 `Browser`가 들어가는 이유도 중요합니다.

```text
createBrowserRouter
       ↑
    Browser
```

브라우저의 History API를 기반으로 동작합니다.

대표적으로:

```js
history.pushState()
history.replaceState()
window.location
popstate
```

같은 브라우저 기능과 연결됩니다.

예를 들어:

```jsx
navigate("/products");
```

라고 하면 개념적으로:

```text
navigate("/products")
       │
       ▼
React Router
       │
       ▼
Browser History
       │
       ▼
history.pushState(...)
       │
       ▼
주소창

/products
```

하지만 페이지 전체를 새로 요청하는 전통적인 navigation이 아니라 **SPA navigation**이 이루어집니다.

---

# 10. BrowserRouter와 createBrowserRouter의 중요한 차이

단순히 문법만 다른 것이 아닙니다.

`BrowserRouter` 방식:

```jsx
<BrowserRouter>
  <Routes>
    <Route ... />
  </Routes>
</BrowserRouter>
```

은 흔히 **Declarative Router 방식**이라고 볼 수 있습니다.

반면:

```jsx
createBrowserRouter(...)
```

는 **Data Router** 기능을 사용할 수 있는 Router를 생성합니다.

Data Router의 핵심은:

```text
URL
 │
 ▼
Route
 │
 ├─ element
 ├─ loader
 ├─ action
 ├─ errorElement
 └─ revalidation
```

처럼 **UI와 데이터 생명주기를 Route에 결합할 수 있다는 것**입니다.

---

# 11. RouterProvider의 역할

그렇다면 왜 `RouterProvider`가 필요한가?

```jsx
const router = createBrowserRouter(routes);

<RouterProvider router={router} />
```

구조를 보면:

```text
createBrowserRouter()
        │
        ▼
Router Object
        │
        │ router prop
        ▼
<RouterProvider>
        │
        ▼
React
```

`RouterProvider`는 Router 객체가 관리하는 상태를 **React 컴포넌트 트리와 연결**합니다.

Router의 상태가:

```text
location
matches
navigation
loaderData
actionData
errors
```

등으로 변경되면 React가 그 변화에 맞춰 UI를 업데이트할 수 있게 합니다.

따라서 역할을 분리하면:

```text
createBrowserRouter
        │
        └─ Router를 만든다

Router
        │
        └─ navigation과 route state를 관리한다

RouterProvider
        │
        └─ Router와 React를 연결한다

Route element
        │
        └─ 실제 UI를 렌더링한다
```

라고 이해하면 좋습니다.

# 13. 가장 중요한 개념 구분

강의에서는 다음 네 개를 명확히 분리해서 설명하는 것이 좋습니다.

```text
createBrowserRouter()
        ↓
"Router 객체를 생성"


Router
        ↓
"라우팅 상태와 navigation을 관리"


RouterProvider
        ↓
"Router 객체와 React를 연결"


Route Object
        ↓
"URL별 UI / loader / action / error 등을 정의"
```

특히 초보자는 다음 둘을 혼동하기 쉽습니다.

```jsx
createBrowserRouter(...)
```

와

```jsx
<BrowserRouter>
```

`createBrowserRouter`는 **함수**이고,

```text
Route 설정
   ↓
Router 객체 생성
```

을 담당합니다.

`BrowserRouter`는 **React Component**입니다.

---

## 한 문장으로 정리

> **`createBrowserRouter()`는 Route Object 설정을 바탕으로 브라우저 History API와 연결된 Data Router 객체를 생성하고, 이 Router가 URL 매칭뿐 아니라 navigation, loader, action, error, revalidation 등의 라우팅 생명주기를 관리하도록 만드는 함수입니다.**
