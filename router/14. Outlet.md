# React Router `<Outlet />` — 왜 필요한지부터 이해하기

`<Outlet />`을 단순히

> **"자식 Route가 렌더링되는 자리"**

라고 외우면 문법은 이해할 수 있지만, **왜 React Router에 이런 컴포넌트가 필요한지는 잘 보이지 않습니다.**

`Outlet`을 제대로 이해하려면 먼저 다음 질문에서 출발해야 합니다.

> **여러 페이지가 공통된 화면 구조를 사용한다면, 공통 부분은 유지하면서 URL에 따라 일부 영역만 어떻게 바꿀 수 있을까?**

이 문제를 해결하는 과정에서 **Nested Route(중첩 라우팅)**가 등장하고, 그 중첩된 자식 Route를 부모 화면의 특정 위치에 연결하기 위해 `<Outlet />`이 필요합니다.

---

# 1. 먼저 Outlet이 없는 일반적인 Route부터 생각해보자

다음과 같은 쇼핑몰 관리 페이지를 만든다고 하겠습니다.

```text
/dashboard
/dashboard/products
/dashboard/orders
```

화면은 모두 비슷합니다.

```text
┌─────────────────────────────────────┐
│ Header                              │
├───────────┬─────────────────────────┤
│           │                         │
│ Sidebar   │       페이지 내용         │
│           │                         │
│           │                         │
├───────────┴─────────────────────────┤
│ Footer                              │
└─────────────────────────────────────┘
```

URL에 따라 실제로 바뀌어야 하는 것은 오른쪽의 **페이지 내용**뿐입니다.

```text
/dashboard
→ DashboardHome

/dashboard/products
→ Products

/dashboard/orders
→ Orders
```

반면 다음 부분은 계속 동일합니다.

```text
Header
Sidebar
Footer
```

즉 우리가 원하는 것은 다음 구조입니다.

```text
┌─────────────────────────────────────┐
│ Header                              │
├───────────┬─────────────────────────┤
│           │                         │
│ Sidebar   │    URL에 따라 변경      │
│           │                         │
├───────────┴─────────────────────────┤
│ Footer                              │
└─────────────────────────────────────┘
```

여기서 중요한 질문이 생깁니다.

> **URL에 따라 바뀌는 컴포넌트를 정확히 어디에 렌더링해야 할까?**

이 질문의 답이 `<Outlet />`입니다.

---

# 2. 가장 단순하게 Route를 만들면 어떤 문제가 생길까?

처음 React Router를 배우면 다음처럼 작성하기 쉽습니다.

```jsx
<Routes>
  <Route path="/dashboard" element={<DashboardHome />} />
  <Route path="/dashboard/products" element={<Products />} />
  <Route path="/dashboard/orders" element={<Orders />} />
</Routes>
```

그런데 `DashboardHome`, `Products`, `Orders` 모두 같은 Header와 Sidebar가 필요하다고 해보겠습니다.

그러면 이런 코드가 만들어질 수 있습니다.

```jsx
function DashboardHome() {
  return (
    <>
      <Header />
      <Sidebar />

      <main>
        <h1>Dashboard</h1>
      </main>

      <Footer />
    </>
  );
}
```

```jsx
function Products() {
  return (
    <>
      <Header />
      <Sidebar />

      <main>
        <h1>Products</h1>
      </main>

      <Footer />
    </>
  );
}
```

```jsx
function Orders() {
  return (
    <>
      <Header />
      <Sidebar />

      <main>
        <h1>Orders</h1>
      </main>

      <Footer />
    </>
  );
}
```

문제가 보입니다.

```text
DashboardHome
├── Header       ← 반복
├── Sidebar      ← 반복
├── Dashboard
└── Footer       ← 반복


Products
├── Header       ← 반복
├── Sidebar      ← 반복
├── Products
└── Footer       ← 반복


Orders
├── Header       ← 반복
├── Sidebar      ← 반복
├── Orders
└── Footer       ← 반복
```

페이지마다 공통 레이아웃이 반복됩니다.

우리가 원하는 구조는 사실 이것입니다.

```text
DashboardLayout
│
├── Header
├── Sidebar
├── ??????
└── Footer
```

`??????` 위치에 URL에 따라

```text
DashboardHome
Products
Orders
```

중 하나가 들어가면 됩니다.

바로 이 `??????`가 `<Outlet />`입니다.

---

# 3. 공통 부분을 부모 Layout으로 분리한다

먼저 반복되는 UI를 `DashboardLayout`으로 분리합니다.

```jsx
function DashboardLayout() {
  return (
    <>
      <Header />

      <div className="dashboard">
        <Sidebar />

        <main>
          여기에 현재 페이지가 들어와야 함
        </main>
      </div>

      <Footer />
    </>
  );
}
```

이제 구조가 훨씬 명확해졌습니다.

```text
DashboardLayout
│
├── Header
│
├── Sidebar
│
├── [ 현재 페이지가 들어갈 자리 ]
│
└── Footer
```

그런데 아직 React Router에게 중요한 정보 하나를 알려주지 않았습니다.

> **"Router야, 네가 URL을 보고 선택한 자식 Route를 여기다 렌더링해."**

그 표시가 바로:

```jsx
<Outlet />
```

입니다.

---

# 4. `<Outlet />`을 넣어보자

```jsx
import { Outlet } from "react-router-dom";

function DashboardLayout() {
  return (
    <>
      <Header />

      <div className="dashboard">
        <Sidebar />

        <main>
          <Outlet />
        </main>
      </div>

      <Footer />
    </>
  );
}
```

이제 `DashboardLayout`의 의미가 완전히 달라집니다.

```text
DashboardLayout
│
├── Header
│
├── Sidebar
│
├── Outlet  ← Router가 선택한 자식 Route의 element
│
└── Footer
```

따라서 `<Outlet />`을 단순한 빈 공간이라고 생각하기보다는 다음과 같이 이해하는 것이 좋습니다.

> **`<Outlet />`은 부모 Route가 자식 Route의 화면을 받을 수 있도록 만든 렌더링 연결 지점이다.**

---

# 5. 그렇다면 어떤 컴포넌트가 Outlet으로 들어올까?

이것은 `<Outlet />`이 결정하지 않습니다.

**현재 URL과 Route Tree를 보고 React Router가 결정합니다.**

Route를 다음처럼 구성합니다.

```jsx
<Routes>
  <Route path="/dashboard" element={<DashboardLayout />}>

    <Route index element={<DashboardHome />} />

    <Route
      path="products"
      element={<Products />}
    />

    <Route
      path="orders"
      element={<Orders />}
    />

  </Route>
</Routes>
```

Route Tree로 표현하면 다음과 같습니다.

```text
/dashboard
DashboardLayout
│
├── index
│   └── DashboardHome
│
├── products
│   └── Products
│
└── orders
    └── Orders
```

여기서 중요한 점은:

```text
DashboardLayout
```

이 **부모 Route의 element**이고,

```text
DashboardHome
Products
Orders
```

가 **자식 Route의 element**라는 것입니다.

그리고 부모인 `DashboardLayout` 안에:

```jsx
<Outlet />
```

이 있습니다.

---

# 6. `/dashboard/products`로 이동하면 무슨 일이 일어날까?

이 부분이 `<Outlet />`을 이해하는 핵심입니다.

브라우저 URL이:

```text
/dashboard/products
```

라고 하겠습니다.

React Router는 Route Tree에서 현재 URL과 일치하는 **Route branch**를 찾습니다.

```text
/dashboard/products
        │
        ▼
   Route Matching
        │
        ├── /dashboard
        │      ↓
        │ DashboardLayout
        │
        └── products
               ↓
            Products
```

즉 하나만 선택되는 것이 아닙니다.

중첩 Route에서는 현재 URL에 대해 다음과 같은 **매칭 계층**이 만들어집니다.

```text
DashboardLayout
      │
      └── Products
```

먼저 부모 Route의 element인:

```jsx
<DashboardLayout />
```

이 렌더링됩니다.

그 안에는:

```jsx
<main>
  <Outlet />
</main>
```

이 있습니다.

그리고 Router는 매칭된 다음 단계의 자식 Route:

```jsx
<Products />
```

를 그 `<Outlet />` 위치에 렌더링합니다.

개념적으로 보면:

```text
<DashboardLayout>

    <Header />

    <Sidebar />

    <Outlet />
        │
        ▼
    <Products />

    <Footer />

</DashboardLayout>
```

입니다.

따라서 최종 화면은:

```text
┌─────────────────────────────────────┐
│ Header                              │
├───────────┬─────────────────────────┤
│           │                         │
│ Sidebar   │       Products          │
│           │                         │
├───────────┴─────────────────────────┤
│ Footer                              │
└─────────────────────────────────────┘
```

가 됩니다.

# 7. URL이 바뀌면 Outlet 내용만 달라진다

같은 Route Tree에서 URL만 변경해보겠습니다.

### `/dashboard`

```text
/dashboard
     │
     ▼
DashboardLayout
     │
     ▼
  <Outlet />
     │
     ▼
DashboardHome
```

화면:

```text
┌─────────────────────────────────────┐
│ Header                              │
├───────────┬─────────────────────────┤
│ Sidebar   │     DashboardHome       │
├───────────┴─────────────────────────┤
│ Footer                              │
└─────────────────────────────────────┘
```

### `/dashboard/products`

```text
/dashboard/products
        │
        ▼
DashboardLayout
        │
        ▼
     <Outlet />
        │
        ▼
     Products
```

화면:

```text
┌─────────────────────────────────────┐
│ Header                              │
├───────────┬─────────────────────────┤
│ Sidebar   │       Products          │
├───────────┴─────────────────────────┤
│ Footer                              │
└─────────────────────────────────────┘
```

### `/dashboard/orders`

```text
/dashboard/orders
        │
        ▼
DashboardLayout
        │
        ▼
     <Outlet />
        │
        ▼
      Orders
```

화면:

```text
┌─────────────────────────────────────┐
│ Header                              │
├───────────┬─────────────────────────┤
│ Sidebar   │        Orders           │
├───────────┴─────────────────────────┤
│ Footer                              │
└─────────────────────────────────────┘
```

여기서 드디어 `<Outlet />`의 역할이 명확해집니다.

```text
                    URL

       /dashboard
            │
            ├──────────────→ DashboardHome
            │
       /dashboard/products
            │
            ├──────────────→ Products
            │
       /dashboard/orders
            │
            └──────────────→ Orders

                    │
                    ▼

             DashboardLayout

          ┌──────────────────┐
          │ Header           │
          ├──────────────────┤
          │                  │
          │    <Outlet />    │
          │        ▲         │
          │        │         │
          │ Router가 선택한  │
          │ child element    │
          │                  │
          ├──────────────────┤
          │ Footer           │
          └──────────────────┘
```

# 8. 여기서 아주 중요한 오해 하나

`<Outlet />`이 URL을 분석하는 것은 아닙니다.

```text
<Outlet />
   ↓
URL 분석
   ↓
컴포넌트 선택
```

이런 구조가 아닙니다.

역할을 정확하게 분리하면:

```text
현재 URL
   │
   ▼
React Router
   │
   ▼
Route Tree Matching
   │
   ▼
매칭된 Route branch 결정
   │
   ├── 부모 element
   │
   └── 자식 element
            │
            ▼
         <Outlet />
```

입니다.

즉:

> **Router가 "무엇을 렌더링할지" 결정하고, Outlet은 "어디에 렌더링할지"를 제공한다.**

이 구분이 매우 중요합니다.

---

# 9. 왜 `<Outlet />`은 부모 Route에 있어야 할까?

다음 Route Tree를 다시 보겠습니다.

```text
DashboardLayout
│
├── DashboardHome
├── Products
└── Orders
```

자식들은 부모의 UI 안으로 들어가야 합니다.

따라서 자식을 받을 위치도 부모가 가지고 있어야 합니다.

```jsx
function DashboardLayout() {
  return (
    <>
      <Header />
      <Sidebar />

      <Outlet />

      <Footer />
    </>
  );
}
```

이를 컴포넌트 트리 관점에서 보면:

```text
DashboardLayout
│
├── Header
│
├── Sidebar
│
├── Outlet
│     │
│     └── 현재 매칭된 child element
│
└── Footer
```

가 됩니다.

그래서 중첩 Route에서 `<Outlet />`은 **부모와 자식 Route의 UI를 연결하는 지점**이라고 할 수 있습니다.

---

# 10. Outlet이 없으면 어떻게 될까?

Route는 그대로 두고:

```jsx
<Route
  path="/dashboard"
  element={<DashboardLayout />}
>
  <Route
    path="products"
    element={<Products />}
  />
</Route>
```

`DashboardLayout`에서 `<Outlet />`을 제거해보겠습니다.

```jsx
function DashboardLayout() {
  return (
    <>
      <Header />
      <Sidebar />
      <Footer />
    </>
  );
}
```

URL은:

```text
/dashboard/products
```

이고 Router는 정상적으로 다음 Route branch를 찾을 수 있습니다.

```text
DashboardLayout
      │
      └── Products
```

하지만 문제가 있습니다.

```text
DashboardLayout

├── Header
├── Sidebar
└── Footer

Products
   │
   └── ??? 어디에 렌더링하지?
```

부모 element 안에 자식 Route를 표시할 **렌더링 지점이 없습니다.**

그래서 부모 Layout은 보이지만 자식 UI가 나타나지 않습니다.

이것이 `<Outlet />`이 필요한 가장 직접적인 이유입니다.

---

# 11. `<Outlet />`을 React의 `children`과 비교하면 더 쉽다

일반 React 컴포넌트에서는 다음처럼 사용할 수 있습니다.

```jsx
<Layout>
  <Products />
</Layout>
```

그리고:

```jsx
function Layout({ children }) {
  return (
    <>
      <Header />

      <main>
        {children}
      </main>

      <Footer />
    </>
  );
}
```

여기서는 개발자가 직접:

```jsx
<Products />
```

를 전달합니다.

```text
개발자
   │
   ▼
<Layout>
   │
   ▼
children
   │
   ▼
Products
```

하지만 `<Outlet />`에서는 다릅니다.

```jsx
function DashboardLayout() {
  return (
    <>
      <Header />

      <main>
        <Outlet />
      </main>

      <Footer />
    </>
  );
}
```

개발자가 여기에 직접:

```jsx
<Products />
```

를 전달하지 않습니다.

대신:

```text
URL
 │
 ▼
React Router
 │
 ▼
Route Matching
 │
 ▼
Products 선택
 │
 ▼
<Outlet />
```

이 됩니다.

따라서 입문 단계에서는 다음처럼 비교하면 이해하기 쉽습니다.

```text
children
────────────────────────
개발자가 자식을 결정한다.

Outlet
────────────────────────
Router가 URL을 보고
자식을 결정한다.
```

---

# 12. Outlet의 진짜 핵심은 "빈 자리"가 아니다

흔히 `<Outlet />`을 다음과 같이 설명합니다.

> "자식 페이지가 들어갈 빈 자리"

틀린 설명은 아닙니다.

하지만 이것만으로는 부족합니다.

중요한 것은 **그 자리에 들어올 컴포넌트를 누가 결정하느냐**입니다.

```text
               현재 URL
                   │
                   ▼
            React Router
                   │
                   ▼
            Route Matching
                   │
                   ▼
        child Route element 결정
                   │
                   ▼
              <Outlet />
                   │
                   ▼
          부모 UI 안에 렌더링
```

따라서 조금 더 정확하게 정의하면:

> **`<Outlet />`은 중첩 라우팅에서 React Router가 현재 URL과 Route Tree를 매칭하여 선택한 다음 단계의 child Route element를 부모 Route element 내부에 렌더링하는 위치입니다.**

---

# 13. 마지막으로 이것만 기억하자

`Outlet`을 이해할 때 다음 세 가지 역할을 분리해서 생각하면 됩니다.

```text
부모 Route
    │
    │  공통 UI를 만든다
    ▼
DashboardLayout
    │
    ├── Header
    ├── Sidebar
    │
    ├── <Outlet />
    │
    └── Footer


React Router
    │
    │  URL을 보고
    │  자식 Route를 선택한다
    ▼


<Outlet />
    │
    │  선택된 자식 element가
    │  렌더링될 위치를 제공한다
    ▼
Products / Orders / DashboardHome
```

한 문장으로 압축하면:

> **부모 Route는 공통 레이아웃을 만들고, React Router는 URL을 보고 자식 Route를 선택하며, `<Outlet />`은 선택된 자식 Route의 element가 부모 레이아웃 안에 들어가는 위치를 제공한다.**

이 관계가 이해되면 `<Outlet />`은 더 이상 외워야 하는 React Router 문법이 아니라, **Nested Routing을 실제 UI 구조로 연결하는 장치**로 보이기 시작합니다.

특히 기존 문서 후반부에 이미 있는 `/dashboard/reports → AppLayout → Outlet → DashboardLayout → Outlet → Reports` 설명은 좋은 내용입니다.  다만 이것을 이해하려면 **그 전에 위와 같은 "Outlet이 없으면 왜 곤란한가"라는 문제 상황을 충분히 경험하게 해야 합니다.**

그리고 `Outlet context`, `ProtectedLayout` 같은 내용은 현재 문서에 잘 들어가 있지만 , **Outlet 자체를 처음 배우는 문서라면 뒤쪽의 응용편으로 확실히 분리하는 편이 좋습니다.** 핵심 개념을 이해하기 전에 기능이 너무 많이 나오면 오히려 `Outlet = 이것저것 하는 컴포넌트`로 받아들이기 쉽습니다.
