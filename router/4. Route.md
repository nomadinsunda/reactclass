# `<Route>` in React Router

## URL 패턴과 React UI를 연결하는 라우팅 규칙

React Router에서 `<Route>`는 가장 핵심적인 구성 요소 중 하나입니다.

`BrowserRouter`가 브라우저의 URL/History와 React Router를 연결하고, `<Routes>`가 현재 URL과 Route Tree를 비교하여 적절한 Route branch를 선택한다면,

`<Route>`는 다음 질문에 답합니다.

> **“이 URL 패턴이 매칭되었을 때 어떤 UI를 사용할 것인가?”**

가장 기본적인 예는 다음과 같습니다.

```jsx
<Route
  path="/about"
  element={<About />}
/>
```

의미는 다음과 같습니다.

```text
현재 URL
/about
   │
   ▼
Route Matching
   │
   ▼
path="/about"
   │
   ▼
element={<About />}
   │
   ▼
<About /> 렌더링
```

따라서 `<Route>`를 한 문장으로 정의하면 다음과 같습니다.

> **`<Route>`는 URL 패턴과 그 URL이 매칭되었을 때 사용할 React UI를 연결하는 React Router의 라우팅 규칙입니다.**

---

# 1. React Router 전체 구조에서 `<Route>`의 위치

먼저 `<Route>`를 독립적으로 보기보다 전체 라우팅 구조 안에서 이해하는 것이 좋습니다.

```text
Browser
   │
   │ URL / History
   ▼
BrowserRouter
   │
   │ location 제공
   ▼
Routes
   │
   │ Route Tree Matching
   ▼
Route
   │
   │ path ↔ element
   ▼
React Element
   │
   ▼
React Rendering
   │
   ▼
UI
```

각 구성 요소의 역할은 다음과 같습니다.

```text
BrowserRouter
"현재 URL과 navigation 환경을 제공한다."

Routes
"현재 URL에 가장 적합한 Route branch를 찾는다."

Route
"특정 URL 패턴과 UI의 관계를 정의한다."

Outlet
"매칭된 자식 Route의 UI가 들어갈 위치를 제공한다."
```

즉 `<Route>`는 라우팅 시스템의 **개별 규칙 하나**라고 생각하면 됩니다.

---

# 2. 기본 사용법

```jsx
import {
  Routes,
  Route
} from 'react-router-dom';

function App() {
  return (
    <Routes>
      <Route
        path="/"
        element={<Home />}
      />

      <Route
        path="/about"
        element={<About />}
      />

      <Route
        path="/users"
        element={<Users />}
      />
    </Routes>
  );
}
```

현재 URL에 따라 다음과 같이 매칭됩니다.

| URL      | Route           | 렌더링 UI      |
| -------- | --------------- | ----------- |
| `/`      | `path="/"`      | `<Home />`  |
| `/about` | `path="/about"` | `<About />` |
| `/users` | `path="/users"` | `<Users />` |

개념적으로:

```text
/about
   │
   ▼
<Routes>
   │
   ▼
<Route path="/about">
   │
   ▼
element={<About />}
   │
   ▼
<About />
```

입니다.

---

# 3. `<Route>`의 주요 속성

대표적으로 다음 속성들을 사용합니다.

| 속성              | 역할                             |
| --------------- | ------------------------------ |
| `path`          | 매칭할 URL 패턴 지정                  |
| `element`       | 매칭되었을 때 렌더링할 React element     |
| `index`         | 부모 Route의 기본 자식 Route 지정       |
| `caseSensitive` | URL 매칭 시 대소문자 구분               |
| `children`      | 중첩 Route 정의                    |
| `loader`        | Data Router에서 데이터 로딩           |
| `action`        | Data Router에서 mutation/form 처리 |
| `errorElement`  | Data Router에서 Route 오류 UI 정의   |
| `handle`        | Route에 사용자 정의 metadata 저장      |

여기서 가장 자주 사용하는 것은:

```text
path
element
index
```

입니다.

---

# 4. `path`

`path`는 해당 Route가 어떤 URL 패턴과 매칭될지를 정의합니다.

예:

```jsx
<Route
  path="/about"
  element={<About />}
/>
```

현재 URL:

```text
/about
```

이면 Route가 매칭됩니다.

다양한 패턴을 사용할 수 있습니다.

```text
/                  루트
/about             정적 경로
/users/:userId     동적 경로
/files/*           splat / wildcard
*                  fallback
```

---

# 5. `element`

매칭된 Route가 어떤 UI를 렌더링할지를 지정합니다.

```jsx
<Route
  path="/login"
  element={<LoginPage />}
/>
```

여기서 중요한 것은:

```jsx
<LoginPage />
```

가 **React element**라는 것입니다.

다음과 구분해야 합니다.

```jsx
LoginPage
```

이는 컴포넌트 함수 자체입니다.

일반적인 선언형 Route에서는 다음과 같이 JSX element를 전달합니다.

```jsx
element={<LoginPage />}
```

즉:

```text
Component Function
LoginPage
      │
      │ JSX
      ▼
React Element
<LoginPage />
```

라고 이해하면 됩니다.

---

# 6. `element`가 항상 필수인 것은 아니다

다음과 같은 Route도 가능합니다.

```jsx
<Route path="users">
  <Route
    index
    element={<UserList />}
  />

  <Route
    path=":id"
    element={<UserDetail />}
  />
</Route>
```

부모 `users` Route에는 `element`가 없습니다.

이 Route는 URL 계층을 구성하기 위한 역할만 수행할 수 있습니다.

따라서:

> **대부분의 화면 Route에서는 `element`를 사용하지만 모든 `<Route>`에 반드시 `element`가 필요한 것은 아닙니다.**

---

# 7. 동적 Route

URL 일부를 변수처럼 사용할 수 있습니다.

예를 들어:

```jsx
<Route
  path="/users/:userId"
  element={<UserDetail />}
/>
```

다음 URL들이 모두 매칭됩니다.

```text
/users/1
/users/10
/users/100
```

Route Pattern은:

```text
/users/:userId
```

입니다.

`:` 뒤의 이름이 Dynamic Segment입니다.

```text
/users/10
       │
       ▼
:userId
       │
       ▼
"10"
```

컴포넌트에서는 `useParams()`로 값을 가져옵니다.

```jsx
import { useParams } from 'react-router-dom';

function UserDetail() {
  const { userId } = useParams();

  return (
    <h1>User ID: {userId}</h1>
  );
}
```

현재 URL이:

```text
/users/10
```

이면:

```js
userId === '10'
```

입니다.

URL parameter는 기본적으로 문자열로 전달된다는 것도 기억해두는 것이 좋습니다.

---

# 8. 중첩 Route

`<Route>`는 다른 `<Route>`를 자식으로 가질 수 있습니다.

```jsx
<Route
  path="/dashboard"
  element={<Dashboard />}
>
  <Route
    path="stats"
    element={<Stats />}
  />

  <Route
    path="settings"
    element={<Settings />}
  />
</Route>
```

Route Tree로 표현하면:

```text
/dashboard
│
├── stats
│    └── <Stats />
│
└── settings
     └── <Settings />
```

따라서 실제 URL은:

```text
/dashboard/stats
/dashboard/settings
```

가 됩니다.

현재 URL이:

```text
/dashboard/settings
```

이면 매칭되는 Route branch는:

```text
/dashboard
    │
    └── settings
```

입니다.

결과적으로:

```text
<Dashboard />
      │
      └── <Settings />
```

계층이 렌더링됩니다.

---

# 9. `<Outlet />`

중첩 Route에서는 부모 element 안에 자식 Route element가 들어갈 위치가 필요합니다.

그 역할을 하는 것이 `<Outlet />`입니다.

```jsx
import { Outlet } from 'react-router-dom';

function Dashboard() {
  return (
    <div>
      <h1>Dashboard</h1>

      <nav>
        ...
      </nav>

      <Outlet />
    </div>
  );
}
```

현재 URL:

```text
/dashboard/settings
```

이면 개념적으로:

```text
Dashboard
│
├── <h1>Dashboard</h1>
├── <nav />
│
└── <Outlet />
       │
       ▼
   <Settings />
```

가 됩니다.

즉:

> **`<Outlet />`은 현재 매칭된 자식 Route의 element가 렌더링되는 자리입니다.**

---

# 10. Index Route

부모 Route의 URL에 정확히 접근했을 때 보여줄 기본 자식 Route를 지정할 수 있습니다.

```jsx
<Route
  path="/products"
  element={<ProductLayout />}
>
  <Route
    index
    element={<ProductList />}
  />

  <Route
    path=":productId"
    element={<ProductDetail />}
  />
</Route>
```

URL과 매칭 결과:

```text
/products
     │
     ▼
index
     │
     ▼
<ProductList />
```

반면:

```text
/products/42
     │
     ▼
:productId
     │
     ▼
<ProductDetail />
```

입니다.

Index Route는 다음과 같이 작성합니다.

```jsx
<Route
  index
  element={<ProductList />}
/>
```

Index Route는 자신의 `path`를 갖지 않습니다.

부모 경로 자체에 대응하는 **기본 자식 Route**이기 때문입니다.

---

# 11. 정적 Route와 동적 Route

정적 Route:

```jsx
<Route
  path="/users/new"
  element={<NewUser />}
/>
```

동적 Route:

```jsx
<Route
  path="/users/:userId"
  element={<UserDetail />}
/>
```

현재 URL이:

```text
/users/new
```

이라면 React Router는 Route ranking을 이용해 더 구체적인:

```text
/users/new
```

Route를 선택합니다.

개념적으로:

```text
/users/:userId
/users/new
      │
      ▼
Specificity 비교
      │
      ▼
/users/new
      │
      ▼
<NewUser />
```

입니다.

Route 작성 순서만을 기준으로 선택하는 것이 아닙니다.

---

# 12. Catch-all Route

어떤 Route에도 매칭되지 않는 URL을 처리할 수 있습니다.

```jsx
<Route
  path="*"
  element={<NotFound />}
/>
```

예:

```text
/about
   ↓
<About />

/users/10
   ↓
<UserDetail />

/abcdef
   ↓
*
   ↓
<NotFound />
```

일반적으로 404 UI에 사용됩니다.

---

# 13. Splat Route

다음처럼 사용할 수도 있습니다.

```jsx
<Route
  path="/files/*"
  element={<FileBrowser />}
/>
```

예를 들어:

```text
/files
/files/images
/files/images/react
/files/docs/api
```

같은 하위 경로들을 매칭하는 데 사용할 수 있습니다.

개념적으로:

```text
/files/*
       │
       └── 나머지 하위 경로
```

입니다.

---

# 14. Pathless Route

`path`가 없는 Route도 가능합니다.

```jsx
<Route element={<AuthLayout />}>
  <Route
    path="/admin"
    element={<Admin />}
  />

  <Route
    path="/mypage"
    element={<MyPage />}
  />
</Route>
```

이 경우 부모 Route는 URL segment를 추가하지 않습니다.

대신 UI 계층이나 공통 동작을 구성하는 용도로 사용할 수 있습니다.

```text
AuthLayout
│
├── /admin
│    └── Admin
│
└── /mypage
     └── MyPage
```

`AuthLayout`에서는 일반적으로:

```jsx
function AuthLayout() {
  return (
    <>
      <AuthHeader />
      <Outlet />
    </>
  );
}
```

처럼 사용합니다.

---

# 15. `caseSensitive`

기본적으로 React Router의 path 매칭은 대소문자를 엄격하게 구분하지 않는 방식으로 사용할 수 있습니다.

필요한 경우:

```jsx
<Route
  path="/About"
  caseSensitive
  element={<About />}
/>
```

처럼 설정하여 대소문자를 구분할 수 있습니다.

이 경우:

```text
/About
```

과:

```text
/about
```

을 서로 다르게 취급할 수 있습니다.

---

# 16. React Router v5의 `exact`는 왜 없어졌는가?

React Router v5에서는 다음과 같은 코드가 자주 사용되었습니다.

```jsx
<Route
  exact
  path="/"
  component={Home}
/>
```

v5에서는 경로 매칭 방식 때문에 `exact`가 필요했습니다.

하지만 v6부터 Route Matching 방식이 크게 바뀌었습니다.

따라서:

```jsx
<Route
  path="/"
  element={<Home />}
/>
```

처럼 사용할 수 있으며 `exact`를 별도로 작성하지 않습니다.

정확한 표현은:

> **v6에서 `exact`가 자동으로 붙는 것이 아니라, 새로운 Route Matching 모델에서는 기존의 `exact` 옵션 자체가 필요하지 않게 되었습니다.**

입니다.

---

# 17. React Router v5와 v6+ 비교

| React Router v5      | React Router v6+     |
| -------------------- | -------------------- |
| `component={Home}`   | `element={<Home />}` |
| `render={() => ...}` | React element 사용     |
| `exact` 사용           | `exact` 제거           |
| `<Switch>`           | `<Routes>`           |
| 작성 순서 영향 큼           | Route ranking        |
| 중첩이 상대적으로 복잡         | Nested Route 중심      |

예:

### v5

```jsx
<Route
  path="/about"
  component={About}
/>
```

### v6+

```jsx
<Route
  path="/about"
  element={<About />}
/>
```

# 18. Data Router에서 사용하는 Route 속성

React Router의 Data Router를 사용할 경우 Route가 UI 매칭 이상의 역할을 수행할 수도 있습니다.

대표적으로:

```text
loader
action
errorElement
handle
```

등이 있습니다.

---

# 19. `loader`

Route가 필요로 하는 데이터를 로드하는 데 사용할 수 있습니다.

개념적으로:

```text
URL 이동
   │
   ▼
Route Matching
   │
   ▼
loader 실행
   │
   ▼
데이터 준비
   │
   ▼
Route UI 렌더링
```

Route configuration에서는 다음과 같은 형태로 사용될 수 있습니다.

```jsx
{
  path: '/profile',
  loader: fetchProfile,
  element: <Profile />
}
```

컴포넌트에서는:

```jsx
const data = useLoaderData();
```

와 같은 방식으로 데이터를 사용할 수 있습니다.

---

# 20. `action`

`action`은 데이터 변경 작업과 연결할 수 있습니다.

대표적으로:

```text
<form>
POST
PUT
PATCH
DELETE
```

같은 mutation 처리에 사용될 수 있습니다.

개념적으로:

```text
사용자 Submit
     │
     ▼
Route action
     │
     ▼
데이터 변경
     │
     ▼
라우트 데이터 갱신
```

입니다.

---

# 21. `errorElement`

Route 처리 과정에서 발생한 오류를 위한 UI를 정의할 수 있습니다.

개념적으로:

```text
Route
 │
 ├── 정상
 │     ↓
 │   element
 │
 └── 오류
       ↓
   errorElement
```

입니다.

이 기능들은 일반적인 `<BrowserRouter><Routes>...</Routes></BrowserRouter>` 설명과는 별도로 **Data Router 기능과 연결해서 배우는 것이 좋습니다.**

---

# 22. `Route` 하나만 선택되는 것은 아니다

중첩 Route를 이해할 때 중요한 부분입니다.

현재 URL이:

```text
/users/10
```

이고 다음과 같은 Route Tree가 있다고 하겠습니다.

```text
/
│
└── users
     │
     └── :userId
```

이 경우 단순히:

```text
:userId
```

Route 하나만 선택되는 것이 아닙니다.

매칭되는 Route branch는:

```text
/
│
└── users
     │
     └── :userId
```

전체입니다.

따라서 React element 계층도:

```text
<Layout />
    │
    └── <Outlet />
           │
           ▼
     <UsersLayout />
           │
           └── <Outlet />
                  │
                  ▼
            <UserDetail />
```

처럼 구성될 수 있습니다.

이것이 Nested Route의 핵심입니다.

---

# 23. 실전 예제

다음과 같은 애플리케이션을 구성해 보겠습니다.

```jsx
<Routes>
  <Route
    path="/"
    element={<Layout />}
  >
    <Route
      index
      element={<Home />}
    />

    <Route
      path="about"
      element={<About />}
    />

    <Route
      path="users"
      element={<UsersLayout />}
    >
      <Route
        index
        element={<UserList />}
      />

      <Route
        path=":userId"
        element={<UserDetail />}
      />
    </Route>

    <Route
      path="*"
      element={<NotFound />}
    />
  </Route>
</Routes>
```

Route Tree는 다음과 같습니다.

```text
/
│
├── index
│    └── Home
│
├── about
│    └── About
│
├── users
│    │
│    ├── index
│    │    └── UserList
│    │
│    └── :userId
│         └── UserDetail
│
└── *
     └── NotFound
```

# 24. `/users/10`에 접근하면 어떻게 되는가?

현재 URL:

```text
/users/10
```

Route Matching:

```text
/
│
└── users
     │
     └── :userId
```

Parameter:

```text
userId = "10"
```

렌더링 계층:

```text
<Layout />
    │
    └── <Outlet />
           │
           ▼
     <UsersLayout />
           │
           └── <Outlet />
                  │
                  ▼
          <UserDetail />
```

전체 흐름:

```text
Browser URL
/users/10
    │
    ▼
BrowserRouter
    │
    ▼
location
    │
    ▼
Routes
    │
    ▼
Route Tree Matching
    │
    ▼
Matched Branch
    │
    ▼
/
└── users
     └── :userId
    │
    ▼
Route Elements
    │
    ▼
Layout
    │
 UsersLayout
    │
 UserDetail
    │
    ▼
React Rendering
    │
    ▼
UI
```

---

# 25. `<Route>`를 이해하는 핵심 관점

`<Route>`를 단순히:

> URL이 `/about`이면 `<About />`을 보여준다.

정도로 이해할 수도 있습니다.

하지만 더 정확하게는:

> **Route Tree 안에서 하나의 URL pattern과 UI 또는 라우팅 동작을 정의하는 노드**

라고 이해하는 것이 좋습니다.

즉:

```text
Route
│
├── path
│
├── element
│
├── index
│
├── children
│
├── loader
│
├── action
│
└── error handling
```

등의 정보를 가진 **라우팅 규칙의 단위**입니다.

---

# 26. 역할 분담

마지막으로 주요 구성 요소를 비교해보겠습니다.

| 구성 요소           | 역할                            |
| --------------- | ----------------------------- |
| `BrowserRouter` | Browser History와 Router 상태 연결 |
| `Routes`        | 현재 location과 Route Tree를 매칭   |
| `Route`         | URL pattern과 UI의 관계 정의        |
| `Outlet`        | 자식 Route element 렌더링 위치       |
| `useParams()`   | Dynamic Segment 값 조회          |

따라서 구조적으로:

```text
BrowserRouter
      │
      ▼
    Routes
      │
      ▼
 Route Matching
      │
      ▼
Route Branch
      │
      ▼
     Route
      │
      ▼
   element
      │
      ▼
    Outlet
      │
      ▼
Nested element
```

이라고 이해하면 됩니다.

# 최종 정의

`<Route>`를 한 문장으로 정리하면 다음과 같습니다.

> **`<Route>`는 React Router의 Route Tree를 구성하는 하나의 라우팅 규칙으로, 특정 URL pattern이 매칭되었을 때 사용할 React element와 중첩 구조, 동적 세그먼트, index Route 등의 라우팅 정보를 정의합니다.**

조금 더 짧게 표현하면:

> **`<Route>` = URL Pattern ↔ React UI의 연결 규칙**

그리고 전체 구조는 다음 순서로 기억하면 됩니다.

```text
Browser URL
     ↓
BrowserRouter
     ↓
location
     ↓
Routes
     ↓
Route Matching
     ↓
Route Branch
     ↓
Route
     ↓
element
     ↓
Outlet
     ↓
React UI
```

이 구조를 이해하면 `<Route>`는 단순히 “URL에 컴포넌트를 붙이는 태그”가 아니라 **React Router의 전체 Route Tree를 구성하는 기본 노드**라는 점을 명확하게 이해할 수 있습니다.
