# React Router 404 / Not Found Route

## — 어떤 Route와도 매칭되지 않을 때 사용자에게 보여줄 화면

React Router에서 Route를 만들다 보면 반드시 이런 상황이 발생합니다.

사용자가 존재하지 않는 URL로 이동하는 경우입니다.

예를 들어 애플리케이션에 다음 Route만 있다고 하겠습니다.

```jsx id="rm4w6x"
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/about" element={<About />} />
  <Route path="/products" element={<Products />} />
</Routes>
```

그런데 사용자가 주소창에:

```text id="9twfyh"
/abc
```

또는:

```text id="h94ppn"
/products123
```

같은 존재하지 않는 URL을 입력하면 어떻게 해야 할까요?

이때 사용하는 것이 **404 / Not Found Route**입니다.

---

# 1. 404 / Not Found Route란?

한 문장으로 정의하면:

> **Not Found Route는 현재 URL이 정의된 어떤 Route와도 매칭되지 않았을 때 대신 렌더링되는 Route입니다.**

예를 들어:

```jsx id="0du8a9"
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/about" element={<About />} />

  <Route path="*" element={<NotFound />} />
</Routes>
```

여기서:

```jsx id="7za9b4"
<Route path="*" element={<NotFound />} />
```

가 Not Found Route입니다.

`*`는:

> **앞의 다른 Route와 매칭되지 않은 나머지 경로**

를 처리하는 역할을 합니다.

---

# 2. 왜 Not Found Route가 필요한가?

Not Found Route가 없다면 사용자가 잘못된 URL로 들어왔을 때 적절한 안내 화면이 없을 수 있습니다.

예를 들어:

```text id="t43qx8"
/about
```

은 정상 Route입니다.

```text id="uxc4xk"
/unknown
```

은 정의된 Route가 아닙니다.

Route Matching 관점에서 보면:

```text id="mms7fb"
현재 URL
/unknown
   │
   ▼
React Router
   │
   ▼
Route Matching
   │
   ├── "/"         ❌
   ├── "/about"    ❌
   └── "/products" ❌
```

모든 Route가 매칭에 실패했습니다.

이때:

```jsx id="4e1rre"
<Route path="*" element={<NotFound />} />
```

가 있으면:

```text id="xns56t"
모든 Route Match 실패
        │
        ▼
       "*"
        │
        ▼
   <NotFound />
```

가 됩니다.

---

# 3. 가장 기본적인 예제

먼저 `NotFound` 컴포넌트를 만들어보겠습니다.

```jsx id="7vbchi"
function NotFound() {
  return (
    <div>
      <h1>404</h1>
      <p>페이지를 찾을 수 없습니다.</p>
    </div>
  );
}

export default NotFound;
```

Route:

```jsx id="zu2yqb"
import {
  BrowserRouter,
  Routes,
  Route
} from "react-router-dom";

import Home from "./pages/Home";
import About from "./pages/About";
import NotFound from "./pages/NotFound";

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />

        <Route path="*" element={<NotFound />} />
      </Routes>
    </BrowserRouter>
  );
}
```

이제:

```text id="8h80ew"
/
→ Home

/about
→ About

/abc
→ NotFound

/hello/world
→ NotFound
```

가 됩니다.

---

# 4. `*`는 무엇을 의미하는가?

React Router에서 `*`는 **Wildcard** 역할을 합니다.

```jsx id="9v8d9d"
<Route path="*" element={<NotFound />} />
```

는 개념적으로:

> **"앞의 Route들 중 아무것도 매칭되지 않으면 여기로 처리해."**

라고 이해하면 됩니다.

예:

```text id="btmefn"
Routes

├── "/"
├── "/about"
├── "/products"
└── "*"
```

URL이:

```text id="5u2gyr"
/about
```

이면:

```text id="4507sr"
/about
  │
  ▼
About Route
```

가 더 구체적으로 매칭됩니다.

반면:

```text id="s9bfbe"
/something
```

이라면:

```text id="70dkbi"
"/"          ❌
"/about"     ❌
"/products"  ❌
"*"          ✅
```

가 됩니다.

---

# 5. `*`는 마지막에 써야 하나?

코드를 읽는 사람 입장에서는 보통 마지막에 배치하는 것이 가장 자연스럽습니다.

```jsx id="u6xg54"
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/about" element={<About />} />
  <Route path="/products" element={<Products />} />

  <Route path="*" element={<NotFound />} />
</Routes>
```

이렇게 보면 의미가 명확합니다.

```text id="t3sb7w"
정상 Route들
      ↓
마지막 fallback
      ↓
Not Found
```

다만 React Router의 매칭은 단순히 위에서 아래로 첫 번째 것을 선택하는 방식으로만 이해하면 안 됩니다.

React Router는 Route들의 **구체성(specificity)**을 기준으로 매칭합니다.

따라서 핵심은:

> **`*`는 가장 덜 구체적인 fallback Route 역할을 한다.**

입니다.

---

# 6. 404 Route와 HTTP 404는 같은 것인가?

이 부분은 매우 중요합니다.

React Router에서:

```jsx id="pn1z85"
<Route path="*" element={<NotFound />} />
```

를 만든다고 해서 브라우저가 자동으로 HTTP 상태 코드:

```text id="x0hfib"
404 Not Found
```

를 받는 것은 아닙니다.

SPA에서는 보통 서버가 먼저:

```text id="8z0ztv"
index.html
```

을 반환합니다.

그 후 브라우저에서 React Router가 URL을 보고:

```text id="r1vko6"
"이 URL은 어떤 Route와도 매칭되지 않는다."
```

라고 판단하여:

```jsx id="v0sm3a"
<NotFound />
```

를 렌더링합니다.

즉:

```text id="krl008"
Server
  │
  │ index.html
  ▼
Browser
  │
  ▼
React App 실행
  │
  ▼
React Router
  │
  ▼
Route Match 실패
  │
  ▼
<NotFound />
```

입니다.

따라서 **클라이언트에서 NotFound 화면을 보여주는 것**과 **HTTP 응답 자체가 404인 것**은 별개의 문제입니다.

---

# 7. BrowserRouter에서는 서버 설정도 중요하다

예를 들어 사용자가 주소창에 직접:

```text id="7qw1uu"
/products/100
```

을 입력했다고 하겠습니다.

브라우저는 서버에게:

```text id="776a0s"
GET /products/100
```

을 요청합니다.

React Router가 동작하려면 먼저 React 애플리케이션 자체가 로드되어야 합니다.

따라서 SPA 서버는 일반적으로:

```text id="3w5yto"
알 수 없는 경로
      │
      ▼
index.html 반환
```

하도록 fallback 설정이 필요합니다.

그 후 React Router가:

```text id="0mky9b"
/products/100
```

을 분석합니다.

즉:

```text id="4zkzt7"
Browser Request
      │
      ▼
Server
      │
      ▼
index.html
      │
      ▼
React App
      │
      ▼
React Router
      │
      ▼
Route Matching
```

이라는 두 단계가 존재합니다.

이 설정이 없으면 React Router의 Not Found Route까지 도달하기 전에 서버에서 실제 404가 발생할 수 있습니다.

---

# 8. Link를 제공하는 NotFound 화면

Not Found 화면에서는 사용자가 다시 정상 페이지로 돌아갈 수 있도록 링크를 제공하는 것이 좋습니다.

```jsx id="afk06j"
import { Link } from "react-router-dom";

function NotFound() {
  return (
    <div>
      <h1>404</h1>

      <p>
        요청하신 페이지를 찾을 수 없습니다.
      </p>

      <Link to="/">
        홈으로 돌아가기
      </Link>
    </div>
  );
}
```

화면 흐름:

```text id="qwzq2p"
잘못된 URL
   │
   ▼
Not Found
   │
   ▼
"홈으로 돌아가기"
   │
   ▼
<Link to="/">
   │
   ▼
Home
```

입니다.

---

# 9. `useNavigate()`를 사용할 수도 있다

버튼으로 이동시키고 싶다면:

```jsx id="2e2i66"
import { useNavigate } from "react-router-dom";

function NotFound() {
  const navigate = useNavigate();

  return (
    <div>
      <h1>404</h1>

      <button
        onClick={() => navigate("/")}
      >
        홈으로 이동
      </button>
    </div>
  );
}
```

또는 이전 페이지로 돌아갈 수도 있습니다.

```jsx id="cr9u28"
<button
  onClick={() => navigate(-1)}
>
  이전 페이지
</button>
```

즉 기존에 배운:

```text id="yjjy5v"
Link
useNavigate
```

개념을 Not Found 페이지에서 자연스럽게 활용할 수 있습니다.

# 10. Nested Route 안에도 Not Found Route를 둘 수 있다

Not Found Route는 최상위 Routes에만 둘 필요는 없습니다.

예를 들어:

```jsx id="sdocru"
<Routes>
  <Route
    path="/dashboard"
    element={<DashboardLayout />}
  >
    <Route
      index
      element={<DashboardHome />}
    />

    <Route
      path="profile"
      element={<Profile />}
    />

    <Route
      path="settings"
      element={<Settings />}
    />

    <Route
      path="*"
      element={<DashboardNotFound />}
    />
  </Route>
</Routes>
```

Route Tree:

```text id="ml44w8"
Dashboard
│
├── index
├── profile
├── settings
└── *
```

그러면:

```text id="9kk0gf"
/dashboard/profile
→ Profile

/dashboard/settings
→ Settings

/dashboard/abc
→ DashboardNotFound
```

가 됩니다.

---

# 11. Nested Not Found의 장점

예를 들어 `/dashboard/abc`에 접근했을 때 전체 사이트의 404 페이지를 보여주는 것보다:

```text id="al6av0"
Dashboard Layout
│
├── Header
├── Sidebar
└── Dashboard 영역 안의 Not Found
```

처럼 보여주는 것이 더 자연스러울 수 있습니다.

개념적으로:

```text id="aeb716"
┌───────────────────────────────┐
│ Dashboard Header              │
├──────────┬────────────────────┤
│ Sidebar  │                    │
│          │  페이지 없음       │
│          │                    │
└──────────┴────────────────────┘
```

즉 Nested Route별로 **문맥에 맞는 Not Found UI**를 만들 수 있습니다.

# 12. Nested Route + Outlet과 함께 보면

URL이:


이면:

```text id="4hfdfx"
      │
      ▼
```

```text id="pr5lh4"
      │
      ├── Header
```

입니다.

```text id="hbcpbp"
/dashboard/abc
→ DashboardNotFound
```

반면:

```text id="lyp8w2"
/completely-wrong
→ 전체 NotFound
```

가 됩니다.

즉 Route 계층마다 fallback을 둘 수 있습니다.

# 14. `*`가 남은 경로를 잡는 경우

`*`는 Nested Route에서도 유용합니다.

예:

```jsx id="vwt8m9"
<Route
  path="/files/*"
  element={<Files />}
 />
```

이 Route는 개념적으로:

```text id="en97o6"
/files/a
/files/a/b
/files/docs/react/router
```

처럼 `/files` 뒤의 여러 segment를 포함하는 경로를 처리할 수 있습니다.

따라서 `*`는 단순히:

```text id="2ljc99"
404 전용 기호
```

라고 이해하면 부족합니다.

더 정확하게는 **Wildcard Path Segment**이며, Not Found Route에서 매우 자주 활용되는 것입니다.

# 15. Not Found Route에서 `Navigate`로 홈으로 보내도 될까?

다음처럼 할 수도 있습니다.

```jsx id="4affva"
<Route
  path="*"
  element={
    <Navigate
      to="/"
      replace
    />
  }
/>
```

그러면 잘못된 URL에 접근했을 때 자동으로 `/`로 이동합니다.

하지만 이 방식은 신중해야 합니다.

예를 들어 사용자가:

```text id="xjznxr"
/products/9999
```

를 입력했는데 갑자기 홈으로 이동해버리면:

> "내가 URL을 잘못 입력했나?"

> "페이지가 삭제된 건가?"

를 알기 어렵습니다.

따라서 일반적인 사용자 경험에서는:

```text id="5q3nvi"
잘못된 URL
      │
      ▼
명확한 Not Found 안내
      │
      ▼
홈/이전 페이지 이동 선택
```

방식이 더 이해하기 쉽습니다.

# 16. Route Not Found와 Resource Not Found를 구분하자

이 부분도 매우 중요합니다.

다음 URL을 생각해보겠습니다.

```text id="idk24n"
/products/100
```

Route 정의:

```jsx id="791289"
<Route
  path="/products/:productId"
  element={<ProductDetail />}
/>
```

URL 패턴 자체는 정상입니다.

따라서 React Router 입장에서는:

```text id="uphowb"
/products/100
        │
        ▼
Route Match 성공
```

입니다.

하지만 서버에 `productId = 100`인 상품이 존재하지 않을 수도 있습니다.

```text id="yrupxk"
Route
/products/:productId
        │
        ▼
Match 성공
        │
        ▼
API Request
/products/100
        │
        ▼
상품 없음
```

이것은 **Route Not Found가 아닙니다.**

# 17. 두 종류의 Not Found

구분하면 다음과 같습니다.

### Route Not Found

```text id="u05qw3"
/hello/world
```

해당 URL 패턴 자체가 존재하지 않습니다.

```text id="3v251z"
Route Matching 실패
       │
       ▼
path="*"
       │
       ▼
NotFound
```

### Resource Not Found

```text id="p102cf"
/products/9999
```

Route는 정상적으로 존재합니다.

```text id="bcgsae"
/products/:productId
       │
       ▼
Route Matching 성공
```

하지만:

```text id="b4czmr"
productId = 9999
       │
       ▼
DB에 해당 Product 없음
```

인 상황입니다.

이 경우는 `ProductDetail` 내부에서 별도로 처리해야 합니다.

# 18. Resource Not Found 예제

```jsx id="0gixvv"
function ProductDetail() {
  const { productId } = useParams();

  const product = findProduct(productId);

  if (!product) {
    return (
      <div>
        상품을 찾을 수 없습니다.
      </div>
    );
  }

  return (
    <div>
      <h1>{product.name}</h1>
    </div>
  );
}
```

즉:

```text id="8fit8a"
URL Pattern 존재?
       │
   ┌───┴───┐
  YES      NO
   │        │
   ▼        ▼
Route      "*"
Match      Route
   │
   ▼
Resource 존재?
   │
 ┌─┴─┐
YES  NO
 │    │
 ▼    ▼
UI   Resource
     Not Found
```

처럼 생각해야 합니다.

# 19. 404 페이지에는 무엇을 넣는 것이 좋을까?

보통 다음 정도를 포함하면 좋습니다.

```text id="clfwvb"
404
페이지를 찾을 수 없습니다.

현재 URL이 잘못되었거나
페이지가 이동/삭제되었을 수 있습니다.

[홈으로]
[이전 페이지]
```

기술적인 에러 메시지보다는 사용자가 다음 행동을 선택할 수 있도록 만드는 것이 중요합니다.

예:

```jsx id="snih57"
function NotFound() {
  const navigate = useNavigate();

  return (
    <section>
      <h1>404</h1>

      <h2>
        페이지를 찾을 수 없습니다.
      </h2>

      <p>
        주소가 잘못되었거나
        페이지가 이동되었을 수 있습니다.
      </p>

      <Link to="/">
        홈으로
      </Link>

      <button
        onClick={() => navigate(-1)}
      >
        이전 페이지
      </button>
    </section>
  );
}
```

# 20. 전체 흐름을 한 번에 보자

다음 Route가 있다고 하겠습니다.

```jsx id="hpejvi"
<Routes>
  <Route path="/" element={<Home />} />

  <Route
    path="/products"
    element={<ProductsLayout />}
  >
    <Route
      index
      element={<ProductList />}
    />

    <Route
      path=":productId"
      element={<ProductDetail />}
    />

    <Route
      path="*"
      element={<ProductsNotFound />}
    />
  </Route>

  <Route
    path="*"
    element={<NotFound />}
  />
</Routes>
```

### URL: `/`

```text id="oo42aa"
/
↓
Home
```

### URL: `/products`

```text id="nvi95o"
/products
↓
Products
↓
index
↓
ProductList
```

# 21. Route Tree 관점에서 보면 더 명확하다

```text id="08z3kn"
Root
│
├── /
│   └── Home
│
├── /products
│   │
│   ├── index
│   │   └── ProductList
│   │
│   ├── :productId
│   │   └── ProductDetail
│   │
│   └── *
│       └── ProductsNotFound
│
└── *
    └── NotFound
```

React Router는 현재 URL과 가장 적절한 Route Branch를 선택합니다.

즉 `*` 역시 Route Tree 안에 존재하는 하나의 Route입니다.

# 22. 흔한 실수 ① 모든 잘못된 URL을 홈으로 Redirect

```jsx id="qk03cp"
<Route
  path="*"
  element={<Navigate to="/" />}
/>
```

기술적으로 가능하지만 사용자가 왜 원래 페이지에 접근하지 못했는지 알기 어렵습니다.

특별한 요구사항이 없다면 명확한 Not Found 페이지를 보여주는 편이 좋습니다.

# 23. 흔한 실수 ② Resource Not Found와 혼동

```text id="1be6oo"
/products/999
```

이 URL이:

```jsx id="yob9eg"
path="/products/:id"
```

와 매칭된다면 Router 관점에서는 정상 Route입니다.

상품 자체가 없는 것은 데이터 문제입니다.

즉:

```text id="ozhb4c"
Route 존재 여부
≠
Resource 존재 여부
```

입니다.

---

# 24. 흔한 실수 ③ BrowserRouter의 서버 fallback을 잊음

개발 서버에서는:

```text id="0xwy3s"
/products/100
```

새로고침이 잘 될 수 있습니다.

하지만 Production 서버가 SPA fallback을 지원하지 않으면:

```text id="tiakb5"
Browser
   │
   │ GET /products/100
   ▼
Server
   │
   ▼
404
```

가 발생하여 React 애플리케이션 자체가 시작되지 않을 수 있습니다.

이 경우 React Router의:

```jsx id="a9oh0j"
<Route path="*" ... />
```

까지 도달하지 못합니다.

따라서:

```text id="t2465o"
Server SPA Fallback
        +
React Router Not Found Route
```

는 서로 다른 계층의 문제입니다.

---

# 25. 세 가지 404를 구분해서 기억하자

React SPA에서는 "404"라는 표현이 서로 다른 세 상황을 가리킬 수 있습니다.

```text id="84s42b"
① Server 404
────────────────────────
서버에 요청한 URL을
처리하지 못함


② Router Not Found
────────────────────────
React App은 실행됐지만
URL과 매칭되는 Route가 없음


③ Resource Not Found
────────────────────────
Route는 정상적으로 매칭됐지만
요청한 데이터가 존재하지 않음
```

이 세 개를 구분하면 404 처리를 훨씬 정확하게 이해할 수 있습니다.

---

# 26. 한 문장 정의

입문자에게는:

> **404 / Not Found Route는 현재 URL과 일치하는 Route가 없을 때 보여주는 fallback Route입니다.**

조금 더 정확하게 표현하면:

> **React Router의 Not Found Route는 Route Tree에서 현재 URL에 더 구체적으로 매칭되는 Route가 없을 때 `*` wildcard path를 통해 fallback UI를 렌더링하는 Route입니다.**

---

# 27. 최종 정리

가장 기본적인 형태:

```jsx id="1j276a"
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/about" element={<About />} />

  <Route
    path="*"
    element={<NotFound />}
  />
</Routes>
```

전체 흐름:

```text id="7mstyt"
현재 URL
    │
    ▼
React Router
    │
    ▼
Route Tree Matching
    │
    ▼
정상 Route와 매칭되는가?
    │
 ┌──┴──┐
YES    NO
 │      │
 ▼      ▼
해당   "*"
Route   Route
 │      │
 ▼      ▼
Page   NotFound
```

그리고 Nested Route에서도:

```text id="c7vpf7"
Parent Route
│
├── 정상 Child
├── 정상 Child
└── *
    └── 해당 영역의 Not Found
```

처럼 사용할 수 있습니다.

마지막으로 가장 중요한 구분입니다.

```text id="l1wxjo"
Server 404
→ 서버가 요청 자체를 처리하지 못함


Router Not Found
→ React Router가 URL에 맞는 Route를 찾지 못함


Resource Not Found
→ Route는 맞지만 데이터가 존재하지 않음
```

따라서 React Router에서 404 처리를 제대로 이해한다는 것은 단순히:

```jsx id="qbd6nt"
<Route path="*" element={<NotFound />} />
```

를 외우는 것이 아니라,

> **현재 URL이 Route Tree에서 어떻게 매칭되고, 어떤 계층에서 "찾을 수 없음"이 발생했는지를 구분하는 것**

입니다.
