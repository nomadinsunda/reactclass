좋습니다. 지금까지의 흐름에서 `navigation`은 **Router가 한 URL에서 다른 URL로 이동하는 전체 과정**을 의미합니다.

```text
Route Object[]
      ↓
createBrowserRouter()
      ↓
Router
      ↓
★ Navigation
      ↓
Router State 변경
      ↓
RouterProvider
      ↓
React UI
```

특히 `navigate()`와 `navigation`을 구분하는 것이 중요합니다.

> **`navigate()`는 "이동을 시작하라"는 명령이고, `navigation`은 그 명령을 받아 Router가 새로운 Route로 이동하면서 수행하는 전체 과정 및 그 진행 상태입니다.**

# 1. Navigation이란?

예를 들어 현재 URL이:

```text
/
```

인데 사용자가:

```jsx
<Link to="/products">Products</Link>
```

를 클릭했다고 하겠습니다.

React Router는 단순히 주소를:

```text
/ → /products
```

로 바꾸고 끝나는 것이 아닙니다.

Data Router에서는 그 과정에서 다음과 같은 작업이 발생할 수 있습니다.

```text
/products로 이동 요청
        ↓
Route Matching
        ↓
필요한 loader 결정
        ↓
loader 실행
        ↓
데이터 준비
        ↓
navigation 결과 commit
        ↓
Router State 갱신
        ↓
React UI 업데이트
```

이 전체 과정이 **navigation**입니다.

---

# 2. navigate()와 navigation의 차이

매우 중요합니다.

컴포넌트에서:

```jsx
const navigate = useNavigate();

navigate("/products");
```

라고 했다고 하겠습니다.

여기서 `navigate()`는 **함수**입니다.

```text
navigate("/products")
        ↓
"Router야 /products로 이동해"
```

라는 이동 요청입니다.

반면 `navigation`은:

```text
요청 접수
   ↓
Route Matching
   ↓
데이터 로딩
   ↓
상태 변경
   ↓
이동 완료
```

라는 **Router의 이동 과정**을 가리킵니다.

따라서:

```text
navigate()
    │
    │ 이동 요청
    ▼
Router
    │
    ▼
navigation
```

으로 이해하면 좋습니다.

---

# 3. navigation은 누가 관리하는가?

**Router 객체**가 관리합니다.

```text
Router
│
├─ Route Matching
├─ navigation
├─ loader
├─ action
├─ error handling
├─ History
│
└─ Router State
```

Router State에는 현재 navigation 진행 상태도 들어 있습니다.

개념적으로:

```js
router.state.navigation
```

입니다.

즉:

```text
Router
└─ state
   └─ navigation
```

입니다.

---

# 4. router.state.navigation

`router.state.navigation`은 **현재 진행 중인 navigation에 대한 상태와 관련 정보**를 나타냅니다.

대표적으로 가장 중요한 것은:

```js
router.state.navigation.state
```

입니다.

상태 값은:

```text
idle
loading
submitting
```

입니다.

여기서 주의할 점이 있습니다.

**`error`는 `navigation.state`의 상태값이 아닙니다.**

에러는 별도의 Router error 처리 흐름으로 다뤄집니다.

따라서 정확한 상태는:

```text
idle
loading
submitting
```

세 가지입니다.

---

# 5. idle

아무 navigation도 진행 중이지 않은 상태입니다.

```text
navigation.state = "idle"
```

예를 들어 현재 `/` 페이지가 정상적으로 표시되고 있다면:

```text
현재 URL: /
navigation.state: idle
```

입니다.

```text
┌───────────────────┐
│       idle        │
│                   │
│ 이동 작업 없음   │
└───────────────────┘
```

---

# 6. loading

새로운 Route로 이동하면서 데이터를 준비하고 있는 상태입니다.

예를 들어:

```jsx
{
  path: "/products",
  element: <Products />,
  loader: productsLoader,
}
```

가 있다고 하겠습니다.

사용자가:

```jsx
<Link to="/products">
  Products
</Link>
```

를 클릭하면:

```text
idle
 ↓
navigation 시작
 ↓
loading
 ↓
Route Matching
 ↓
productsLoader()
 ↓
데이터 준비
 ↓
commit
 ↓
idle
```

이 됩니다.

즉 일반적인 navigation은:

```text
idle → loading → idle
```

입니다.

---

# 7. submitting

`action`으로 데이터를 제출하는 동안 사용되는 상태입니다.

예를 들어:

```jsx
<Form method="post">
  <input name="name" />
  <button>등록</button>
</Form>
```

이 있고 Route에는:

```jsx
{
  path: "/products/new",
  element: <NewProduct />,
  action: createProductAction,
}
```

이 있다고 하겠습니다.

Form을 제출하면:

```text
idle
 ↓
submit
 ↓
submitting
 ↓
action()
 ↓
action 완료
 ↓
필요한 loader revalidation
 ↓
loading
 ↓
idle
```

처럼 진행될 수 있습니다.

따라서 mutation이 포함된 대표적인 흐름은:

```text
idle
 ↓
submitting
 ↓
loading
 ↓
idle
```

입니다.

---

# 8. loading과 submitting의 차이

둘을 구분하면 navigation이 훨씬 쉬워집니다.

```text
loading
= 데이터를 읽고 이동하는 중

submitting
= 데이터를 변경하기 위해 제출하는 중
```

대표적인 예는:

| 상태           | 상황                       |
| ------------ | ------------------------ |
| `idle`       | 작업 없음                    |
| `loading`    | Route 이동 / loader 데이터 로딩 |
| `submitting` | Form 제출 / action 실행      |

예를 들어:

```text
상품 목록으로 이동

/products
   ↓
loader
   ↓

idle → loading → idle
```

반면 상품 등록은:

```text
상품 등록 Form
     ↓
POST
     ↓
action
     ↓
loader revalidation

idle → submitting → loading → idle
```

처럼 이해할 수 있습니다.

---

# 9. useNavigation()

React 컴포넌트에서 `router.state.navigation`을 직접 다루기보다는 일반적으로:

```jsx
useNavigation()
```

을 사용합니다.

```jsx
import { useNavigation } from "react-router-dom";

function RootLayout() {
  const navigation = useNavigation();

  return (
    <>
      {navigation.state === "loading" && (
        <p>Loading...</p>
      )}

      <Outlet />
    </>
  );
}
```

관계는:

```text
Router
  │
  └─ state.navigation
           ↓
    RouterProvider
           ↓
      React Context
           ↓
    useNavigation()
           ↓
     Component
```

입니다.

---

# 10. useNavigate()와 useNavigation()

이름이 비슷해서 초보자가 매우 많이 혼동합니다.

### useNavigate()

```jsx
const navigate = useNavigate();

navigate("/products");
```

**이동시키는 기능**을 가져옵니다.

```text
useNavigate()
     ↓
navigate()
     ↓
이동 요청
```

### useNavigation()

```jsx
const navigation = useNavigation();

navigation.state
```

**현재 이동 진행 상황**을 가져옵니다.

```text
useNavigation()
      ↓
navigation
      ↓
현재 이동 상태 확인
```

따라서:

```text
useNavigate
    ↓
"이동시켜!"

useNavigation
    ↓
"지금 이동이 어떻게 진행되고 있어?"
```

라고 기억하면 쉽습니다.

---

# 11. navigation 객체에는 state만 있는 것이 아니다

`useNavigation()`이 반환하는 navigation 객체는 진행 상태뿐 아니라 **현재 진행 중인 navigation에 관한 정보**도 제공합니다.

개념적으로:

```js
const navigation = useNavigation();
```

그리고 다음과 같은 정보를 볼 수 있습니다.

```text
navigation
│
├─ state
├─ location
├─ formMethod
├─ formAction
├─ formEncType
├─ formData
├─ json
└─ text
```

버전과 사용하는 API에 따라 세부적인 의미는 달라질 수 있지만 핵심은:

> **navigation은 단순히 `"loading"`이라는 문자열 하나가 아니라 현재 이동/제출 작업에 관한 정보를 담은 객체입니다.**

---

# 12. navigation.location

현재 **이동하려고 하는 목적지 location**을 알 수 있습니다.

예를 들어 현재:

```text
/
```

에서:

```text
/products
```

로 이동하고 있다면 navigation 도중 개념적으로:

```text
현재 Router location
/

navigation.location
/products
```

처럼 볼 수 있습니다.

이 차이가 중요합니다.

navigation이 완료되기 전에는:

```text
현재 화면
     │
     ▼
location = "/"

이동 목적지
     │
     ▼
navigation.location = "/products"
```

일 수 있습니다.

그리고 navigation이 commit되면:

```text
location = "/products"

navigation.state = "idle"
```

이 됩니다.

---

# 13. navigation과 loader

Data Router에서 navigation이 중요한 가장 큰 이유 중 하나입니다.

일반 SPA Router를 아주 단순화하면:

```text
URL 변경
   ↓
Component 변경
```

이라고 생각할 수 있습니다.

하지만 Data Router에서는:

```text
Navigation
    ↓
Route Matching
    ↓
loader 확인
    ↓
loader 실행
    ↓
데이터 준비
    ↓
Route commit
    ↓
UI 업데이트
```

가 가능합니다.

즉 **navigation과 데이터 로딩이 하나의 라우팅 생명주기 안에서 연결됩니다.**

---

# 14. navigation과 action

Form 제출에서는 action도 navigation 과정에 참여합니다.

```text
<Form> submit
      ↓
navigation
      ↓
submitting
      ↓
action()
      ↓
데이터 변경
      ↓
loader revalidation
      ↓
loading
      ↓
새 데이터 준비
      ↓
idle
```

그래서 `navigation.state`를 사용하면:

```jsx
const navigation = useNavigation();

const submitting =
  navigation.state === "submitting";
```

처럼 제출 중 UI를 만들 수 있습니다.

```jsx
<button disabled={submitting}>
  {submitting ? "등록 중..." : "등록"}
</button>
```

# 15. navigation과 Router State

Router 관점에서 보면 navigation은 Router State 변화 과정입니다.

처음에는:

```text
Router State

location = "/"
navigation.state = "idle"
```

사용자가 `/products`로 이동합니다.

```text
navigate("/products")
        ↓

Router State

location = "/"
navigation.state = "loading"
navigation.location = "/products"
```

loader가 끝나고 navigation이 commit되면:

```text
Router State

location = "/products"
navigation.state = "idle"
loaderData = products
```

즉 navigation을 이해하려면:

> **현재 location과 이동 중인 navigation.location을 구분하는 것**

도 중요합니다.

# 16. navigation과 History API

브라우저 Router이므로 최종적으로 브라우저 History와도 연결됩니다.

```text
navigate("/products")
       ↓
Router navigation
       ↓
Route Matching
       ↓
loader/action 등 처리
       ↓
navigation commit
       ↓
Browser History / URL 반영
       ↓
Router State 확정
```

여기서 중요한 것은 React Router navigation을 단순히:

```text
navigate()
↓
history.pushState()
```

라고만 이해하면 부족하다는 것입니다.

Data Router에서는 그 사이에:

```text
Route Matching
loader
action
redirect
error handling
revalidation
```

등의 작업이 개입할 수 있기 때문입니다.

# 17. Link도 결국 navigation을 발생시킨다

다음 코드도:

```jsx
<Link to="/products">
  Products
</Link>
```

Router navigation을 발생시킵니다.

그리고:

```jsx
const navigate = useNavigate();

navigate("/products");
```

도 Router navigation을 발생시킵니다.

차이는 **navigation을 요청하는 방법**입니다.

```text
<Link>
   │
   │ 사용자 클릭
   ▼
navigation


navigate()
   │
   │ JavaScript 코드
   ▼
navigation
```

결국 둘 다 Router의 navigation 시스템으로 들어갑니다.

지금까지의 이미지 시리즈를 연결하면 navigation의 위치가 훨씬 명확합니다.

```text
Route Object[]
      │
      │ 라우팅 규칙
      ▼
createBrowserRouter()
      │

      │
```

## 핵심 정리

가장 중요한 개념은 네 가지입니다.

```text
navigate()
= 이동을 요청하는 함수

navigation
= Router가 이동을 처리하는 전체 과정

navigation.state
= 현재 navigation의 진행 상태
  idle / loading / submitting

useNavigation()
= React Component에서
  현재 navigation 정보를 읽는 Hook
```

따라서 가장 간단하게 정리하면:

> **Navigation은 단순한 URL 변경이 아니라, Router가 이동 요청을 받아 Route Matching → loader/action → 데이터 준비 → commit → Router State 갱신 → React UI 업데이트까지 수행하는 라우팅 생명주기입니다.**

그리고 이 개념을 정확히 잡아두면 다음에 **`useNavigation()`**, **`navigate()`**, **loader/action revalidation**, **redirect**를 설명할 때 모두 하나의 흐름으로 연결됩니다.
