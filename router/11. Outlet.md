# `<Outlet />` — 중첩 Route의 렌더링 위치

## 1. `<Outlet />`이란?

`<Outlet />`은 React Router에서 **현재 부모 Route 아래에 매칭된 자식 Route의 `element`가 렌더링될 위치**를 나타내는 컴포넌트입니다.

```jsx
import { Outlet } from "react-router-dom";

function Layout() {
  return (
    <div>
      <Header />

      <main>
        <Outlet />
      </main>

      <Footer />
    </div>
  );
}
```

한 문장으로 정의하면:

> **`<Outlet />`은 Router가 현재 URL과 매칭한 child route의 `element`를 부모 컴포넌트 안에 렌더링하는 자리입니다.**

원문에서 표현한 것처럼 쉽게 생각하면 **“자식 Route가 들어갈 자리”**입니다. 

---

# 2. 왜 `<Outlet />`이 필요한가?

다음과 같은 사이트가 있다고 해보겠습니다.

```text
Header
────────────────────
       Page
────────────────────
Footer
```

URL에 따라 가운데 `Page`만 바뀝니다.

```text
/            → Home
/about       → About
/dashboard   → Dashboard
```

우리가 원하는 구조는 다음과 같습니다.

```text
              URL
               │
               ▼
         React Router
               │
               ▼
        어떤 Route인가?
               │
      ┌────────┼─────────┐
      ▼        ▼         ▼
    Home     About    Dashboard
      │        │         │
      └────────┼─────────┘
               ▼
          <Outlet />
               │
               ▼
┌─────────────────────────────┐
│ Header                      │
├─────────────────────────────┤
│                             │
│      현재 페이지            │
│                             │
├─────────────────────────────┤
│ Footer                      │
└─────────────────────────────┘
```

즉, `Header`와 `Footer`는 그대로 유지하면서 **URL에 따라 가운데 내용만 Router가 결정하도록 만드는 것**입니다.

---

# 3. Route의 부모·자식 구조

먼저 Route를 중첩해서 선언합니다.

```jsx
<Routes>
  <Route path="/" element={<AppLayout />}>
    <Route index element={<Home />} />
    <Route path="about" element={<About />} />
    <Route path="dashboard" element={<Dashboard />} />
  </Route>
</Routes>
```

Route Tree로 표현하면:

```text
Route "/"
element = <AppLayout />
│
├── index
│   └── <Home />
│
├── "about"
│   └── <About />
│
└── "dashboard"
    └── <Dashboard />
```

여기서 `AppLayout`은 **부모 Route의 element**이고,

`Home`, `About`, `Dashboard`는 **자식 Route의 element**입니다. 

---

# 4. 부모 컴포넌트에 `<Outlet />` 배치

이제 `AppLayout`에 `<Outlet />`을 넣습니다.

```jsx
import { Outlet } from "react-router-dom";

function AppLayout() {
  return (
    <>
      <Header />

      <main>
        <Outlet />
      </main>

      <Footer />
    </>
  );
}
```

`AppLayout`은 다음과 같은 틀을 제공합니다.

```text
<AppLayout>

    <Header />

    ┌─────────────────────┐
    │                     │
    │     <Outlet />      │
    │                     │
    └─────────────────────┘

    <Footer />

</AppLayout>
```

그리고 Router가 `<Outlet />` 위치에 현재 URL과 매칭된 자식 Route의 `element`를 렌더링합니다.

---

# 5. URL에 따라 무엇이 들어가는가?

앞의 Route 설정을 다시 보겠습니다.

```jsx
<Route path="/" element={<AppLayout />}>
  <Route index element={<Home />} />
  <Route path="about" element={<About />} />
  <Route path="dashboard" element={<Dashboard />} />
</Route>
```

### URL이 `/`

```text
<AppLayout>
    <Header />

    <Outlet>
        <Home />
    </Outlet>

    <Footer />
</AppLayout>
```

### URL이 `/about`

```text
<AppLayout>
    <Header />

    <Outlet>
        <About />
    </Outlet>

    <Footer />
</AppLayout>
```

### URL이 `/dashboard`

```text
<AppLayout>
    <Header />

    <Outlet>
        <Dashboard />
    </Outlet>

    <Footer />
</AppLayout>
```

여기서 `<Outlet>...</Outlet>` 표기는 **실제 JSX 코드가 아니라 렌더링 관계를 설명하기 위한 개념도**입니다.

실제 코드는 항상:

```jsx
<Outlet />
```

입니다.

원문의 핵심도 바로 이 부분입니다. URL이 `/`, `/about`, `/dashboard`일 때 각각 `Home`, `About`, `Dashboard`가 같은 `<Outlet />` 위치에 렌더링됩니다. 

---

# 6. `<Outlet />`의 실제 동작 흐름

URL이 다음과 같다고 해보겠습니다.

```text
/dashboard
```

React Router는 Route Tree를 확인합니다.

```text
Route Tree

"/"                  → <AppLayout />
 │
 └── "dashboard"     → <Dashboard />
```

그리고 현재 URL과 매칭되는 Route branch를 찾습니다.

```text
/dashboard
     │
     ▼
Route Matching
     │
     ├── "/"
     │    → <AppLayout />
     │
     └── "dashboard"
          → <Dashboard />
```

그 결과 렌더링 구조는:

```text
<AppLayout>
      │
      ├── <Header />
      │
      ├── <Outlet />
      │       │
      │       ▼
      │   <Dashboard />
      │
      └── <Footer />
```

가 됩니다.

따라서 핵심 흐름은:

```text
URL 변경
   ↓
Route Tree 탐색
   ↓
Route Matching
   ↓
부모 Route element 렌더링
   ↓
<Outlet />
   ↓
매칭된 child Route element 렌더링
```

입니다.

---

# 7. `<Outlet />`은 여러 단계로 이어질 수 있다

중첩 Route는 한 단계로 끝날 필요가 없습니다.

```jsx
<Routes>
  <Route path="/" element={<AppLayout />}>

    <Route path="dashboard" element={<DashboardLayout />}>

      <Route index element={<DashboardHome />} />
      <Route path="reports" element={<Reports />} />
      <Route path="settings" element={<Settings />} />

    </Route>

  </Route>
</Routes>
```

Route Tree는 다음과 같습니다.

```text
AppLayout
│
└── DashboardLayout
    │
    ├── DashboardHome
    ├── Reports
    └── Settings
```

이 경우 두 Layout 모두 `<Outlet />`을 가질 수 있습니다.

```jsx
function AppLayout() {
  return (
    <>
      <Header />
      <Outlet />
    </>
  );
}
```

```jsx
function DashboardLayout() {
  return (
    <>
      <DashboardSidebar />
      <Outlet />
    </>
  );
}
```

URL이:

```text
/dashboard/reports
```

라면:

```text
<AppLayout>
     │
     └── <Outlet />
            │
            ▼
     <DashboardLayout>
            │
            └── <Outlet />
                   │
                   ▼
               <Reports />
```

가 됩니다.

즉:

> **중첩 Route의 각 단계에서 `<Outlet />`은 다음 child route로 이어지는 렌더링 연결점입니다.**

원문에서도 `/dashboard/reports`가 `AppLayout → DashboardLayout → Reports`로 이어지는 구조를 같은 방식으로 설명하고 있습니다. 

---

# 8. `<Outlet />`이 없으면?

다음 Route가 있다고 하겠습니다.

```jsx
<Route path="/" element={<AppLayout />}>
  <Route index element={<Home />} />
</Route>
```

그런데 `AppLayout`이:

```jsx
function AppLayout() {
  return (
    <>
      <Header />
    </>
  );
}
```

처럼 `<Outlet />`을 가지고 있지 않다면 부모 Route는 렌더링되지만 **매칭된 자식 Route의 UI가 표시될 위치가 없습니다.**

결과:

```text
<AppLayout>
     │
     └── Header      ← 보임

<Home />             ← 표시될 Outlet이 없음
```

따라서 중첩 Route를 구성했다면 **부모 element에서 자식 UI를 보여줄 위치에 `<Outlet />`이 필요합니다.** 

---

# 9. Index Route와 `<Outlet />`

다음 설정을 보겠습니다.

```jsx
<Route path="/products" element={<ProductsLayout />}>
  <Route index element={<ProductList />} />
  <Route path=":id" element={<ProductDetail />} />
</Route>
```

`index` Route는 부모 URL 자체에 매칭되는 **기본 자식 Route**입니다.

따라서:

```text
/products
     │
     ▼
<ProductsLayout>
     │
     ▼
<Outlet />
     │
     ▼
<ProductList />
```

반면:

```text
/products/42
     │
     ▼
<ProductsLayout>
     │
     ▼
<Outlet />
     │
     ▼
<ProductDetail />
```

입니다.

자식 Route가 매칭되지 않으면 `<Outlet />`에는 렌더링할 자식 element가 없습니다. 부모 URL에 기본 화면이 필요하다면 `index` Route를 정의할 수 있습니다. 

---

# 10. `<Outlet />` vs `children`

두 개념은 겉보기에는 비슷합니다.

### `children`

```jsx
<Layout>
  <Home />
</Layout>
```

```jsx
function Layout({ children }) {
  return (
    <main>
      {children}
    </main>
  );
}
```

여기서는 개발자가 직접:

```jsx
<Home />
```

을 전달했습니다.

### `<Outlet />`

```jsx
function Layout() {
  return (
    <main>
      <Outlet />
    </main>
  );
}
```

여기서는 개발자가 자식 페이지를 직접 전달하지 않습니다.

```text
현재 URL
   ↓
React Router
   ↓
Route Matching
   ↓
child Route 결정
   ↓
<Outlet />
```

차이를 정리하면:

| 구분          | `<Outlet />`     | `children`            |
| ----------- | ---------------- | --------------------- |
| 자식을 결정하는 주체 | React Router     | 컴포넌트를 사용하는 코드         |
| 결정 기준       | URL + Route Tree | JSX로 직접 전달            |
| 주요 목적       | Nested Routing   | Component Composition |
| 대표 사용       | Layout Route     | 일반 UI Container       |

따라서 입문 단계에서는:

> **`<Outlet />`은 Router가 관리하는 `children`과 비슷하다.**

라고 이해할 수 있습니다.

다만 정확하게는 둘은 **자식을 결정하는 주체와 목적이 서로 다릅니다.**

---

# 11. `<Outlet context>`로 자식 Route에 데이터 전달

`<Outlet />`은 자식 Route에 데이터를 전달할 수도 있습니다.

부모:

```jsx
import { Outlet } from "react-router-dom";

function DashboardLayout() {
  const user = {
    id: 1,
    name: "Alice"
  };

  return (
    <main>
      <Outlet context={{ user }} />
    </main>
  );
}
```

자식:

```jsx
import { useOutletContext } from "react-router-dom";

function DashboardHome() {
  const { user } = useOutletContext();

  return <h1>Hello, {user.name}</h1>;
}
```

데이터 흐름:

```text
DashboardLayout
      │
      │ context={{ user }}
      ▼
   <Outlet />
      │
      ▼
DashboardHome
      │
      ▼
useOutletContext()
```

이는 특정 Route 계층 안에서 부모 Layout과 자식 Route가 데이터를 공유할 때 유용합니다. 원문도 이를 전역 상태보다는 **특정 레이아웃 계층 안에서 공유할 값**에 적합한 방식으로 설명하고 있습니다. 

---

# 12. 실무에서 자주 사용하는 구조

`<Outlet />`은 단순한 페이지 교체뿐 아니라 여러 Layout 패턴에 사용됩니다.

```text
AppLayout
│
├── Header
├── Navigation
├── Outlet
└── Footer


ProtectedLayout
│
├── Authentication Check
└── Outlet


DashboardLayout
│
├── Sidebar
└── Outlet


SettingsLayout
│
├── Tabs
└── Outlet
```

예를 들어 인증 Layout:

```jsx
function ProtectedLayout() {
  const isLoggedIn = useAuth();

  if (!isLoggedIn) {
    return <Navigate to="/login" replace />;
  }

  return <Outlet />;
}
```

```jsx
<Route element={<ProtectedLayout />}>
  <Route path="/dashboard" element={<Dashboard />} />
  <Route path="/settings" element={<Settings />} />
</Route>
```

인증을 통과한 child route만 `<Outlet />`을 통해 렌더링하는 구조입니다. 

---

# 13. 자주 하는 실수

가장 중요한 것은 다음 네 가지입니다.

1. **부모 Route의 element에 `<Outlet />`을 넣지 않음**

   * 부모 Layout은 보이는데 자식 페이지가 보이지 않음

2. **중첩 Route의 상대 경로를 잘못 작성**

   ```jsx
   <Route path="dashboard" element={<DashboardLayout />}>
     <Route path="settings" element={<Settings />} />
   </Route>
   ```

3. **`<Outlet />`과 `children`의 역할을 혼동**

   * `children`은 직접 전달
   * `<Outlet />`은 Router가 매칭 결과에 따라 제공

4. **`Outlet context`를 전역 상태처럼 사용**

   * 특정 Route/Layout 계층에서 공유하는 데이터에 적합

이 부분은 원문의 실수 목록과도 일치합니다.

# 14. 전체 동작을 한 번에 이해하기

다음 코드가 있다고 하겠습니다.

```jsx
<Routes>
  <Route path="/" element={<AppLayout />}>
    <Route index element={<Home />} />

    <Route path="dashboard" element={<DashboardLayout />}>
      <Route index element={<DashboardHome />} />
      <Route path="reports" element={<Reports />} />
    </Route>
  </Route>
</Routes>
```

사용자가:

```text
/dashboard/reports
```

로 이동하면:

```text
URL
/dashboard/reports
        │
        ▼
   <Routes>
        │
        ▼
Route Tree Matching
        │
        ├── /
        │
        ├── dashboard
        │
        └── reports
        │
        ▼
<AppLayout>
        │
        ▼
   <Outlet />
        │
        ▼
<DashboardLayout>
        │
        ▼
   <Outlet />
        │
        ▼
    <Reports />
```

최종 UI는 개념적으로:

```text
┌─────────────────────────────────┐
│ AppLayout                       │
│                                 │
│  Header                         │
│                                 │
│  ┌───────────────────────────┐  │
│  │ DashboardLayout           │  │
│  │                           │  │
│  │ Sidebar                   │  │
│  │                           │  │
│  │  ┌─────────────────────┐  │  │
│  │  │ Reports             │  │  │
│  │  │                     │  │  │
│  │  │                     │  │  │
│  │  └─────────────────────┘  │  │
│  └───────────────────────────┘  │
│                                 │
│  Footer                         │
└─────────────────────────────────┘
```

가 됩니다.

# 최종 정리

`<Outlet />`을 이해할 때 가장 중요한 것은 **“빈 공간” 자체가 아니라 누가 그 공간에 들어갈 컴포넌트를 결정하는가**입니다.

```text
children

개발자가 JSX로
자식을 직접 결정
       │
       ▼
  {children}


Outlet

현재 URL
   │
   ▼
React Router
   │
   ▼
Route Matching
   │
   ▼
child Route의 element 결정
   │
   ▼
<Outlet />
```

따라서 가장 정확한 정의는 다음과 같습니다.

> **`<Outlet />`은 중첩 라우팅에서 React Router가 현재 URL과 매칭한 child route의 `element`를 부모 route의 element 내부에 렌더링하는 위치를 나타내는 컴포넌트입니다.**

그리고 강의에서는 다음 한 문장으로 시작하면 가장 직관적입니다.

> **부모 Route는 레이아웃을 만들고, Router는 URL을 보고 자식 Route를 선택하며, `<Outlet />`은 그 자식이 들어가는 자리다.**
