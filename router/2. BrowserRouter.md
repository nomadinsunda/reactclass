

# React `BrowserRouter`

## — 브라우저 URL과 React Router를 연결하는 라우팅 엔진

React로 SPA(Single Page Application)를 만들다 보면 다음과 같은 일이 자연스럽게 일어납니다.

```text
/              → Home
/about         → About
/users         → Users
/users/10      → UserDetail
```

주소창의 URL은 계속 바뀌지만 페이지 전체가 새로고침되지는 않습니다.

심지어 브라우저의 **뒤로 가기 / 앞으로 가기**도 정상적으로 동작합니다.

이 동작의 중심에 있는 것이 바로 `BrowserRouter`입니다.

---

# 1. `BrowserRouter`란?

먼저 한 문장으로 정의해 보겠습니다.

> **`BrowserRouter`는 브라우저의 History API를 기반으로 현재 URL과 React Router의 라우팅 상태를 동기화하고, 그 정보를 하위 라우팅 컴포넌트와 Hook이 사용할 수 있도록 제공하는 최상위 Router 컴포넌트입니다.**

기본적인 사용 방법은 다음과 같습니다.

```jsx
import { BrowserRouter } from 'react-router-dom';

function App() {
  return (
    <BrowserRouter>
      <Routes>
        ...
      </Routes>
    </BrowserRouter>
  );
}
```

보통 실제 프로젝트에서는 `main.jsx`에서 전체 애플리케이션을 감쌉니다.

```jsx
ReactDOM.createRoot(document.getElementById('root')).render(
  <BrowserRouter>
    <App />
  </BrowserRouter>
);
```

구조적으로 보면 다음과 같습니다.

```text
Browser
   │
   │ URL / History
   ▼
BrowserRouter
   │
   │ Router Context
   ▼
React Application
   │
   ├── Routes
   ├── Route
   ├── Link
   ├── NavLink
   ├── useNavigate()
   ├── useLocation()
   ├── useParams()
   └── useSearchParams()
```

즉, `BrowserRouter`는 **브라우저와 React Router 세계를 연결하는 경계**에 위치합니다.

---

# 2. 왜 `BrowserRouter`가 필요한가?

이를 이해하려면 먼저 MPA와 SPA의 차이를 알아야 합니다.

## 전통적인 MPA

전통적인 웹에서는 사용자가 다음 링크를 클릭하면

```text
/users/10
```

브라우저가 서버에 새로운 HTTP 요청을 보냅니다.

```text
Browser
   │
   │ GET /users/10
   ▼
Server
   │
   │ HTML Response
   ▼
Browser
   │
   ▼
새로운 페이지 로드
```

즉,

```text
URL 변경
   ↓
서버 요청
   ↓
새 HTML 문서
   ↓
전체 페이지 로드
```

방식입니다.

---

# 3. SPA에서는 무엇이 다른가?

React SPA는 최초 접속 시 보통 하나의 HTML 문서를 로드합니다.

```text
index.html
```

그리고 이후 화면 전환은 React가 담당합니다.

```text
/users
   ↓
/users/10
```

으로 이동한다고 해서 반드시 새로운 HTML 문서를 서버에서 받아올 필요가 없습니다.

React가 기존 페이지 안에서

```text
<Users />
```

대신

```text
<UserDetail />
```

을 렌더링하면 됩니다.

즉 우리가 원하는 것은 다음과 같습니다.

```text
URL 변경
   ↓
페이지 전체 새로고침 X
   ↓
React가 URL 확인
   ↓
해당 컴포넌트 렌더링
```

그런데 여기서 문제가 하나 생깁니다.

> **페이지를 새로고침하지 않고 브라우저 주소창의 URL을 어떻게 변경할 것인가?**

이 문제를 해결하는 브라우저 기능이 **History API**입니다.

---

# 4. 핵심 기반 기술: History API

브라우저의 `window.history` 객체는 현재 탭의 세션 히스토리를 관리합니다.

대표적인 API가 다음 세 가지입니다.

```js
history.pushState()
history.replaceState()
popstate
```

---

## 4.1 `history.pushState()`

```js
history.pushState(
  { id: 10 },
  '',
  '/users/10'
);
```

실행하면 주소창이

```text
http://localhost:5173/users
```

에서

```text
http://localhost:5173/users/10
```

으로 변경됩니다.

중요한 점은 다음입니다.

> **URL은 변경되지만 새로운 HTML 문서를 요청하는 페이지 이동은 발생하지 않습니다.**

그리고 새로운 History Entry가 추가됩니다.

```text
History Stack

/home
/users
/users/10    ← 현재
```

따라서 브라우저의 뒤로 가기가 가능합니다.

---

# 5. `history.replaceState()`

`replaceState()`는 새로운 History Entry를 추가하지 않고 **현재 Entry를 교체**합니다.

```js
history.replaceState(
  null,
  '',
  '/login'
);
```

개념적으로

```text
pushState

A → B → C
        ↑
       추가
```

라면,

```text
replaceState

A → C
    ↑
 B를 교체
```

와 비슷합니다.

React Router의

```jsx
navigate('/login', {
  replace: true
});
```

같은 동작이 이에 대응합니다.

---

# 6. `popstate` 이벤트

이번에는 사용자가 브라우저의 **뒤로 가기** 버튼을 누른다고 생각해 보겠습니다.

```text
/home
   ↓
/users
   ↓
/users/10
```

현재 위치가 `/users/10`일 때 뒤로 가기를 누르면 브라우저의 History Entry가 변경됩니다.

```text
/users/10
     ↓
  BACK
     ↓
/users
```

이러한 History 탐색을 감지할 때 중요한 이벤트가

```js
popstate
```

입니다.

```js
window.addEventListener('popstate', () => {
  console.log(window.location.pathname);
});
```

React Router는 브라우저 History의 이러한 변화를 추적하여 자신의 라우팅 상태를 갱신합니다.

---

# 7. 그렇다면 `BrowserRouter`는 무엇을 하는가?

이제 전체 구조를 연결할 수 있습니다.

```text
┌─────────────────────────────┐
│          Browser            │
│                             │
│ URL                         │
│ window.location             │
│ window.history              │
└──────────────┬──────────────┘
               │
               │ History API
               ▼
┌─────────────────────────────┐
│       BrowserRouter         │
│                             │
│ 현재 location 관리          │
│ navigation 연결             │
│ History 변경 감지           │
└──────────────┬──────────────┘
               │
               │ Context
               ▼
┌─────────────────────────────┐
│       React Router          │
│                             │
│ Routes / Route              │
│ Link / NavLink              │
│ useNavigate                 │
│ useLocation                 │
│ useParams                   │
└─────────────────────────────┘
```

즉 핵심은

```text
Browser History
      ↕
BrowserRouter
      ↕
Router Context
      ↕
Routes / Hooks
```

구조입니다.

---

# 8. `BrowserRouter` 내부 구조를 개념적으로 이해하기

실제 React Router 내부 구현은 버전에 따라 달라질 수 있고 훨씬 복잡합니다.

하지만 학습 목적으로 단순화하면 다음과 같이 생각할 수 있습니다.

```jsx
function BrowserRouter({ children }) {

  // 브라우저 History 기반 navigator 준비
  const history = createBrowserHistory();

  // 현재 location을 React 쪽 상태로 관리
  const [state, setState] = useState({
    location: history.location,
    action: history.action
  });

  // History 변경 구독
  useEffect(() => {
    return history.listen(setState);
  }, [history]);

  return (
    <Router
      location={state.location}
      navigationType={state.action}
      navigator={history}
    >
      {children}
    </Router>
  );
}
```

이 코드는 **개념 설명을 위해 단순화한 수도 코드**입니다.

핵심은 세 가지입니다.

```text
1. 브라우저 History와 연결

2. 현재 location 추적

3. Router Context를 통해 하위 컴포넌트에 제공
```

---

# 9. 중요한 개념: `location`

React Router에서 URL은 단순한 문자열 하나로만 다뤄지지 않습니다.

예를 들어

```text
/users/10?page=2#profile
```

이라는 URL이 있다면 `location`은 개념적으로 다음과 같은 정보를 가집니다.

```js
{
  pathname: '/users/10',
  search: '?page=2',
  hash: '#profile',
  state: null,
  key: '...'
}
```

이 정보를 가져오는 대표적인 Hook이

```jsx
useLocation()
```

입니다.

```jsx
const location = useLocation();

console.log(location.pathname);
```

---

# 10. `Routes`는 무엇을 하는가?

여기서 역할을 정확하게 구분해야 합니다.

`BrowserRouter`가 직접

> "`/users/10`이니까 `UserDetail`을 렌더링해!"

라고 결정하는 것은 아닙니다.

`BrowserRouter`의 핵심 책임은 **현재 location과 navigation 환경을 제공하는 것**입니다.

실제 Route 매칭은 `Routes`와 React Router의 매칭 로직이 담당합니다.

예를 들어 다음과 같은 Route가 있다고 하겠습니다.

```jsx
<Routes>

  <Route
    path="/"
    element={<Home />}
  />

  <Route
    path="/users"
    element={<Users />}
  />

  <Route
    path="/users/:userId"
    element={<UserDetail />}
  />

</Routes>
```

현재 URL이

```text
/users/10
```

이라면 개념적으로

```text
BrowserRouter
      │
      │ location.pathname
      ▼
 "/users/10"
      │
      ▼
   Routes
      │
      │ Route Matching
      ▼
"/users/:userId"
      │
      ▼
<UserDetail />
```

이 됩니다.

---

# 11. `navigate()`를 호출하면 무슨 일이 일어나는가?

다음 코드를 생각해 봅시다.

```jsx
const navigate = useNavigate();

navigate('/users/10');
```

개념적인 흐름은 다음과 같습니다.

```text
navigate("/users/10")
        │
        ▼
React Router navigator
        │
        ▼
History API 기반 이동
        │
        ▼
URL 변경

/users
   ↓
/users/10
        │
        ▼
Router의 location 갱신
        │
        ▼
Routes 재평가
        │
        ▼
Route Matching
        │
        ▼
<UserDetail />
```

이 과정에서 일반적인 문서 탐색처럼 새로운 HTML 문서를 서버에서 다시 받아오는 것은 아닙니다.

이것이 **Client-Side Routing**의 핵심입니다.

---

# 12. `<Link>`도 결국 같은 라우팅 시스템을 사용한다

React Router에서는 일반적으로

```html
<a href="/users/10">
```

대신

```jsx
<Link to="/users/10">
  User 10
</Link>
```

을 사용합니다.

왜일까요?

일반적인 `<a>` 탐색은 브라우저의 문서 탐색을 일으킬 수 있습니다.

```text
<a href>
    ↓
Browser Navigation
    ↓
HTTP Request
    ↓
새 HTML Document
```

반면 React Router의 `<Link>`는 지원되는 일반적인 SPA 탐색에서 브라우저의 기본 문서 이동을 가로채 React Router의 navigation 시스템을 사용합니다.

```text
<Link>
   ↓
React Router
   ↓
History API
   ↓
URL 변경
   ↓
location 변경
   ↓
Route Matching
   ↓
컴포넌트 변경
```

따라서 전체 페이지를 다시 로드하지 않고 화면을 전환할 수 있습니다.

---

# 13. 브라우저 뒤로 가기는 어떻게 동작하는가?

이번에는 사용자가 React 버튼이 아니라 **브라우저의 뒤로 가기 버튼**을 눌렀다고 생각해 보겠습니다.

현재 History가

```text
/
/users
/users/10 ← 현재
```

라고 하겠습니다.

사용자가 뒤로 가기를 누릅니다.

```text
BACK
 ↓
```

브라우저가 이전 History Entry로 이동합니다.

```text
/users
```

이러한 History 탐색을 React Router가 감지합니다.

전체 흐름은 다음과 같습니다.

```text
사용자 BACK 클릭
      │
      ▼
Browser History 이동
      │
      ▼
popstate 계열 History 변화
      │
      ▼
React Router가 변화 감지
      │
      ▼
location 갱신
      │
      ▼
Routes 재평가
      │
      ▼
이전 Route 렌더링
```

그래서 SPA임에도 브라우저의 **뒤로 가기 / 앞으로 가기**가 자연스럽게 동작합니다.

# 14. `BrowserRouter`와 Router Hook의 관계

`BrowserRouter`가 Router Context를 구성하기 때문에 하위 컴포넌트에서는 다양한 Hook을 사용할 수 있습니다.

대표적으로 다음과 같습니다.

| Hook                | 역할                   |
| ------------------- | -------------------- |
| `useNavigate()`     | 프로그래밍 방식의 페이지 이동     |
| `useLocation()`     | 현재 location 조회       |
| `useParams()`       | Dynamic Segment 조회   |
| `useSearchParams()` | Query String 조회 및 변경 |
| `useMatch()`        | 특정 URL 패턴과 현재 URL 비교 |

예를 들어

```jsx
function UserDetail() {

  const { userId } = useParams();
  const navigate = useNavigate();
  const location = useLocation();

  ...
}
```

이 Hook들은 Router가 제공하는 라우팅 Context를 기반으로 동작합니다.

따라서 Router 밖에서 사용하면 오류가 발생합니다.

```text
BrowserRouter
│
└── App
    │
    ├── useNavigate()   OK
    ├── useLocation()   OK
    └── useParams()     OK
```

반대로

```text
useNavigate()    ← Router 밖
     │
     X
BrowserRouter
```

와 같은 구조는 사용할 수 없습니다.

# 15. Vite + React 프로젝트 예제

프로젝트 구조를 다음과 같이 만들어 보겠습니다.

```text
src/
│
├── main.jsx
├── App.jsx
│
├── components/
│   └── Layout.jsx
│
└── pages/
    ├── Home.jsx
    ├── About.jsx
    ├── Users.jsx
    └── UserDetail.jsx
```

## `main.jsx`

```jsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import { BrowserRouter } from 'react-router-dom';

import App from './App';

ReactDOM.createRoot(
  document.getElementById('root')
).render(
  <React.StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </React.StrictMode>
);
```

전체 애플리케이션이 `BrowserRouter` 안에 들어갑니다.

# 16. `App.jsx`

```jsx
import {
  Routes,
  Route
} from 'react-router-dom';

import Layout from './components/Layout';
import Home from './pages/Home';
import About from './pages/About';
import Users from './pages/Users';
import UserDetail from './pages/UserDetail';

export default function App() {

  return (
    <Routes>

      <Route
        path="/"
        element={<Layout />}
      >

        <Route
          index
          element={<Home />}
        />

        <Route
          path="about"
          element={<About />}
        />

        <Route
          path="users"
          element={<Users />}
        />

        <Route
          path="users/:userId"
          element={<UserDetail />}
        />

        <Route
          path="*"
          element={<p>Not Found</p>}
        />

      </Route>

    </Routes>
  );
}
```

현재 URL이

```text
/users/10
```

이라면

```text
BrowserRouter
      │
      ▼
location.pathname
"/users/10"
      │
      ▼
Routes
      │
      ▼
Route Matching
      │
      ▼
users/:userId
      │
      ▼
UserDetail
```

과 같은 흐름으로 이해할 수 있습니다.

# 17. Index Route란?

다음 Route를 보겠습니다.

```jsx
<Route path="/" element={<Layout />}>

  <Route
    index
    element={<Home />}
  />

</Route>
```

`index` Route는 **부모 Route의 URL에 정확히 도달했을 때 기본적으로 렌더링되는 자식 Route**입니다.

따라서 부모가

```text
/
```

라면

```jsx
<Route index element={<Home />} />
```

는 `/`에서 렌더링됩니다.

개념적으로

```text
/
│
├── index → Home
│
├── about → About
│
└── users → Users
```

라고 생각하면 됩니다.

# 18. `BrowserRouter`의 가장 중요한 함정: 새로고침

여기까지 이해했다면 매우 중요한 문제가 하나 남습니다.

React Router를 사용하여

```text
/users/10
```

으로 이동했다고 하겠습니다.

SPA 내부에서 이동할 때는 문제가 없습니다.

```text
React Router Navigation
        ↓
History API
        ↓
/users/10
        ↓
UserDetail
```

그런데 이 상태에서 브라우저의 **새로고침(F5)** 을 누르면 상황이 달라집니다.

---

# 19. 새로고침하면 React Router보다 서버가 먼저 만난다

새로고침을 하면 브라우저는 현재 주소를 서버에 요청합니다.

```http
GET /users/10
```

흐름이 완전히 달라집니다.

```text
F5
 │
 ▼
Browser
 │
 │ GET /users/10
 ▼
Web Server
```

아직 React가 실행되기 전입니다.

따라서 서버가 `/users/10`이라는 실제 리소스를 찾으려고 했는데 존재하지 않는다면

```text
404 Not Found
```

가 발생할 수 있습니다.

---

# 20. SPA Fallback이 필요한 이유

우리가 원하는 것은 서버가 `/users/10`을 직접 처리하는 것이 아닙니다.

서버는 일단

```text
index.html
```

을 내려주고,

그 이후

```text
/users/10
```

이라는 URL의 의미는 React Router가 해석하도록 해야 합니다.

따라서 서버를 다음과 같이 설정합니다.

```text
GET /users/10
      │
      ▼
Web Server
      │
      │ 해당 정적 파일 없음
      ▼
index.html
      │
      ▼
React 실행
      │
      ▼
BrowserRouter
      │
      ▼
현재 URL 확인
/users/10
      │
      ▼
Routes
      │
      ▼
UserDetail
```

이를 일반적으로 **SPA Fallback** 또는 **History API Fallback**이라고 부릅니다.

# 22. `BrowserRouter` vs `HashRouter`

`BrowserRouter`는 다음처럼 일반적인 URL을 사용합니다.

```text
https://example.com/users/10
```

반면 `HashRouter`는

```text
https://example.com/#/users/10
```

형태를 사용합니다.

`#` 이후의 Fragment는 일반적인 HTTP 요청에서 서버로 전달되지 않습니다.

따라서 서버는 기본적으로

```text
https://example.com/
```

부분만 처리하면 됩니다.

이 때문에 서버 측 SPA Fallback 설정이 어려운 환경에서는 `HashRouter`가 편리할 수 있습니다.

---

# 23. `BrowserRouter` vs `HashRouter` vs `MemoryRouter`

| Router          | URL 예         | 기반          | 대표 용도             |
| --------------- | ------------- | ----------- | ----------------- |
| `BrowserRouter` | `/users/10`   | History API | 일반적인 웹 SPA        |
| `HashRouter`    | `/#/users/10` | URL Hash    | 서버 설정이 어려운 환경     |
| `MemoryRouter`  | 주소창 없음        | Memory      | 테스트 및 비브라우저형 시나리오 |

대부분의 일반적인 React 웹 애플리케이션에서는 `BrowserRouter`를 사용합니다.

# 27. 가장 중요한 역할 분담

`BrowserRouter`, `Routes`, `Route`의 역할을 혼동하지 않는 것이 중요합니다.

```text
BrowserRouter
      │
      │ 브라우저 History와
      │ Router 상태 연결
      ▼
    Routes
      │
      │ 현재 location에 대해
      │ Route 매칭 수행
      ▼
     Route
      │
      │ 매칭된 UI 정의
      ▼
React Component
```

따라서 다음처럼 정리할 수 있습니다.

### `BrowserRouter`

> **브라우저 URL/History와 React Router를 연결한다.**

### `Routes`

> **현재 location에 가장 적합한 Route를 매칭한다.**

### `Route`

> **특정 URL 패턴에 어떤 UI를 연결할 것인지 정의한다.**

# 29. 최종 정의

마지막으로 한 문장으로 정리해 보겠습니다.

> **`BrowserRouter`는 브라우저의 History API와 React Router의 라우팅 상태를 연결하여 URL 변경을 추적하고 navigation 환경과 현재 location을 Context를 통해 하위 컴포넌트에 제공함으로써, 페이지 전체를 다시 로드하지 않는 Client-Side Routing을 가능하게 하는 최상위 Router 컴포넌트입니다.**

더 짧게 표현하면 다음과 같습니다.

> **`BrowserRouter` = Browser URL/History ↔ React Router를 연결하는 다리**

그리고 전체 라우팅 구조는 다음 순서로 기억하면 됩니다.

```text
Browser
   ↓
History API
   ↓
BrowserRouter
   ↓
Router Context
   ↓
Routes
   ↓
Route Matching
   ↓
React Component
```

이 흐름을 이해하면 `Link`, `useNavigate`, `useLocation`, `useParams`, Nested Route 같은 React Router의 나머지 기능도 훨씬 쉽게 이해할 수 있습니다.
