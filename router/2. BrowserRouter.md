# 🧠 `BrowserRouter`

## 1. 📌 `BrowserRouter`의 정의

`BrowserRouter`는 React Router에서 제공하는 라우팅 컨테이너로, 브라우저의 **HTML5 History API**를 사용하여 URL을 조작하고 라우팅을 관리합니다.

```jsx
<BrowserRouter>
  <Routes>
    <Route path="/" element={<Home />} />
    <Route path="/about" element={<About />} />
  </Routes>
</BrowserRouter>
```

이 구조는 `window.history.pushState`, `replaceState`, 그리고 `popstate` 이벤트를 활용하여 URL을 변경하고 이에 따라 뷰를 동기화합니다.

---

## 2. 🔧 내부 작동 방식

### 2.1 History API 기반

* `pushState(state, title, url)`은 주소창의 URL을 변경하지만 페이지를 리로드하지 않습니다.
* `popstate` 이벤트는 뒤로가기/앞으로가기 시 발생합니다.

React Router는 이를 감지하여 필요한 `Route` 컴포넌트를 리렌더링합니다.

### 2.2 Context 기반 전역 라우팅 상태 관리

React Router는 내부적으로 `NavigationContext`와 `LocationContext`를 이용해 라우팅 상태를 전역에서 공유합니다.

```tsx
// React Router 내부 (개념 예시)
const NavigationContext = React.createContext();
const LocationContext = React.createContext();

<NavigationContext.Provider value={history}>
  <LocationContext.Provider value={location}>
    {children}
  </LocationContext.Provider>
</NavigationContext.Provider>
```

`useNavigate`, `useLocation`, `useParams` 등의 Hook은 이 Context에서 값을 꺼내 사용합니다.

## 3. 🧱 핵심 구성 요소 비교

| 구성 요소           | 설명                                            |
| --------------- | --------------------------------------------- |
| `BrowserRouter` | History API 사용, URL을 그대로 유지하며 라우팅             |
| `Routes`        | 라우팅 트리 정의, React 6부터 도입된 구성 방식                |
| `Route`         | 개별 경로와 해당 컴포넌트를 연결                            |
| `useNavigate`   | imperative 방식으로 이동하는 Hook                     |
| `useLocation`   | 현재 위치 객체를 제공 (`pathname`, `search`, `hash` 등) |
| `useParams`     | 동적 라우팅 시 URL 파라미터 추출                          |

## 4. 🛠️ 서버 설정과 문제점

### 💥 문제: 새로고침 시 404 에러가 나는 이유

#### ✅ 상황 설명

React Router의 `<BrowserRouter>`는 **HTML5 History API**를 사용합니다. 이 방식은 실제로는 클라이언트(React 앱)에서만 URL을 해석합니다.

* 예를 들어, 사용자가 `http://localhost:3000/about`으로 직접 접속하거나, `/about`에서 새로고침하면...
* 브라우저는 서버에 **`GET /about`** 요청을 보냅니다.
* 서버는 `/about`이라는 **정적 파일 경로가 없기 때문에 404 Not Found 에러**를 반환합니다.

#### ❌ 기본적인 정적 서버는 이 요청을 처리할 수 없습니다.

---

### ✅ 해결책: 모든 경로 요청을 `index.html`로 리디렉션

SPA(싱글 페이지 애플리케이션)에서는 어떤 경로로 들어오든 **항상 `index.html`만 응답하고, 이후 경로 해석은 React Router가 담당**하게 만들어야 합니다.

---

#### 🔧 Vite 개발 서버 설정 (`vite.config.js`)

```js
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  server: {
    historyApiFallback: true  // ← 핵심 설정
  }
});
```

#### 설명:

* Vite의 개발 서버는 내부적으로 [connect-history-api-fallback](https://github.com/bripkens/connect-history-api-fallback)을 사용합니다.
* 이 설정은 개발 중에도 `/about`, `/products/42` 등으로 직접 접근해도 `index.html`을 반환하도록 만듭니다.

---

### 🧠 핵심 정리

| 항목              | 설명                                   |
| --------------- | ------------------------------------ |
| 문제 원인           | 브라우저 새로고침 시 서버가 실제 경로(`/about`)를 요청함 |
| SPA의 특성         | 실제 라우팅은 React Router가 담당해야 함         |
| 해결 방법           | 서버에서 모든 경로 요청을 `index.html`로 리디렉션    |
| 개발 서버(Vite)     | `historyApiFallback: true` 설정 필요     |
| Node/Express 서버 | `app.get('*', ...)` 설정 필요            |

---

## ✅ 결과적으로...

> 이 설정은 SPA의 핵심 개념인 \*\*"라우팅은 클라이언트가 한다"\*\*를 서버에서도 지원하기 위해 반드시 필요합니다.

---

추가로 필요하시면:

* Nginx, Apache, Netlify, Vercel 등의 정적 호스팅 서버 설정 방법도 알려드릴 수 있습니다.
* CSR/SSR 각각의 라우팅 방식 차이도 시각적으로 정리해드릴 수 있습니다.

## 5. 🔁 BrowserRouter vs HashRouter

| 항목          | `BrowserRouter`    | `HashRouter`                 |
| ----------- | ------------------ | ---------------------------- |
| 주소 형태       | `/products/123`    | `/#/products/123`            |
| History API | ✅ 사용               | ❌ 사용 안 함 (hashchange 이벤트 사용) |
| 서버 설정 필요    | ✅ 필요               | ❌ 불필요                        |
| SEO         | ✅ 가능               | ❌ 불가능                        |
| 브라우저 지원     | 최신 브라우저 (IE 10 이상) | 레거시 브라우저까지 가능                |

## 6. ⛓️ 고급 활용: `<basename>`, `<location>`, `<navigator>`

### ✅ `basename` 속성

하위 디렉토리에서 앱을 호스팅할 경우 필요.

```jsx
<BrowserRouter basename="/myapp">
  <Routes>
    <Route path="/" element={<Dashboard />} />
  </Routes>
</BrowserRouter>
```

* 실제 URL: `/myapp/` → 내부적으로 `/`로 처리됨.

### ✅ `location`, `navigator` Props

SSR 또는 커스텀 history 객체를 전달할 때 사용.

```jsx
<BrowserRouter location={customLocation} navigator={customNavigator} />
```

---

## 7. 🧠 React Router v6 이상에서의 변화

* `Switch` → `Routes`로 대체 (정확한 매칭 우선).
* 중첩 라우팅 지원 강화.
* `element={<Component />}` 형식으로 구성.
* `useRoutes` 훅으로 라우팅 정의도 가능 (코드 기반 선언적 라우팅).

---

## 8. 📉 단점 및 주의사항

* SSR 환경과의 호환성: 서버에선 `BrowserRouter`를 사용할 수 없으며, 대신 `StaticRouter` 사용.
* 반드시 서버 설정을 해야 함: SEO 목적이 아니더라도 기본 경로에 대한 fallback이 필요.
* SSG 빌드 시 `BrowserRouter` 경로 별 HTML 생성이 불가능.

---

## ✅ 결론

* `BrowserRouter`는 **SEO를 고려한 SPA 라우팅**에 적합하며, 깔끔한 URL과 히스토리 관리 기능을 제공합니다.
* 하지만 반드시 **서버 리디렉션 설정**과 **SPA 구성 이해**가 전제되어야 하며, **SSR/SSG 환경**에서는 대체 라우터 컴포넌트 사용을 고려해야 합니다.
