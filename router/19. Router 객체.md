```text
Route Object[]
      ↓
createBrowserRouter()
      ↓
★ Router 객체
      ↓
<RouterProvider router={router} />
      ↓
React UI
```

여기서 **Router 객체는 Route 설정을 실제로 실행하면서 URL, Route Matching, navigation, loader/action, 에러, 라우팅 상태 등을 관리하는 핵심 실행 객체**입니다.

# 1. Router 객체란?

다음 코드를 보겠습니다.

```jsx
const router = createBrowserRouter([
  {
    path: "/",
    element: <RootLayout />,
    children: [
      {
        path: "products",
        element: <Products />,
        loader: productsLoader,
      },
    ],
  },
]);
```

여기서:

```jsx
const router = createBrowserRouter(...);
```

의 `router`가 **Router 객체**입니다.

중요한 것은 이것이 React Component가 아니라는 것입니다.

```jsx
// ❌ 잘못된 이해
<router />
```

Router 객체는 React UI가 아니라 **라우팅 시스템을 동작시키는 JavaScript 객체**입니다.

개념적으로:

```text
Route Object[]
      │
      ▼
createBrowserRouter()
      │
      ▼
┌─────────────────────────┐
│      Router 객체         │
│                         │
│ Route 설정 보관/사용      │
│ URL 상태 관리            │
│ Route Matching          │
│ Navigation 실행         │
│ loader/action 실행      │
│ Error 처리              │
│ History API 연동        │
│ Router State 관리       │
└─────────────────────────┘
```

---

# 2. Route Object와 Router 객체는 완전히 다르다

이 둘은 반드시 구분해야 합니다.

`Route Object`는 **설정(configuration)** 입니다.

```jsx
{
  path: "/products",
  element: <Products />,
  loader: productsLoader,
}
```

이 객체 자체가 navigation을 실행하는 것은 아닙니다.

반면 Router는 이 설정을 받아 실제 라우팅을 수행합니다.

```text
Route Object
"무엇을 해야 하는가?"
        ↓
     설정 정보

Router
"그 설정을 실제로 실행"
        ↓
     실행 주체
```

비유하면:

```text
Route Object = 설계도
Router       = 설계도를 보고 움직이는 시스템
```

입니다.

---

# 3. Router 객체는 누가 만드는가?

우리가 직접 만들지 않습니다.

```jsx
const router = createBrowserRouter(routes);
```

`createBrowserRouter()`가 생성합니다.

```text
Route Object[]
      ↓
createBrowserRouter(routes)
      ↓
Router 객체 생성
```

그래서 다음 코드의 의미를 정확하게 읽어야 합니다.

```jsx
const router = createBrowserRouter(routes);
```

이는:

```text
routes를 기반으로
브라우저 환경에서 동작하는
Data Router 객체를 만들어
router 변수에 저장한다.
```

는 의미입니다.

---

# 4. Router 객체의 핵심은 Router State

Router는 현재 라우팅 상황을 내부 상태로 관리합니다.

개념적으로:

```text
router
│
├─ routes
│
├─ state
│   │
│   ├─ location
│   ├─ matches
│   ├─ navigation
│   ├─ loaderData
│   ├─ actionData
│   ├─ errors
│   └─ ...
│
├─ navigate()
├─ subscribe()
├─ fetch()
└─ ...
```

여기서 특히 중요한 것이:

```jsx
router.state
```

입니다.

Router의 현재 상태를 나타냅니다.

---

# 5. state.location

현재 URL 위치입니다.

예를 들어 현재 URL이:

```text
/products/10
```

이라면 개념적으로:

```js
router.state.location
```

은 다음과 비슷한 정보를 가집니다.

```js
{
  pathname: "/products/10",
  search: "",
  hash: "",
  state: null,
  key: "..."
}
```

즉 Router는 브라우저 주소창만 바라보는 것이 아니라 **현재 location을 자신의 Router State로 관리**합니다.

```text
Browser URL
     ↕
History
     ↕
Router
     │
     └─ state.location
```

---

# 6. state.matches

현재 URL과 매칭된 Route들의 목록입니다.

예를 들어 Route가:

```jsx
{
  path: "/",
  element: <RootLayout />,
  children: [
    {
      path: "products",
      element: <Products />,
      children: [
        {
          path: ":id",
          element: <ProductDetail />,
        },
      ],
    },
  ],
}
```

이고 URL이:

```text
/products/10
```

이라면 단 하나의 Route만 매칭되는 것이 아닙니다.

개념적으로:

```text
/
↓
products
↓
:id
```

가 모두 매칭됩니다.

따라서:

```text
state.matches

[
  RootLayout Route,
  Products Route,
  ProductDetail Route
]
```

와 같은 Route Match 체인이 만들어집니다.

이것이 중첩 Route 렌더링의 기반입니다.

---

# 7. state.navigation

현재 navigation 진행 상태를 나타냅니다.

예를 들어 사용자가:

```jsx
<Link to="/products">Products</Link>
```

를 클릭합니다.

Router는 새로운 Route로 이동하는 동안 navigation 상태를 관리합니다.

대표적으로:

```text
idle
loading
submitting
```

상태가 있습니다.

일반적인 페이지 이동:

```text
idle
 ↓
loading
 ↓
idle
```

Form 제출이라면:

```text
idle
 ↓
submitting
 ↓
loading
 ↓
idle
```

처럼 진행될 수 있습니다.

React에서는 보통:

```jsx
const navigation = useNavigation();
```

으로 이 상태를 사용합니다.

예:

```jsx
function RootLayout() {
  const navigation = useNavigation();

  return (
    <>
      {navigation.state === "loading" && <Loading />}
      <Outlet />
    </>
  );
}
```

중요한 연결은:

```text
Router
└─ state.navigation
        ↓
useNavigation()
        ↓
React Component
```

입니다.

---

# 8. state.loaderData

Route의 `loader`가 반환한 데이터도 Router가 관리합니다.

```jsx
{
  path: "products",
  element: <Products />,
  loader: productsLoader,
}
```

`productsLoader`가:

```jsx
async function productsLoader() {
  const response = await fetch("/api/products");
  return response.json();
}
```

이라고 하겠습니다.

실행 흐름은:

```text
/products 이동
      ↓
Router
      ↓
Route Matching
      ↓
productsLoader()
      ↓
데이터 반환
      ↓
Router State
      ↓
loaderData
```

입니다.

컴포넌트에서는:

```jsx
const products = useLoaderData();
```

로 접근합니다.

즉 개념적으로:

```text
loader()
   ↓
Router
   ↓
state.loaderData
   ↓
useLoaderData()
   ↓
Component
```

입니다.

---

# 9. state.actionData

`action`의 결과도 Router State에 연결될 수 있습니다.

예를 들어:

```jsx
{
  path: "products/new",
  element: <NewProduct />,
  action: createProduct,
}
```

Form이 제출되면:

```text
<Form>
   ↓
Router
   ↓
action()
   ↓
action 결과
   ↓
state.actionData
```

React에서는:

```jsx
const actionData = useActionData();
```

로 사용할 수 있습니다.

---

# 10. state.errors

loader/action/render 과정에서 Route error가 발생하면 Router가 Route 단위로 에러를 관리합니다.

```jsx
{
  path: "products",
  element: <Products />,
  loader: productsLoader,
  errorElement: <ProductsError />,
}
```

예를 들어:

```text
productsLoader()
       ↓
     Error
       ↓
Router가 Error 처리
       ↓
state.errors
       ↓
적절한 errorElement 선택
       ↓
<ProductsError />
```

가 됩니다.

따라서 에러 처리 역시 Router가 관여하는 라우팅 생명주기의 일부입니다.

---

# 11. Router의 navigate()

Router는 navigation을 실행할 수 있습니다.

개념적으로:

```js
router.navigate("/products");
```

와 같은 기능을 제공합니다.

React 컴포넌트에서는 직접 Router 객체를 다루기보다 보통:

```jsx
const navigate = useNavigate();

navigate("/products");
```

를 사용합니다.

전체 관계를 보면:

```text
useNavigate()
     ↓
navigate("/products")
     ↓
Router navigation
     ↓
Route Matching
     ↓
loader 등 실행
     ↓
Router State 변경
     ↓
React UI 업데이트
```

입니다.

따라서 `navigate()`는 단순히 주소창 문자열을 바꾸는 함수라고 이해하면 부족합니다.

**Router의 navigation 프로세스를 시작시키는 기능**입니다.

---

# 12. Router의 subscribe()

Router State가 변경되면 그것을 알아야 하는 대상이 있습니다.

대표적으로 `RouterProvider`입니다.

개념적으로 Router에는 상태 변화를 구독할 수 있는 메커니즘이 있습니다.

```text
Router
  │
  │ state 변경
  ▼
subscriber에게 알림
```

이 구조 덕분에:

```text
Router State 변경
        ↓
RouterProvider가 변화 감지
        ↓
React에 새로운 Router 상태 제공
        ↓
필요한 UI 업데이트
```

가 가능합니다.

여기서 `RouterProvider`의 역할이 명확해집니다.

---

# 13. RouterProvider와 Router의 관계

코드를 보면:

```jsx
const router = createBrowserRouter(routes);

function App() {
  return <RouterProvider router={router} />;
}
```

입니다.

여기서 역할을 구분해야 합니다.

```text
createBrowserRouter()
        ↓
Router 객체 생성


Router
        ↓
라우팅 시스템 실행
상태 관리


RouterProvider
        ↓
Router와 React 연결
```

즉:

> **Router가 라우팅을 관리하고 RouterProvider가 그 Router를 React 세계와 연결합니다.**

전체적으로:

```text
┌──────────────────────────┐
│         Router           │
│                          │
│ location                 │
│ matches                  │
│ navigation               │
│ loaderData               │
│ actionData               │
│ errors                   │
└────────────┬─────────────┘
             │
             │ subscribe
             ▼
┌──────────────────────────┐
│     RouterProvider       │
│                          │
│ Router ↔ React 연결      │
└────────────┬─────────────┘
             │
             ▼
        React Tree
```

라고 볼 수 있습니다.

---

# 14. History API와 Router의 관계

`createBrowserRouter()`가 만드는 Router는 브라우저 History와 연결됩니다.

브라우저에는:

```js
history.pushState()
history.replaceState()
history.go()
```

등이 있습니다.

Router는 이 브라우저 navigation 메커니즘을 추상화하여 사용합니다.

개념적으로:

```text
React
  │
  │ navigate("/products")
  ▼
Router
  │
  ├─ Route Matching
  ├─ loader/action
  ├─ Router State 관리
  │
  ▼
History
  │
  ▼
Browser URL
```

그리고 브라우저의 뒤로가기/앞으로가기 같은 History 이동도 Router가 감지하여 적절한 Route State를 구성합니다.

---

# 15. 실제 navigation 전체 흐름

이제 가장 중요한 부분입니다.

사용자가:

```jsx
<Link to="/products">Products</Link>
```

를 클릭했다고 하겠습니다.

전체 흐름은 개념적으로:

```text
① <Link> 클릭
       ↓
② navigate("/products")
       ↓
③ Router가 navigation 시작
       ↓
④ Route Matching
       ↓
⑤ 필요한 loader 확인
       ↓
⑥ loader 실행
       ↓
⑦ 데이터 준비
       ↓
⑧ navigation 결과 commit
       ↓
⑨ Router State 갱신
   ├─ location
   ├─ matches
   ├─ navigation
   ├─ loaderData
   └─ errors
       ↓
⑩ RouterProvider가 상태 변화 감지
       ↓
⑪ React 업데이트
       ↓
⑫ 새로운 Route UI 렌더링
```

그래서 Router를 단순히:

```text
URL 변경 객체
```

라고 생각하면 안 됩니다.

오히려:

```text
                Router
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
      URL       Route      Data
              Matching
        │         │         │
        ├─────────┼─────────┤
                  ▼
            Router State
                  │
                  ▼
           RouterProvider
                  │
                  ▼
              React UI
```

에 가깝습니다.

---

# 16. Router는 일종의 상태 머신처럼 볼 수 있다

이 관점이 중요합니다.

예를 들어 현재 상태가:

```text
location = /
navigation = idle
```

인데 `/products`로 이동한다고 해보겠습니다.

```text
현재
location = /
navigation = idle

        ↓ navigate("/products")

이동 중
location = /
navigation = loading

        ↓
Route Matching
loader 실행

        ↓ commit

완료
location = /products
navigation = idle
loaderData = products
```

따라서 Router는 **navigation 과정에서 여러 상태를 전이시키는 상태 관리자**라고 볼 수 있습니다.

다만 "Router가 공식적으로 단순한 finite-state machine 객체다"라는 의미보다는 **상태 머신처럼 이해하면 내부 동작을 파악하기 좋다**는 뜻입니다.

---

# 17. Redux와 비교하면 이해하기 쉽다

Redux를 알고 있다면 상당히 재미있는 비교가 가능합니다.

```text
Redux                         React Router

Redux Store                   Router
     │                           │
state                        Router State
     │                           │
subscribe()                  subscribe()
     │                           │
React Redux Provider         RouterProvider
     │                           │
useSelector()                useLoaderData()
                             useNavigation()
                             useMatches()
                             useLocation()
```

물론 Redux Store와 Router는 목적과 구현이 서로 다릅니다.

하지만 **외부 상태 관리 객체 → Provider → React가 상태 사용**이라는 구조적 관점에서는 비슷하게 이해할 수 있습니다.

# 18. Route Object → Router → RouterProvider의 관계

지금까지 배운 세 가지를 하나로 합치면 가장 중요합니다.

```text
Route Object[]
│
│ "라우팅 규칙을 선언"
│
├─ path
├─ element
├─ children
├─ loader
├─ action
└─ errorElement
        │
        ▼
createBrowserRouter(routes)
        │
        ▼
┌─────────────────────────────┐
│          Router             │
│                             │
│ Route Matching              │
│ Navigation                  │
│ loader/action 실행          │
│ Error 처리                  │
│ History 연동                │
│                             │
│ Router State                │
│ ├─ location                 │
│ ├─ matches                  │
│ ├─ navigation               │
│ ├─ loaderData               │
│ ├─ actionData               │
│ └─ errors                   │
└──────────────┬──────────────┘
               │
               │ state 변화
               ▼
       ┌────────────────┐
       │ RouterProvider │
       │                │
       │ Router와       │
       │ React 연결     │

               │
```

# 핵심 정리

강의에서는 다음 세 문장으로 정리하면 좋습니다.

> **Route Object는 라우팅의 "설정"이다.**

> **Router 객체는 그 설정을 바탕으로 Route Matching, navigation, 데이터 로딩, 에러 처리, History 연동과 Router State를 실제로 관리하는 "실행 주체"다.**

> **RouterProvider는 그 Router 객체의 상태를 React 컴포넌트 트리와 연결한다.**

결국 전체 구조는:

```text
Route Object[]
      ↓
"설정"

createBrowserRouter()
      ↓

Router
      ↓
"실행 + 상태 관리"

RouterProvider
      ↓
"React와 연결"

React UI
      ↓
"화면 렌더링"
```

입니다.

따라서 **`createBrowserRouter()`를 제대로 이해한다는 것은 사실상 `Route Object → Router 객체 → Router State → RouterProvider → React UI`라는 연결 구조를 이해하는 것**이라고 볼 수 있습니다.
