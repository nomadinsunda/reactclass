# `<Routes>` in React Router

## URL과 Route Tree를 연결하는 매칭 엔진

React Router에서 `BrowserRouter`가 **브라우저의 URL/History와 React Router를 연결하는 역할**을 담당한다면, `<Routes>`는 그 다음 단계에서 중요한 역할을 담당합니다.

현재 URL이 다음과 같다고 생각해 보겠습니다.

```text
/users/10
```

그리고 애플리케이션에 다음 Route들이 정의되어 있습니다.

```jsx
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/about" element={<About />} />
  <Route path="/users" element={<Users />} />
  <Route path="/users/:userId" element={<UserDetail />} />
</Routes>
```

React Router는 현재 URL과 Route 설정을 비교하여:

```text
현재 URL
/users/10
    │
    ▼
<Routes>
    │
    ▼
Route Matching
    │
    ▼
/users/:userId
    │
    ▼
<UserDetail />
```

과 같은 결과를 만들어냅니다.

따라서 `<Routes>`를 한 문장으로 정의하면 다음과 같습니다.

> **`<Routes>`는 현재 location과 하위 `<Route>`로 구성된 Route Tree를 비교하여 가장 적합한 Route branch를 찾고, 해당 branch의 React element 계층을 렌더링하는 라우팅 컨테이너입니다.**

---

# 1. `<Routes>`는 어디에 위치하는가?

전체 구조에서 `<Routes>`의 위치부터 이해하는 것이 중요합니다.

```text
Browser
   │
   │ URL / History
   ▼
BrowserRouter
   │
   │ 현재 location 제공
   ▼
Routes
   │
   │ Route Matching
   ▼
Route
   │
   │ element
   ▼
React Component
```

각각의 역할을 구분하면 다음과 같습니다.

```text
BrowserRouter
      │
      │ Browser History와
      │ Router 상태 연결
      ▼
    Routes
      │
      │ 현재 location에 대해
      │ Route Matching
      ▼
     Route
      │
      │ 매칭될 UI 정의
      ▼
React Element
```

즉:

### `BrowserRouter`

> 브라우저 URL/History와 React Router를 연결합니다.

### `Routes`

> 현재 location과 Route Tree를 비교하여 적절한 Route branch를 찾습니다.

### `Route`

> 특정 URL 패턴에 어떤 UI를 연결할 것인지 정의합니다.

이 역할을 구분해서 이해하는 것이 중요합니다.

---

# 2. 기본 사용법

가장 기본적인 형태는 다음과 같습니다.

```jsx
import {
  Routes,
  Route
} from 'react-router-dom';

function App() {
  return (
    <Routes>
      <Route
        path="/"
        element={<Home />}
      />

      <Route
        path="/about"
        element={<About />}
      />

      <Route
        path="/users"
        element={<Users />}
      />
    </Routes>
  );
}
```

현재 URL에 따라 다음과 같이 매칭됩니다.

```text
URL             Route                 React Element

/          →    path="/"         →    <Home />

/about     →    path="/about"    →    <About />

/users     →    path="/users"    →    <Users />
```

따라서 `<Routes>`는 단순히 여러 `<Route>`를 담는 박스가 아닙니다.

현재 URL을 기준으로 Route 설정을 평가하고 **렌더링할 Route branch를 결정하는 역할**을 합니다.

---

# 3. `<Routes>`는 현재 URL을 어디에서 얻는가?

`<Routes>`가 독립적으로 브라우저 주소창을 직접 읽어서 동작한다고 이해하면 안 됩니다.

일반적으로 상위 Router가 현재 `location` 정보를 제공합니다.

```jsx
<BrowserRouter>
  <App />
</BrowserRouter>
```

그리고 `App` 내부에:

```jsx
function App() {
  return (
    <Routes>
      ...
    </Routes>
  );
}
```

가 존재합니다.

구조적으로:

```text
Browser
   │
   ▼
window.location
   │
   ▼
BrowserRouter
   │
   │ Router Context
   │ location
   ▼
Routes
   │
   ▼
Route Matching
```

이라고 이해할 수 있습니다.

예를 들어 현재 URL이:

```text
http://localhost:5173/users/10
```

이라면 현재 pathname은:

```text
/users/10
```

입니다.

이 location을 기반으로 `<Routes>`가 Route 매칭을 수행합니다.

---

# 4. Route Matching은 단순한 위에서 아래 검색이 아니다

React Router v5의 `<Switch>`를 배운 사람이라면 다음과 같이 생각하기 쉽습니다.

```text
첫 번째 Route 확인
      ↓
매칭 실패
      ↓
두 번째 Route 확인
      ↓
매칭 성공
      ↓
종료
```

하지만 React Router v6의 `<Routes>`는 단순히 JSX에 작성된 순서대로 첫 번째 매칭을 선택하는 방식으로 이해하면 안 됩니다.

예를 들어:

```jsx
<Routes>
  <Route
    path="/users/:id"
    element={<User />}
  />

  <Route
    path="/users/new"
    element={<NewUser />}
  />
</Routes>
```

현재 URL이:

```text
/users/new
```

이라고 하겠습니다.

문자열을 단순히 위에서부터 비교한다면:

```text
/users/:id
```

의 `:id`가 `new`와 매칭될 수도 있습니다.

하지만 React Router는 Route의 구체성을 고려합니다.

개념적으로:

```text
/users/:id
/users/new
      │
      ▼
Route Ranking
      │
      ▼
/users/new
더 구체적
      │
      ▼
<NewUser />
```

따라서 Route 작성 순서에 의존하여 가장 먼저 일치하는 Route를 선택하는 방식과는 다릅니다.

---

# 5. Route Branch라는 개념

중첩 Route까지 이해하려면 단순히 "Route 하나를 선택한다"고 생각하는 것보다 **Route branch를 선택한다**고 이해하는 것이 좋습니다.

다음 Route를 생각해 보겠습니다.

```jsx
<Routes>
  <Route
    path="/users"
    element={<UsersLayout />}
  >
    <Route
      index
      element={<UserList />}
    />

    <Route
      path=":userId"
      element={<UserDetail />}
    />
  </Route>
</Routes>
```

현재 URL이:

```text
/users/10
```

이라면 단순히:

```text
:userId
```

Route 하나만 매칭되는 것이 아닙니다.

개념적으로 다음 branch가 매칭됩니다.

```text
/users
   │
   └── :userId
```

즉:

```text
UsersLayout
    │
    ▼
UserDetail
```

이라는 React element 계층이 만들어집니다.

이것이 중첩 라우팅을 이해하는 핵심입니다.

---

# 6. 중첩 라우팅

React Router의 강력한 기능 중 하나가 Nested Routes입니다.

예를 들어 URL 구조가:

```text
/dashboard
/dashboard/profile
/dashboard/settings
```

라면 Route Tree를 다음과 같이 만들 수 있습니다.

```jsx
<Routes>
  <Route
    path="/dashboard"
    element={<Dashboard />}
  >
    <Route
      index
      element={<DashboardHome />}
    />

    <Route
      path="profile"
      element={<Profile />}
    />

    <Route
      path="settings"
      element={<Settings />}
    />
  </Route>
</Routes>
```

Route Tree로 표현하면:

```text
/dashboard
│
├── index
│    └── DashboardHome
│
├── profile
│    └── Profile
│
└── settings
     └── Settings
```

현재 URL이:

```text
/dashboard/profile
```

이라면 매칭되는 branch는:

```text
/dashboard
    │
    └── profile
```

입니다.

따라서 렌더링 구조는:

```text
<Dashboard />
     │
     └── <Profile />
```

이 되어야 합니다.

여기에서 중요한 역할을 하는 것이 `<Outlet />`입니다.

---

# 7. `<Outlet />`의 역할

부모 Route의 element는 자식 Route가 렌더링될 위치를 지정해야 합니다.

```jsx
import { Outlet } from 'react-router-dom';

function Dashboard() {
  return (
    <div>
      <h1>Dashboard</h1>

      <nav>
        ...
      </nav>

      <Outlet />
    </div>
  );
}
```

현재 URL이:

```text
/dashboard/profile
```

이라면 개념적으로:

```text
Dashboard
│
├── <h1>Dashboard</h1>
├── <nav>...</nav>
│
└── <Outlet />
       │
       ▼
   <Profile />
```

이 됩니다.

따라서 `<Outlet />`은:

> **매칭된 자식 Route의 element가 렌더링되는 자리**

라고 이해하면 됩니다.

---

# 8. Index Route

부모 Route 자체의 URL에 접근했을 때 기본적으로 보여줄 자식 Route를 지정할 수 있습니다.

```jsx
<Route
  path="/dashboard"
  element={<Dashboard />}
>
  <Route
    index
    element={<DashboardHome />}
  />

  <Route
    path="profile"
    element={<Profile />}
  />
</Route>
```

현재 URL이:

```text
/dashboard
```

이면:

```text
/dashboard
    │
    └── index
          │
          ▼
   DashboardHome
```

이 매칭됩니다.

따라서:

```jsx
<Route index element={<DashboardHome />} />
```

는 부모 Route의 **기본 자식 Route**라고 이해할 수 있습니다.

---

# 9. 동적 Route

URL의 일부를 동적인 값으로 만들 수 있습니다.

```jsx
<Route
  path="/users/:userId"
  element={<UserDetail />}
/>
```

다음 URL들은 모두 같은 Route 패턴과 매칭될 수 있습니다.

```text
/users/10
/users/20
/users/100
```

매칭 구조는:

```text
/users/10
      │
      ▼
/users/:userId
      │
      ▼
userId = "10"
```

입니다.

컴포넌트에서는 `useParams()`를 사용할 수 있습니다.

```jsx
import { useParams } from 'react-router-dom';

function UserDetail() {
  const { userId } = useParams();

  return (
    <h1>User ID: {userId}</h1>
  );
}
```

---

# 10. `element`에는 무엇을 전달하는가?

React Router v6에서 중요한 변화 중 하나입니다.

다음처럼 작성합니다.

```jsx
<Route
  path="/about"
  element={<About />}
/>
```

여기서:

```jsx
<About />
```

은 **React element**입니다.

다음과 혼동하면 안 됩니다.

```jsx
element={About}     // X
```

일반적인 선언형 Route에서는:

```jsx
element={<About />} // O
```

형태로 작성합니다.

React Router v5에서는 다음과 같은 API를 사용했습니다.

```jsx
<Route
  path="/about"
  component={About}
/>
```

v6에서는 선언형 Route에서 주로:

```jsx
<Route
  path="/about"
  element={<About />}
/>
```

형태를 사용합니다.

따라서 `element`를 **컴포넌트 인스턴스**라고 부르는 것보다는 **React element 또는 JSX element**라고 설명하는 것이 정확합니다.

---

# 11. Catch-all Route

어떤 Route와도 매칭되지 않는 URL을 처리할 수 있습니다.

```jsx
<Route
  path="*"
  element={<NotFound />}
/>
```

예를 들어:

```text
/about
   ↓
<About />

/users/10
   ↓
<UserDetail />

/abcdef
   ↓
*
   ↓
<NotFound />
```

와 같이 사용할 수 있습니다.

보통 404 화면을 구현할 때 사용합니다.

---

# 12. Pathless Route

`path` 없이 Route를 만들 수도 있습니다.

```jsx
<Route element={<AuthLayout />}>
  <Route
    path="/admin"
    element={<AdminDashboard />}
  />

  <Route
    path="/mypage"
    element={<MyPage />}
  />
</Route>
```

이 경우 부모 Route는 URL segment를 추가하기 위한 것이 아니라 **공통 UI 또는 공통 라우팅 구조를 제공하기 위한 Route**로 사용할 수 있습니다.

예를 들어:

```text
AuthLayout
│
├── /admin
│     └── AdminDashboard
│
└── /mypage
      └── MyPage
```

와 같은 구조를 만들 수 있습니다.

`AuthLayout` 내부에는 일반적으로:

```jsx
function AuthLayout() {
  return (
    <>
      <AuthHeader />
      <Outlet />
    </>
  );
}
```

처럼 `<Outlet />`을 사용합니다.

---

# 13. `<Routes>`와 `useRoutes()`

React Router는 JSX 기반 선언 방식뿐만 아니라 JavaScript 객체 기반 Route 설정도 지원합니다.

JSX 방식:

```jsx
<Routes>
  <Route
    path="/"
    element={<Home />}
  />

  <Route
    path="/about"
    element={<About />}
  />
</Routes>
```

객체 기반 방식:

```jsx
const element = useRoutes([
  {
    path: '/',
    element: <Home />
  },
  {
    path: '/about',
    element: <About />
  }
]);
```

개념적으로 두 방식 모두:

```text
Route Configuration
       │
       ▼
현재 Location
       │
       ▼
Route Matching
       │
       ▼
Matched Route Branch
       │
       ▼
React Elements
```

이라는 동일한 핵심 라우팅 개념을 사용합니다.

다만 하나는 **JSX 기반 선언 방식**, 다른 하나는 **JavaScript 객체 기반 방식**이라는 차이가 있습니다.

# 14. 전체 동작 흐름

이제 `<Routes>`의 동작을 전체적으로 연결해 보겠습니다.

현재 URL이:

```text
/users/10
```

이라고 하겠습니다.

Route 설정:

```jsx
<Routes>
  <Route
    path="/"
    element={<Layout />}
  >
    <Route
      index
      element={<Home />}
    />

    <Route
      path="about"
      element={<About />}
    />

    <Route
      path="users"
      element={<Users />}
    />

    <Route
      path="users/:userId"
      element={<UserDetail />}
    />

    <Route
      path="*"
      element={<NotFound />}
    />
  </Route>
</Routes>
```

전체 흐름은 다음과 같습니다.

```text
Browser
   │
   ▼
URL
/users/10
   │
   ▼
BrowserRouter
   │
   │ location 제공
   ▼
Routes
   │
   ▼
Route Tree 분석
   │
   ▼
Route Branch Ranking
   │
   ▼
가장 적합한 Branch 선택
   │
   ▼
/
└── users/:userId
   │
   ▼
React Element 계층 생성
   │
   ▼
<Layout />
    │
    └── <Outlet />
           │
           ▼
      <UserDetail />
   │
   ▼
React Rendering
   │
   ▼
화면
```

이 흐름이 `<Routes>`를 이해하는 데 가장 중요합니다.

# 15. `<Switch>`와 `<Routes>`의 차이

React Router v5에서는 `<Switch>`가 사용되었습니다.

개념적으로 v5에서는 Route의 작성 순서가 중요했습니다.

```jsx
<Switch>
  <Route path="/users/new" ... />
  <Route path="/users/:id" ... />
</Switch>
```

`<Switch>`는 위에서 아래로 Route를 검사하면서 처음 매칭되는 Route를 선택하는 방식이었습니다.

React Router v6의 `<Routes>`에서는 Route ranking을 사용하기 때문에 **Route 정의 순서에 대한 의존성이 크게 줄었습니다.**

따라서 다음과 같이 이해하는 것이 좋습니다.

| React Router v5 | React Router v6+    |
| --------------- | ------------------- |
| `<Switch>`      | `<Routes>`          |
| 작성 순서 중요        | Route ranking 사용    |
| 첫 번째 매칭 중심      | 가장 적합한 branch 선택    |
| `component` 사용  | `element` 사용        |
| 중첩 구성이 상대적으로 불편 | Nested Routes 중심 설계 |

---

# 16. `<Routes>` 내부 동작을 수도 코드로 이해하기

실제 React Router 내부 구현은 훨씬 복잡하지만 학습 목적으로 단순화하면 다음처럼 생각할 수 있습니다.

```jsx
function Routes({ children }) {
  // 1. 현재 location 가져오기
  const location = useLocation();

  // 2. <Route> 구조를 Route 설정으로 변환
  const routes = createRoutesFromChildren(children);

  // 3. 현재 location과 Route Tree 매칭
  const matches = matchRoutes(
    routes,
    location
  );

  // 4. 매칭된 Route branch 렌더링
  return renderMatches(matches);
}
```

이 코드는 실제 구현을 그대로 재현한 코드가 아니라 **개념을 설명하기 위한 수도 코드**입니다.

핵심은 다음 네 단계입니다.

```text
location 획득
      ↓
Route Tree 구성
      ↓
Route Matching
      ↓
Matched Branch Rendering
```

---

# 17. 역할을 정확히 구분하기

React Router를 배울 때 다음 세 컴포넌트의 역할이 자주 혼동됩니다.

```text
BrowserRouter
      │
      ▼
    Routes
      │
      ▼
     Route
```

각각의 핵심 책임은 다음과 같습니다.

| 구성 요소           | 핵심 역할                            |
| --------------- | -------------------------------- |
| `BrowserRouter` | 브라우저 History와 React Router 상태 연결 |
| `Routes`        | 현재 location과 Route Tree를 매칭      |
| `Route`         | URL 패턴과 UI의 관계 정의                |
| `Outlet`        | 매칭된 자식 Route element의 렌더링 위치 제공  |

한 문장씩 압축하면:

```text
BrowserRouter
"현재 URL이 무엇인지 Router 세계에 알려준다."

Routes
"현재 URL에 맞는 Route branch를 찾는다."

Route
"이 URL 패턴에는 이 UI를 사용한다고 정의한다."

Outlet
"매칭된 자식 UI가 들어갈 위치를 제공한다."
```

# 최종 정의

`<Routes>`를 가장 정확하게 한 문장으로 정리하면 다음과 같습니다.

> **`<Routes>`는 Router가 제공하는 현재 location과 하위 `<Route>`로 구성된 Route Tree를 비교하여 가장 적합한 Route branch를 선택하고, 해당 branch에 대응하는 React element 계층을 렌더링하는 React Router의 선언형 Route Matching 컨테이너입니다.**

더 짧게 표현하면:

> **`<Routes>` = 현재 URL → Route Tree Matching → React UI**

그리고 `BrowserRouter`까지 연결하면 전체 흐름은 다음과 같습니다.

```text
Browser URL / History
        ↓
BrowserRouter
        ↓
location
        ↓
Routes
        ↓
Route Tree Matching
        ↓
Matched Route Branch
        ↓
Route elements
        ↓
Outlet을 통한 중첩
        ↓
React UI
```

이 구조를 이해하면 `Route`, `Outlet`, `index`, Dynamic Segment, `useParams()`, Nested Routes가 각각 독립적인 기능이 아니라 **하나의 Route Tree Matching 시스템을 구성하는 요소들**이라는 사실을 자연스럽게 이해할 수 있습니다.
