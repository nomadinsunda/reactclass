`<li>` 태그의 **key 속성**은 React에서 리스트 렌더링할 때 **각 요소를 식별하기 위한 고유한 ID 역할**을 합니다.
HTML의 원래 `<li>` 속성이 아니라, **React가 리스트를 관리할 때만 사용하는 특별한 속성**입니다.

---

# 🔑 1. key 속성이란?

React가 리스트를 렌더링할 때 **각 요소를 고유하게 식별하는 값**입니다.

```jsx
<li key={user.id}>{user.name}</li>
```

📌 key는 **React 내부의 가상 DOM diff 알고리즘**이
"무엇이 변경되었는가?"를 판단할 때 기준이 됩니다.

---

# 🤖 2. 왜 key가 필요한가?

React는 리스트가 변경되면 전체를 다시 그리지 않고
**변한 부분만 업데이트하려고** 합니다.

예를 들어:

```jsx
<ul>
  <li>홍길동</li>
  <li>이순신</li>
  <li>강감찬</li>
</ul>
```

중간에 새로운 요소가 삽입된다면?

React는 “어디에 새로운 요소가 들어갔는지” 알아야 합니다.

👉 **key가 없으면 React는 요소 구분을 못하고 비효율적인 업데이트를 하게 됨**

---

# 🔥 3. key가 없을 때 발생하는 문제

### ❌ React는 리스트의 순서로 요소를 판단함

예) key 없이:

```jsx
<li>{users[0]}</li>
<li>{users[1]}</li>
<li>{users[2]}</li>
```

중간에 새로운 요소가 들어가면:

* 기존 index 1 → index 2로 밀림
* React는 “아, 이건 새로운 컴포넌트인가?”라고 오해
* 내부 state가 꼬일 수도 있음

➡️ 특히 입력 폼, 내부 state가 있는 컴포넌트 목록에서 **치명적 버그** 발생 가능

---

# ⭐ 4. key는 무엇을 써야 하나?

### ✔ 가장 좋은 key: **데이터의 고유 ID**

예:

```jsx
{users.map(user => (
  <li key={user.id}>{user.name}</li>
))}
```

### ✔ 두 번째 선택: **고유한 값**

예:

```jsx
<li key={email}>{email}</li>
```

### ❌ 절대 금지: index 사용

```jsx
<li key={index}></li>
```

→ 요소 순서가 바뀌면 React가 제대로 구분 못해서 버그 발생

---

# 🚀 5. key는 HTML로 내려가지 않는다

중요한 사실!
**key는 DOM 속성이 아니라, 오직 React 내부 전용 속성입니다.**

즉 실제 HTML에는 key가 존재하지 않습니다.

브라우저에 이렇게는 안 나옵니다:

```html
<li key="1">홍길동</li>  <!-- ❌ 실존하지 않음 -->
```

React만 key를 사용하고 렌더링될 때는 버려집니다.

---

# 📘 6. 가장 React다운 리스트 예시

```jsx
function UserList({ users }) {
  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```
