

# 🧠 `React.createContext`로 다중 Context 관리

---

## ✅ 1. 왜 "다중 Context"가 필요한가?

### ❌ 단일 Context 문제

```tsx
const AppContext = createContext({
  user: null,
  theme: 'light',
  language: 'ko',
});
```

> 하나의 Context에 여러 상태를 묶으면…

* 한 값만 바뀌어도 **모든 구독 컴포넌트가 리렌더링**
* 값의 변화 추적이 어려워지고, 성능 저하 발생

---

## ✅ 2. 해결: Context를 역할별로 **분리**

### 🎯 각각 독립적인 Context 생성

```tsx
// contexts/UserContext.js
export const UserContext = createContext(null);

// contexts/ThemeContext.js
export const ThemeContext = createContext('light');

// contexts/LanguageContext.js
export const LanguageContext = createContext('ko');
```

---

## ✅ 3. Provider 중첩으로 공급하기

```tsx
import { UserContext } from './contexts/UserContext';
import { ThemeContext } from './contexts/ThemeContext';
import { LanguageContext } from './contexts/LanguageContext';

export default function App() {
  return (
    <UserContext.Provider value={{ name: '홍길동' }}>
      <ThemeContext.Provider value="dark">
        <LanguageContext.Provider value="en">
          <MainApp />
        </LanguageContext.Provider>
      </ThemeContext.Provider>
    </UserContext.Provider>
  );
}
```

✅ 각 Context는 **독립적으로 관리되고 리렌더링 범위도 좁음**

---

## ✅ 4. `useContext`로 필요한 것만 꺼내기

```tsx
const user = useContext(UserContext);
const theme = useContext(ThemeContext);
```

> 필요한 Context만 구독하면 리렌더링도 **그 컴포넌트만 발생**

---

## 🧠 고급 패턴: `ContextProvider` 컴포넌트로 감싸기

> 여러 개의 Provider를 하나의 컴포넌트로 추상화하면 코드가 깔끔해집니다.

```tsx
// AppProviders.jsx
import { UserContext } from './contexts/UserContext';
import { ThemeContext } from './contexts/ThemeContext';
import { LanguageContext } from './contexts/LanguageContext';

export default function AppProviders({ children }) {
  return (
    <UserContext.Provider value={{ name: '홍길동' }}>
      <ThemeContext.Provider value="dark">
        <LanguageContext.Provider value="ko">
          {children}
        </LanguageContext.Provider>
      </ThemeContext.Provider>
    </UserContext.Provider>
  );
}
```

```tsx
// main.jsx
<AppProviders>
  <App />
</AppProviders>
```

---

## ⚠️ 주의: 리렌더링과 성능 최적화

* 각 Context는 **독립적인 값**을 가져야 함
* `value`에 함수/객체를 넣는 경우는 반드시 `useMemo`나 `useCallback`으로 **참조 고정**

```tsx
const user = useMemo(() => ({ name: '홍길동' }), []);
<UserContext.Provider value={user} />
```

---

## ✨ 실전 적용 예시

| Context 이름          | 역할          | 값 예시                   |
| ------------------- | ----------- | ---------------------- |
| `UserContext`       | 로그인 유저 정보   | `{ id, name, email }`  |
| `ThemeContext`      | 테마 (다크/라이트) | `'light'` 또는 `'dark'`  |
| `LocaleContext`     | 언어 설정       | `'en'`, `'ko'`, `'ja'` |
| `PermissionContext` | 권한 설정       | `{ isAdmin: true }`    |

## ✅ 마무리 요약

| 항목            | 설명                                              |
| ------------- | ----------------------------------------------- |
| 다중 Context 목적 | 역할별 상태를 나누고, 불필요한 리렌더를 줄이기 위함                   |
| 구성 방법         | `createContext`로 각 역할별 Context 생성               |
| Provider 관리   | 중첩된 Provider는 `AppProviders`로 추상화               |
| 최적화 팁         | `value`에 객체/함수 넣을 땐 `useMemo`, `useCallback` 사용 |
