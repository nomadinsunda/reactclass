# 🔥 HMR (Hot Module Replacement)이란?

> **HMR은 코드 변경 시 전체 페이지를 새로고침하지 않고, 변경된 모듈만 실시간으로 교체(대체)하는 기술입니다.**

| 항목    | 설명                              |
| ----- | ------------------------------- |
| 목적    | 빠른 피드백 루프, 상태 유지, UI 반응성 향상     |
| 적용 대상 | JS 모듈, CSS, React 컴포넌트, 스타일 등   |
| 비교    | HMR vs Live Reloading (전체 새로고침) |

---

## 🎯 왜 필요한가?

### ❌ 기존 방식: 전체 새로고침 (Full Reload)

* 모든 JS 번들 다시 다운로드
* 앱 상태(state), 포커스, 스크롤 모두 초기화
* UX & 개발자 경험 저하

### ✅ HMR: 모듈 단위 대체

* 변경된 모듈만 네트워크로 요청
* 나머지 앱 상태 보존
* 반응 속도 매우 빠름

---

# 🛠️ HMR 작동 방식 (기술 흐름)

```text
[1] 코드 변경 발생 (.jsx, .css 등)
 ↓
[2] Vite/Webpack dev 서버가 변경 감지
 ↓
[3] 변경된 모듈만 새로 번들링
 ↓
[4] 브라우저의 WebSocket 연결을 통해 "변경 통지"
 ↓
[5] 클라이언트 측 HMR 런타임이 해당 모듈만 "핫 교체"
 ↓
[6] 기존 앱 상태 유지하면서 UI 반영
```

---

## ⚡ Vite의 HMR 특징

| 항목      | 설명                                    |
| ------- | ------------------------------------- |
| 기술 기반   | ESM 기반, No bundle                     |
| 속도      | 매우 빠름 (ms 단위 적용)                      |
| 적용 대상   | JS, TS, CSS, SASS, JSON, React 컴포넌트 등 |
| 내부 프로토콜 | WebSocket + ESM dynamic import        |

📌 Vite는 **전체 재빌드가 없이** ESM 모듈만 교체하여 **즉시 반영**합니다.

---

## 🔁 Webpack의 HMR과 비교

| 항목                 | Vite       | Webpack                    |
| ------------------ | ---------- | -------------------------- |
| 기반                 | ESM 직접 서빙  | 내부 번들 시스템                  |
| 속도                 | 빠름 (즉시 적용) | 느림 (재번들 → 다시 주입)           |
| 설정                 | 기본 자동      | 수동 설정 필요 많음 (HMR 플러그인 등)   |
| React Fast Refresh | 지원         | 지원 (react-refresh 플러그인 필요) |

---

## 👀 Vite에서 HMR 예시

1. `npm run dev` 실행 중
2. `src/pages/Home.jsx` 파일 수정
3. 브라우저의 **WebSocket 연결을 통해 변경 알림 수신**
4. 수정된 `Home.jsx`만 다시 가져와서 교체
5. **앱 상태는 그대로**, UI만 반영됨

---

## ⚠️ HMR이 작동하지 않는 경우

| 원인                 | 설명                                |
| ------------------ | --------------------------------- |
| module boundary 깨짐 | 모듈 경계에서 상태가 재생성됨 (예: hook 밖 변수 등) |
| 외부 상태 관리 오류        | Redux 등 외부 상태에 따라 잘못된 교체 발생 가능    |
| 클라이언트 라이브러리 미지원    | 일부 3rd-party 모듈은 HMR을 지원하지 않음     |

---

## 🧪 실전 팁

### ✅ React에서 Fast Refresh와 HMR 차이

| 항목         | HMR             | Fast Refresh               |
| ---------- | --------------- | -------------------------- |
| 변경 범위      | 모듈 단위           | 함수 단위                      |
| 상태 유지      | X (컴포넌트 전체 재생성) | ✅ 유지 (useState, useRef 보존) |
| React에서 권장 | ❌               | ✅ (기본값 in Vite)            |

→ Vite의 `@vitejs/plugin-react`는 React Fast Refresh를 **기본 내장**합니다.

---

## 🧾 요약

| 항목      | 요약                           |
| ------- | ---------------------------- |
| 정의      | 모듈 단위로 실시간 교체하는 개발 편의 기능     |
| 목적      | 빠른 피드백, 상태 유지, 전체 새로고침 방지    |
| Vite 기반 | ESM 기반, 매우 빠르고 간결            |
| 작동 방식   | WebSocket + 모듈 단위 핫 스왑       |
| React   | Fast Refresh를 통해 컴포넌트 상태도 유지 |

---

필요하시면 HMR 작동 시 네트워크 흐름, WebSocket 메시지 예제, Fast Refresh 동작 방식도 시각적으로 정리해 드릴 수 있습니다.
