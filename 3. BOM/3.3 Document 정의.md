# DOM(Document Object Model)

DOM을 단순히 **"HTML을 트리 구조로 표현한 것"**이라고 설명하면 절반만 설명한 것입니다.

DOM의 핵심은 다음 문장에 있습니다.

> **DOM은 브라우저가 HTML/XML 문서를 프로그램에서 접근하고 변경할 수 있도록 메모리에 표현한 객체 기반 문서 모델이며, 동시에 그 객체들을 조작하기 위한 표준 API를 정의한다.**

즉 DOM에는 두 가지 의미가 함께 들어 있습니다.

1. 문서를 `Document`, `Element`, `Text` 같은 **객체(Node)들의 구조로 표현하는 모델**
2. 그 객체를 탐색하고 생성하고 변경하고 삭제하고 이벤트를 처리할 수 있는 **API**

---

# 1. DOM은 왜 필요한가?

다음 HTML을 생각해 봅시다.

```html
<!DOCTYPE html>
<html>
<head>
  <title>DOM Example</title>
</head>
<body>
  <h1 id="title">Hello</h1>
  <button>Change</button>
</body>
</html>
```

HTML은 기본적으로 **문자열로 작성된 마크업 문서**입니다.

파일이나 HTTP 응답으로 전달될 때 브라우저가 받는 것은 결국 HTML 텍스트입니다.

```text
"<!DOCTYPE html><html><head>..."
```

그런데 JavaScript가 단순 문자열만 가지고 있다면 다음과 같은 작업은 매우 어렵습니다.

```text
id가 title인 요소를 찾아라.
그 요소의 텍스트를 변경하라.
새로운 <div>를 만들어라.
button이 클릭되면 함수를 실행하라.
특정 요소를 삭제하라.
```

따라서 브라우저는 HTML 문자열을 분석하여 프로그램이 다루기 쉬운 **구조화된 객체들의 집합**으로 변환합니다.

그 결과가 DOM입니다.

---

# 2. HTML과 DOM은 같은 것이 아니다

이 차이는 DOM을 이해할 때 가장 중요합니다.

```text
HTML
↓
브라우저 HTML Parser
↓
DOM
```

HTML은 **문서의 소스(Source)**이고,

DOM은 브라우저가 그 문서를 해석하여 만든 **메모리상의 객체 모델(Object Model)**입니다.

예를 들어,

```html
<body>
  <h1>Hello</h1>
</body>
```

브라우저는 이것을 개념적으로 다음과 같은 객체 관계로 표현합니다.

```text
Document
   │
   └── html
        │
        ├── head
        │
        └── body
             │
             └── h1
                  │
                  └── "Hello"
```

여기에서 중요한 것은 `<h1>`이라는 문자열이 그대로 존재하는 것이 아니라는 점입니다.

브라우저 내부에서는 `<h1>`에 대응하는 **Element 객체**, `"Hello"`에 대응하는 **Text 객체**가 존재합니다.

---

# 3. DOM에서 D가 Document인 진짜 이유

DOM은

```text
Document Object Model
```

의 약자입니다.

각 단어를 정확하게 해석하면 DOM의 의미가 훨씬 명확해집니다.

## Document

DOM이 모델링하는 대상입니다.

HTML이나 XML과 같은 **구조화된 문서 전체**를 의미합니다.

## Object

문서를 단순 문자열이 아니라 프로그램에서 접근 가능한 **객체들**로 표현한다는 의미입니다.

예를 들어 JavaScript에서는:

```js
const h1 = document.querySelector("h1");

console.log(typeof h1); // "object"
```

`h1`은 HTML 문자열이 아니라 브라우저가 제공하는 객체입니다.

## Model

실제 문서를 프로그램에서 다룰 수 있도록 일정한 규칙과 관계를 가진 구조로 **추상화하여 표현한다**는 의미입니다.

따라서 DOM을 자연스럽게 풀면 다음과 같습니다.

> **문서(Document)를 객체(Object)들의 구조로 표현한 모델(Model)**

그리고 그 모델을 프로그램에서 조작할 수 있도록 API까지 정의합니다.

---

# 4. DOM의 핵심은 "Tree"보다 "Node"이다

DOM을 처음 배우면 흔히 다음 그림부터 접합니다.

```text
Document
   ↓
 html
 ├─ head
 └─ body
     ├─ h1
     └─ p
```

그래서 DOM을 단순히 **트리 구조**라고 생각하기 쉽습니다.

하지만 더 중요한 개념은 **Node**입니다.

DOM에서는 문서를 구성하는 객체를 기본적으로 **Node**라는 추상적인 개념으로 다룹니다.

대표적인 Node 종류는 다음과 같습니다.

| Node 종류            | 예                           |
| ------------------ | --------------------------- |
| `Document`         | 문서 전체                       |
| `DocumentType`     | `<!DOCTYPE html>`           |
| `Element`          | `<html>`, `<body>`, `<div>` |
| `Text`             | 요소 내부의 텍스트                  |
| `Comment`          | `<!-- comment -->`          |
| `DocumentFragment` | 문서에 연결되지 않은 부분 트리           |

따라서 DOM Tree란 정확히 말하면

> **Node 객체들이 부모-자식 관계로 연결되어 만들어진 문서 구조**

입니다.

---

# 5. DOM Tree는 어떻게 만들어지는가?

브라우저가 HTML을 받으면 HTML Parser가 HTML을 순차적으로 분석합니다.

```text
HTML Bytes
    ↓
문자 디코딩
    ↓
HTML Characters
    ↓
Tokenization
    ↓
Tokens
    ↓
Tree Construction
    ↓
DOM Tree
```

예를 들어:

```html
<body>
  <h1>Hello</h1>
</body>
```

HTML Parser는 개념적으로 다음과 같은 토큰들을 처리합니다.

```text
<body>
<h1>
Hello
</h1>
</body>
```

그리고 Tree Construction 과정을 통해 적절한 DOM Node 객체를 생성하고 서로 연결합니다.

```text
Document
   │
   └── HTMLHtmlElement
          │
          └── HTMLBodyElement
                 │
                 └── HTMLHeadingElement
                         │
                         └── Text("Hello")
```

즉 DOM은 HTML 파일 자체가 아니라 **HTML 파싱 결과로 만들어진 객체 구조**입니다.

---

# 6. `document`는 무엇인가?

브라우저에서 다음 코드를 사용할 수 있습니다.

```js
console.log(document);
```

여기서 `document`는 현재 브라우징 컨텍스트에 로드된 **문서 전체를 나타내는 DOM 객체**입니다.

중요한 구분이 있습니다.

```text
Document
```

는 Web API에서 정의된 **인터페이스/생성자**이고,

```text
document
```

는 현재 페이지의 실제 **Document 객체**를 가리키는 전역 접근점입니다.

```js
document instanceof Document
// true
```

---

# 7. `document`와 `<html>`은 같은 것이 아니다

이 부분은 초보자가 매우 자주 혼동합니다.

```text
document
    │
    ├── <!DOCTYPE html>
    │
    └── <html>
          ├── <head>
          └── <body>
```

`document`는 `<html>` 요소가 아닙니다.

문서 전체를 나타내는 `Document` 객체입니다.

반면:

```js
document.documentElement
```

은 HTML 문서의 `<html>` 요소를 반환합니다.

```js
console.log(document.documentElement);
```

따라서:

```text
document
      ↓
Document 객체

document.documentElement
      ↓
<html> Element 객체
```

입니다.

---

# 8. `window`와 `document`의 관계

브라우저 JavaScript에서는 다음 구조를 이해해야 합니다.

```text
Window
  │
  ├── document ──────→ Document
  │                       │
  │                       └── DOM Tree
  │
  ├── location
  ├── history
  ├── navigator
  ├── localStorage
  ├── setTimeout()
  └── ...
```

`window`는 브라우저 탭의 전역 환경과 연결된 최상위 객체이고,

`document`는 그 Window에 현재 로드되어 있는 문서를 나타냅니다.

```js
window.document === document
// true
```

따라서:

```text
window
```

와

```text
document
```

는 같은 객체가 아닙니다.

`window`는 브라우저 환경 전체에 대한 인터페이스이고,

`document`는 그 안에 로드된 **문서에 대한 DOM 진입점**입니다.

---

# 9. DOM 객체의 핵심 상속 구조

DOM API가 강력한 이유를 이해하려면 인터페이스 관계를 알아야 합니다.

대표적으로:

```text
EventTarget
    ↑
   Node
    ↑
 Element
    ↑
HTMLElement
    ↑
HTMLDivElement
```

예를 들어:

```html
<div id="box">Hello</div>
```

를 선택하면:

```js
const box = document.querySelector("#box");
```

`box`는 일반적인 JavaScript 객체 하나처럼 보이지만 여러 DOM 인터페이스의 기능을 가지고 있습니다.

```js
box instanceof HTMLDivElement // true
box instanceof HTMLElement    // true
box instanceof Element        // true
box instanceof Node           // true
box instanceof EventTarget    // true
```

따라서 `<div>` 객체는 다음 능력을 모두 가집니다.

### Node로부터

트리 구조 관련 기능:

```js
box.parentNode
box.childNodes
box.appendChild(...)
box.removeChild(...)
```

### Element로부터

Element 관련 기능:

```js
box.id
box.classList
box.getAttribute(...)
box.querySelector(...)
```

### HTMLElement로부터

HTML 요소 공통 기능:

```js
box.hidden
box.title
box.dataset
box.style
```

### EventTarget으로부터

이벤트 기능:

```js
box.addEventListener(...)
box.removeEventListener(...)
box.dispatchEvent(...)
```

즉 DOM API는 단순 메서드 모음이 아니라 **인터페이스 계층 구조를 기반으로 설계된 객체 모델**입니다.

---

# 10. `Node`와 `Element`는 다르다

DOM을 제대로 이해하려면 반드시 구분해야 합니다.

모든 Element는 Node이지만 모든 Node가 Element는 아닙니다.

```text
Node
├── Document
├── DocumentType
├── Element
│     └── HTMLElement
│           ├── HTMLDivElement
│           ├── HTMLInputElement
│           └── HTMLButtonElement
├── Text
├── Comment
└── DocumentFragment
```

예를 들어:

```html
<p>Hello</p>
```

에는 최소한 다음 객체들이 존재합니다.

```text
HTMLParagraphElement
        │
        └── Text("Hello")
```

`<p>`는 Element Node이고 `"Hello"`는 Text Node입니다.

그래서 다음 두 프로퍼티는 결과가 다를 수 있습니다.

```js
element.children
element.childNodes
```

`children`은 **Element만** 대상으로 하지만,

`childNodes`는 Text, Comment 등을 포함한 **모든 Node**를 대상으로 합니다.

---

# 11. DOM 탐색

DOM 객체들은 서로 연결되어 있기 때문에 문서를 이동하며 탐색할 수 있습니다.

```html
<body>
  <main>
    <h1>Hello</h1>
    <p>DOM Example</p>
  </main>
</body>
```

대표적인 관계는:

```text
parent
  │
  ├── child
  ├── child
  └── child
```

입니다.

Node 기준 탐색:

```js
node.parentNode
node.childNodes
node.firstChild
node.lastChild
node.nextSibling
node.previousSibling
```

Element 기준 탐색:

```js
element.parentElement
element.children
element.firstElementChild
element.lastElementChild
element.nextElementSibling
element.previousElementSibling
```

Element 전용 API는 텍스트 노드 등을 제외하기 때문에 실제 UI 코드에서는 더 직관적인 경우가 많습니다.

# 12. `document`를 이용한 요소 검색

실제 개발에서는 트리를 직접 이동하는 것보다 선택 API를 많이 사용합니다.

```js
document.getElementById("title");
```

```js
document.querySelector(".item");
```

```js
document.querySelectorAll(".item");
```

특히:

```js
document.querySelector()
document.querySelectorAll()
```

은 CSS Selector 문법을 사용할 수 있기 때문에 매우 강력합니다.

```js
document.querySelector("#main");
document.querySelector(".user");
document.querySelector("ul > li");
document.querySelector('input[name="email"]');
```

---

# 13. `querySelector()`는 왜 `document`에 있는가?

다음 코드를 보면:

```js
document.querySelector("#title");
```

마치 `document`만 검색할 수 있는 것처럼 보입니다.

하지만 실제로는 Element에서도 가능합니다.

```js
const main = document.querySelector("main");

main.querySelector(".item");
```

차이는 **검색 범위**입니다.

```text
document.querySelector(...)
        ↓
문서 전체 검색

element.querySelector(...)
        ↓
해당 Element의 후손 범위 검색
```

DOM API가 문서 전체뿐 아니라 **부분 트리(subtree)**도 동일한 방식으로 다룰 수 있도록 설계되어 있기 때문입니다.

---

# 14. DOM Node 생성

DOM은 기존 문서를 읽기만 하는 모델이 아닙니다.

새로운 Node를 만들 수도 있습니다.

```js
const div = document.createElement("div");
```

이 시점의 `div`는 실제 DOM 객체입니다.

하지만 아직 문서 트리에 연결되어 있지 않습니다.

```text
Document
   │
   └── 기존 DOM Tree


div
↑
독립적으로 존재
```

이후:

```js
document.body.appendChild(div);
```

를 실행하면:

```text
Document
   │
   └── html
        └── body
             └── div
```

처럼 문서 트리에 연결됩니다.

즉:

```js
createElement()
```

은 **생성**이고,

```js
append()
appendChild()
prepend()
before()
after()
```

등은 **트리에 연결하는 작업**입니다.

이 둘을 구분하는 것이 중요합니다.

# 15. DOM 변경은 어떻게 화면에 반영되는가?

다음 코드를 실행한다고 가정합니다.

```js
const title = document.querySelector("#title");

title.textContent = "Hello DOM";
```

개념적인 흐름은:

```text
JavaScript
     ↓
DOM API 호출
     ↓
DOM 상태 변경
     ↓
브라우저 렌더링 시스템이 변경 감지
     ↓
필요한 스타일/레이아웃/페인트 작업
     ↓
화면 업데이트
```

입니다.

여기서 중요한 점은:

> **DOM 자체가 화면은 아니다.**

DOM은 문서의 구조와 상태를 나타내는 객체 모델입니다.

실제 화면 표시에는 DOM 외에도 CSSOM과 브라우저의 렌더링 과정이 관여합니다.

---

# 16. DOM + CSSOM + Rendering

브라우저 화면이 만들어지는 과정을 단순화하면:

```text
HTML
 ↓
DOM
   \
    \
     → Render Tree → Layout → Paint → Composite
    /
   /
CSS
 ↓
CSSOM
```

즉:

```text
DOM ≠ Render Tree
DOM ≠ 화면
```

입니다.

DOM은 **문서 구조**, CSSOM은 **스타일 규칙 구조**를 표현합니다.

브라우저는 이 정보들을 이용하여 실제 렌더링에 필요한 구조와 기하 정보를 계산합니다.

---

# 17. DOM 변경 = 항상 즉시 Reflow는 아니다

다음 설명은 피해야 합니다.

> DOM을 한 번 수정할 때마다 브라우저가 즉시 Reflow한다.

현대 브라우저는 성능을 위해 여러 변경을 모아서 처리할 수 있습니다.

```js
element.style.width = "100px";
element.style.height = "100px";
element.style.margin = "10px";
```

이 세 줄이 반드시 즉각적인 세 번의 Layout을 의미하는 것은 아닙니다.

브라우저는 변경을 기록한 뒤 적절한 렌더링 시점에 작업을 처리할 수 있습니다.

다만 변경 직후 다음과 같이 **현재 레이아웃 정보를 즉시 요구**하면:

```js
element.style.width = "100px";

console.log(element.offsetWidth);
```

브라우저가 정확한 값을 제공하기 위해 미뤄두었던 스타일 계산이나 Layout을 강제로 수행해야 하는 상황이 발생할 수 있습니다.

이를 흔히 **forced synchronous layout**이라고 부릅니다.

# 18. DocumentFragment의 정확한 역할

여러 Node를 임시로 담아두려면:

```js
const fragment = document.createDocumentFragment();
```

를 사용할 수 있습니다.

```js
const fragment = document.createDocumentFragment();

for (let i = 0; i < 100; i++) {
  const li = document.createElement("li");
  li.textContent = `Item ${i}`;
  fragment.appendChild(li);
}

document.querySelector("ul").appendChild(fragment);
```

구조는:

```text
DocumentFragment
├── li
├── li
├── li
└── ...
```

입니다.

그리고 fragment를 실제 DOM에 삽입하면:

```text
DocumentFragment 자체
        X

자식 Node들
        ↓

<ul>
 ├── li
 ├── li
 ├── li
 └── ...
```

처럼 **fragment의 자식들이 이동**합니다.

따라서 삽입 후 fragment는 비게 됩니다.

중요한 점:

> `DocumentFragment`는 React의 Virtual DOM과 전혀 다른 개념입니다.

DocumentFragment는 DOM 표준에 정의된 **실제 Node 객체**입니다.

---

# 19. DOM과 Event가 연결되는 이유

DOM 객체는 단순 데이터 객체가 아닙니다.

많은 DOM 객체가 `EventTarget`을 기반으로 하기 때문에 이벤트를 받을 수 있습니다.

```js
const button = document.querySelector("button");

button.addEventListener("click", () => {
  console.log("clicked");
});
```

대표적인 인터페이스 관계는:

```text
EventTarget
     ↑
    Node
     ↑
  Element
     ↑
HTMLElement
     ↑
HTMLButtonElement
```

따라서 button 객체는 DOM 트리의 Node이면서 동시에 EventTarget입니다.

---

# 20. 이벤트 전파와 DOM Tree

DOM Tree가 중요한 또 하나의 이유가 바로 **이벤트 전파(Event Propagation)**입니다.

```html
<div id="outer">
  <button id="button">Click</button>
</div>
```

button을 클릭하면 이벤트는 DOM Tree를 기준으로 이동합니다.

```text
Window
 ↓
Document
 ↓
html
 ↓
body
 ↓
div
 ↓
button
```

### Capturing Phase

```text
Window → Document → ... → button
```

### Target Phase

```text
button
```

### Bubbling Phase

```text
button → ... → Document → Window
```

즉 DOM Tree는 단순히 HTML 구조를 표현하기 위한 것이 아니라 **이벤트가 전달되는 경로를 결정하는 중요한 기반 구조**이기도 합니다.

---

# 21. `DOMContentLoaded`는 무엇을 의미하는가?

브라우저가 HTML을 파싱하여 DOM Tree 구성을 완료하면 중요한 이벤트가 발생합니다.

```js
document.addEventListener("DOMContentLoaded", () => {
  console.log("DOM ready");
});
```

핵심 의미는:

> **초기 HTML 문서가 완전히 파싱되고, 관련 defer/module 스크립트 실행 조건까지 충족되어 DOM을 사용할 준비가 된 시점**

입니다.

이미지 같은 모든 외부 리소스가 로딩될 필요는 없습니다.

반면:

```js
window.addEventListener("load", () => {
  console.log("resources loaded");
});
```

는 이미지, iframe 등의 하위 리소스까지 로딩이 완료된 시점을 다룹니다.

---

# 22. `document.readyState`

현재 문서 로딩 상태는:

```js
document.readyState
```

로 확인할 수 있습니다.

상태는 크게:

```text
loading
   ↓
interactive
   ↓
complete
```

로 진행됩니다.

### loading

HTML 문서를 파싱 중입니다.

### interactive

HTML 파싱이 완료되어 DOM Tree가 만들어진 상태입니다.

### complete

문서와 필요한 하위 리소스 로딩이 완료된 상태입니다.

실무에서는 다음 패턴을 사용할 수 있습니다.

```js
function onReady(callback) {
  if (document.readyState === "loading") {
    document.addEventListener("DOMContentLoaded", callback);
  } else {
    callback();
  }
}
```

---

# 23. `<script type="module">`과 DOM

Vite 기반 React 프로젝트에서는 보통:

```html
<div id="root"></div>

<script type="module" src="/src/main.jsx"></script>
```

형태를 사용합니다.

모듈 스크립트는 기본적으로 HTML 파싱과 조화를 이루도록 처리되므로 일반적인 Vite 프로젝트에서:

```js
document.addEventListener("DOMContentLoaded", ...)
```

로 React 초기화를 감쌀 필요가 없습니다.

그래서 바로:

```jsx
createRoot(document.getElementById("root")).render(
  <App />
);
```

와 같이 작성할 수 있습니다.

---

# 24. DOM과 JavaScript는 같은 기술이 아니다

이것도 매우 중요한 구분입니다.

다음 기능들은 JavaScript 언어 자체가 아닙니다.

```js
document
window
querySelector()
addEventListener()
setTimeout()
fetch()
```

JavaScript 표준인 ECMAScript가 `document`를 정의하는 것이 아닙니다.

브라우저가 **Web API**를 제공하고 JavaScript가 그것을 호출하는 것입니다.

개념적으로:

```text
JavaScript / ECMAScript
        │
        │ API 호출
        ▼
Browser Web APIs
        │
        ├── DOM
        ├── Fetch
        ├── Storage
        ├── History
        ├── Geolocation
        └── ...
```

따라서:

```js
document.querySelector(...)
```

는

> JavaScript 문법을 이용하여 브라우저가 제공하는 DOM API를 호출하는 것

입니다.

---

# 25. DOM과 JavaScript 객체의 관계

DOM 객체는 JavaScript 객체처럼 사용할 수 있지만 **JavaScript 엔진이 순수하게 만든 일반 객체와는 성격이 다릅니다.**

```js
const user = {
  name: "Alice"
};
```

이것은 일반 JavaScript 객체입니다.

반면:

```js
const div = document.createElement("div");
```

의 `div`는 브라우저 DOM 구현과 연결된 객체입니다.

JavaScript 코드에서는 둘 다 객체처럼 접근하지만:

```text
일반 JS Object
      ↓
JavaScript Engine이 관리

DOM Object
      ↓
브라우저 DOM 구현과 연결된 Web API 객체
```

라는 차이가 있습니다.

이러한 객체를 흔히 **host object / platform object**라는 관점에서 설명할 수 있습니다.

---

# 26. DOM API를 기능별로 이해하기

DOM API를 무작정 외우기보다는 다음과 같이 분류하는 것이 좋습니다.

| 목적    | 대표 API                                                      |
| ----- | ----------------------------------------------------------- |
| 문서 접근 | `document`, `documentElement`, `head`, `body`               |
| 검색    | `getElementById`, `querySelector`, `querySelectorAll`       |
| 생성    | `createElement`, `createTextNode`, `createDocumentFragment` |
| 삽입    | `append`, `appendChild`, `prepend`, `before`, `after`       |
| 삭제    | `remove`, `removeChild`                                     |
| 교체    | `replaceWith`, `replaceChild`                               |
| 속성    | `getAttribute`, `setAttribute`, `removeAttribute`           |
| 클래스   | `classList`                                                 |
| 콘텐츠   | `textContent`, `innerHTML`                                  |
| 탐색    | `parentElement`, `children`, `nextElementSibling`           |
| 이벤트   | `addEventListener`, `removeEventListener`                   |
| 상태    | `readyState`, `visibilityState`, `activeElement`            |

이렇게 보면 DOM API 전체가 결국 다음 작업을 위한 것임을 알 수 있습니다.

```text
찾는다
 ↓
읽는다
 ↓
만든다
 ↓
변경한다
 ↓
연결한다
 ↓
삭제한다
 ↓
이벤트에 반응한다
```

---

# 27. `innerHTML`과 DOM Node 생성의 차이

다음 두 코드는 결과 화면만 보면 비슷합니다.

```js
container.innerHTML = "<h1>Hello</h1>";
```

그리고:

```js
const h1 = document.createElement("h1");
h1.textContent = "Hello";

container.appendChild(h1);
```

하지만 과정은 다릅니다.

### innerHTML

```text
HTML String
   ↓
HTML Parser
   ↓
DOM Node 생성
   ↓
기존 내용 교체
```

### createElement

```text
DOM API
   ↓
Element 객체 직접 생성
   ↓
DOM Tree 연결
```

따라서 DOM을 배울 때는 **HTML 문자열 조작과 DOM 객체 조작을 구분해서 이해해야 합니다.**

사용자가 입력한 문자열을 `innerHTML`에 넣는 것은 보안상 위험할 수도 있으므로 신뢰할 수 없는 데이터는 특히 주의해야 합니다.

---

# 28. DOM은 원본 HTML과 달라질 수 있다

매우 중요한 사실입니다.

처음 서버가 전달한 HTML:

```html
<h1>Hello</h1>
```

JavaScript 실행 후:

```js
document.querySelector("h1").textContent = "Goodbye";

const p = document.createElement("p");
p.textContent = "New Node";

document.body.append(p);
```

현재 DOM은 개념적으로:

```html
<h1>Goodbye</h1>
<p>New Node</p>
```

가 됩니다.

하지만 서버가 처음 전송한 HTML 파일 자체가 변경된 것은 아닙니다.

따라서:

> **DOM은 현재 브라우저 메모리에서 유지되는 문서의 살아 있는 상태이며, 원본 HTML 소스와 반드시 같지 않다.**

이 차이는 `View Source`와 개발자 도구의 `Elements` 패널이 서로 다르게 보일 수 있는 이유이기도 합니다.

---

# 29. DOM을 "살아 있는 문서 모델"이라고 부를 수 있는 이유

DOM의 진짜 힘은 HTML을 읽는 데 있지 않습니다.

JavaScript가 실행되는 동안 계속 변경할 수 있다는 데 있습니다.

```text
Initial HTML
     ↓
DOM 생성
     ↓
JavaScript 실행
     ↓
DOM 변경
     ↓
사용자 이벤트
     ↓
DOM 다시 변경
     ↓
서버 데이터 수신
     ↓
DOM 다시 변경
     ↓
...
```

그래서 현대 웹 애플리케이션의 화면은 고정된 HTML 파일이 아니라 **계속 변화하는 DOM 상태**를 기반으로 만들어질 수 있습니다.

---

# 30. DOM 전체를 하나의 흐름으로 이해하기

DOM을 다음 흐름으로 기억하면 대부분의 개념이 연결됩니다.

```text
                 HTTP Response
                       │
                       ▼
                  HTML Text
                       │
                       ▼
                 HTML Parser
                       │
                       ▼
                 DOM Objects
                       │
              ┌────────┴────────┐
              │                 │
          Document            Nodes
                                │
                    ┌───────────┼───────────┐
                    │           │           │
                 Element       Text       Comment
                    │
               HTMLElement
                    │
          ┌─────────┼──────────┐
          │         │          │
        div       button      input
```

그리고 JavaScript는:

```text
JavaScript
    │
    ├── 탐색
    ├── 읽기
    ├── 생성
    ├── 변경
    ├── 삭제
    └── 이벤트 등록
           │
           ▼
         DOM
           │
           ▼
    Browser Rendering
           │
           ▼
         Screen
```

이라는 방식으로 DOM과 상호작용합니다.

# 핵심 정리

DOM을 단순히

> "HTML을 트리로 만든 것"

이라고 기억하면 부족합니다.

보다 정확한 이해는 다음과 같습니다.

> **DOM(Document Object Model)은 HTML/XML과 같은 문서를 브라우저와 프로그램이 다룰 수 있도록 `Document`, `Element`, `Text` 등의 객체(Node) 구조로 표현하는 표준화된 문서 모델이며, 그 객체들을 탐색·생성·수정·삭제하고 이벤트를 처리할 수 있는 API를 제공한다.**

그리고 브라우저 관점에서 보면:

```text
HTML
 ↓
Parsing
 ↓
DOM 생성
 ↓
JavaScript가 DOM API로 접근
 ↓
DOM 상태 변경
 ↓
브라우저 렌더링 과정에 반영
 ↓
화면 변화
```

가 DOM의 핵심 흐름입니다.

마지막으로 반드시 구분해야 할 것은 다음 네 가지입니다.

```text
HTML
= 문서를 기술하는 마크업

DOM
= 현재 문서를 표현하는 객체 모델 + API

JavaScript
= DOM API를 사용할 수 있는 프로그래밍 언어

Rendering
= DOM과 CSS 등의 정보를 이용하여 실제 화면을 만드는 브라우저 과정
```

이 네 가지를 분리해서 이해하면 이후의 **CSSOM, Render Tree, Event Propagation, JavaScript Event Loop, React Virtual DOM**까지 자연스럽게 연결됩니다.
