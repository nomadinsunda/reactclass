웹브라우저의 **`window` 객체**를 제대로 이해하려면 단순히 "`alert()`가 들어 있는 객체" 정도가 아니라, **브라우저에서 실행되는 JavaScript가 브라우저 환경과 연결되는 최상위 객체**라고 이해하는 것이 좋습니다.

특히 DOM, BOM, 전역 변수, 이벤트 루프를 배우기 전에 `window`를 잡아두면 이후 내용이 상당히 자연스럽게 연결됩니다.

# 1. `window` 객체란?

브라우저에서 JavaScript가 실행될 때 브라우저는 해당 웹페이지를 위한 **전역 실행 환경(Global Environment)**을 제공합니다.

이 환경에서 가장 대표적인 전역 객체가 바로:

```javascript
window
```

입니다.

쉽게 표현하면:

```text
Browser
│
└── Window
     │
     ├── document
     ├── location
     ├── history
     ├── navigator
     ├── console
     │
     ├── alert()
     ├── setTimeout()
     ├── setInterval()
     ├── fetch()
     │
     └── ...
```

따라서 `window`는 **현재 브라우징 컨텍스트의 JavaScript 전역 객체 역할을 하면서, 브라우저가 제공하는 다양한 Web API로 접근하는 출발점**이라고 볼 수 있습니다.

---

# 2. 가장 먼저 알아야 할 것: `window`는 브라우저가 제공한다

다음 JavaScript를 생각해봅시다.

```javascript
console.log(window);
```

Chrome 같은 브라우저에서 실행하면 거대한 객체가 출력됩니다.

그 안에는 우리가 자주 사용하는 것들이 들어 있습니다.

```javascript
window.document
window.location
window.history
window.navigator

window.alert()
window.setTimeout()
window.setInterval()
window.fetch()
```

여기서 중요한 것은 이런 기능들이 **JavaScript 언어 자체의 기능은 아니라는 것**입니다.

예를 들어:

```javascript
setTimeout()
fetch()
document
location
```

등은 ECMAScript 언어 자체가 정의하는 기능이 아니라 **브라우저 실행 환경이 제공하는 Web API**입니다.

즉,

```text
JavaScript Language
        +
Browser Environment
        ↓
브라우저에서 사용하는 JavaScript
```

라고 생각하는 것이 좋습니다.

---

# 3. `window`는 전역 객체(Global Object)다

일반적인 브라우저의 classic script에서 `window`는 전역 객체입니다.

그래서 다음 두 코드는 사실상 같은 대상을 호출합니다.

```javascript
window.alert("Hello");
```

```javascript
alert("Hello");
```

`alert`를 그냥 호출할 수 있는 이유는 `alert`가 전역에서 접근 가능하기 때문입니다.

마찬가지로:

```javascript
window.setTimeout(() => {
    console.log("Hello");
}, 1000);
```

보통은 다음처럼 사용합니다.

```javascript
setTimeout(() => {
    console.log("Hello");
}, 1000);
```

따라서 학생들이 보는 코드:

```javascript
alert()
setTimeout()
fetch()
```

앞에는 사실 개념적으로 `window.`를 생각해볼 수 있습니다.

다만 모든 전역 이름을 단순히 "`window`의 프로퍼티를 생략한 것"이라고 설명하면 이후 `let`, `const`, ES Module에서 문제가 생깁니다. 이 부분은 뒤에서 구분하겠습니다.

---

# 4. `window.document`가 DOM으로 연결된다

`window`를 배울 때 가장 중요한 프로퍼티 중 하나가:

```javascript
window.document
```

입니다.

`document`는 현재 페이지의 **Document 객체**, 즉 DOM 트리의 진입점입니다.

예를 들어 브라우저가 다음 HTML을 읽었다고 합시다.

```html
<!DOCTYPE html>
<html>
<head>
    <title>Hello</title>
</head>
<body>
    <h1 id="title">Hello</h1>
</body>
</html>
```

브라우저는 HTML을 파싱하여 DOM을 만듭니다.

개념적으로:

```text
window
  │
  └── document
        │
        └── html
             ├── head
             │    └── title
             │
             └── body
                  └── h1
```

JavaScript에서는:

```javascript
window.document.getElementById("title");
```

이라고 접근할 수 있습니다.

하지만 `document`가 전역에서 접근 가능하므로 보통:

```javascript
document.getElementById("title");
```

이라고 작성합니다.

그래서 정확한 관계는:

```text
window
   ↓
document
   ↓
DOM Tree
   ↓
html
   ↓
body
   ↓
h1, div, button ...
```

입니다.

여기서 아주 중요한 구분이 생깁니다.

**`window`와 DOM은 같은 것이 아닙니다.**

`document`가 DOM에 접근하는 핵심 객체이고, `window`는 그 `document`를 포함하여 훨씬 넓은 브라우저 환경을 제공합니다.

---

# 5. Window와 Document의 차이

초보자가 가장 많이 혼동하는 부분입니다.

```text
window
  │
  ├── document ──→ HTML / DOM
  │
  ├── location
  ├── history
  ├── navigator
  ├── setTimeout()
  ├── alert()
  └── ...
```

따라서:

**Window**

```text
브라우저의 브라우징 컨텍스트와 연결된 전역 객체
```

**Document**

```text
현재 로드된 HTML/XML 문서를 표현하는 DOM 객체
```

라고 구분하면 됩니다.

예를 들어:

```javascript
window.location
```

은 현재 페이지의 URL과 관련된 객체입니다.

반면:

```javascript
document.body
```

는 현재 HTML 문서의 `<body>` 요소를 나타냅니다.

# 6. window와 BOM

전통적인 교육에서는 브라우저가 제공하는 객체들을 **BOM(Browser Object Model)**이라는 이름으로 묶어서 설명하기도 합니다.

대표적으로:

```text
window
 ├── location
 ├── history
 ├── navigator
 ├── screen
 └── ...
```

### location

현재 페이지 URL과 관련됩니다.

```javascript
console.log(window.location.href);
```

또는:

```javascript
console.log(location.href);
```

페이지 이동도 가능합니다.

```javascript
location.href = "/login";
```

---

### history

브라우저 방문 기록과 관련됩니다.

```javascript
history.back();
history.forward();
history.go(-1);
```

---

### navigator

브라우저 환경과 관련된 정보를 제공합니다.

```javascript
console.log(navigator.userAgent);
console.log(navigator.language);
```

---

### screen

사용자의 화면과 관련된 정보를 제공합니다.

```javascript
console.log(screen.width);
console.log(screen.height);
```

---

# 7. window와 전역 변수의 관계

여기서 중요한 JavaScript 규칙이 등장합니다.

classic script의 전역 영역에서 `var`로 변수를 선언해봅시다.

```html
<script>
var name = "Alice";

console.log(name);
console.log(window.name);
</script>
```

전역 `var` 선언은 전역 객체의 프로퍼티와 연결됩니다.

따라서 이런 관계를 관찰할 수 있습니다.

```javascript
var age = 20;

console.log(window.age); // 20
```

하지만 `let`과 `const`는 다릅니다.

```javascript
let score = 100;
const PI = 3.14;

console.log(window.score); // undefined
console.log(window.PI);    // undefined
```

이것이 매우 중요합니다.

```text
classic script의 전역 영역

var
 ↓
전역 객체(window)의 property와 연결

let / const
 ↓
전역 선언으로 존재하지만
window의 property가 되지는 않음
```

따라서 단순히

> 모든 전역 변수는 `window`에 들어간다.

라고 가르치면 정확하지 않습니다.

---

# 8. 왜 `let`과 `const`는 window에 안 들어가는가?

ECMAScript의 전역 환경은 단순히 `window` 객체 하나만으로 설명되지 않습니다.

개념적으로는 **Global Environment Record**가 있고 내부적으로 전역 선언을 서로 다른 방식으로 관리합니다.

교육용으로 단순화하면:

```text
Global Environment
│
├── Object 쪽
│    │
│    └── 전역 var / 전역 함수 선언 등
│          ↓
│        window와 연결
│
└── Declarative 쪽
     │
     └── let / const / class
          ↓
        window property가 아님
```

그래서:

```javascript
var a = 10;
let b = 20;
const c = 30;
```

일 때:

```javascript
window.a  // 10
window.b  // undefined
window.c  // undefined
```

가 됩니다.

이 부분은 나중에 **호이스팅, TDZ, 실행 컨텍스트**를 설명할 때 굉장히 중요합니다.

# 9. `window.window`는 무엇인가?

재미있는 코드가 있습니다.

```javascript
console.log(window.window);
```

결과는 다시 `window`입니다.

즉:

```javascript
window.window === window
```

결과:

```javascript
true
```

입니다.

또한:

```javascript
window.self === window
```

도 일반적으로:

```javascript
true
```

입니다.

즉 `window` 객체는 자신을 가리키는 프로퍼티도 가지고 있습니다.

```text
window
 │
 ├── window ─────┐
 ├── self ───────┤
 │               │
 └───────────────┘
      자기 자신
```

# 10. `this`와 window

classic script의 최상위 레벨에서는 다음을 확인할 수 있습니다.

```html
<script>
console.log(this === window);
</script>
```

결과는:

```javascript
true
```

입니다.

하지만 여기서도 주의해야 합니다.

ES Module:

```html
<script type="module">
    console.log(this);
</script>
```

에서는 top-level `this`가:

```javascript
undefined
```

입니다.

따라서:

```text
classic script
top-level this
      ↓
    window

ES Module
top-level this
      ↓
   undefined
```

로 구분해야 합니다.

# 11. `globalThis`는 왜 생겼을까?

JavaScript는 브라우저에서만 실행되는 언어가 아닙니다.

환경에 따라 전역 객체에 접근하는 방식이 달랐습니다.

```text
Browser
   ↓
window

Web Worker
   ↓
self

다른 JavaScript 환경
   ↓
각 환경별 전역 객체
```

그래서 표준화된 방법으로 전역 객체에 접근할 수 있도록:

```javascript
globalThis
```

가 도입되었습니다.

브라우저의 일반적인 페이지에서는:

```javascript
globalThis === window
```

가 `true`입니다.

따라서 현대 JavaScript에서는 **환경 독립적으로 전역 객체를 가리켜야 한다면 `globalThis`**를 사용하는 것이 더 적절합니다.


처럼 사용할 수 있습니다.

# 13. window와 이벤트

`window` 자체도 이벤트를 받을 수 있습니다.

예를 들어:

```javascript
window.addEventListener("resize", () => {
    console.log("브라우저 크기가 변경되었습니다.");
});
```

브라우저 viewport 크기가 바뀌면 콜백이 호출됩니다.

또:

```javascript
window.addEventListener("scroll", () => {
    console.log("스크롤 발생");
});
```

등도 가능합니다.

여기에서도 구조를 보면:

```text
window
  │
  └── addEventListener()
          │
          └── callback 등록
```

이라는 관계입니다.

---

# 14. window와 setTimeout 그리고 이벤트 루프

이 부분은 `window`를 Promise/비동기 수업과 연결할 때 중요합니다.

```javascript
console.log("A");

setTimeout(() => {
    console.log("B");
}, 1000);

console.log("C");
```

`setTimeout()`은 JavaScript 엔진이 타이머를 직접 세면서 Call Stack에서 기다리는 함수가 아닙니다.

브라우저 환경이 타이머 기능을 제공합니다.

개념적으로:

```text
JavaScript
Call Stack
    │
    │ setTimeout(callback, 1000)
    ↓
Browser Web API
    │
    │ timer
    │ 1 second
    ↓
Task Queue
    │
    ↓
Event Loop
    │
    ↓
Call Stack
    │
    ↓
callback()
```

따라서 `window`를 이해하면:

```javascript
setTimeout()
fetch()
addEventListener()
```

같은 기능들이 왜 순수 JavaScript 언어 기능과 구별되는지도 이해하기 쉬워집니다.

---

# 15. 중요한 주의점: `window`가 Web API를 "실행한다"고 보면 안 된다

> window 객체가 setTimeout을 실행한다.

완전히 틀렸다고 할 수는 없지만 내부 구조를 설명할 때는 부정확해질 수 있습니다.

더 좋은 표현은:

> 브라우저가 제공하는 `Window` 인터페이스를 통해 `setTimeout()` 같은 Web API에 JavaScript 코드가 접근할 수 있다.

입니다.

즉:

```text
JavaScript 코드
      │
      ↓
Window / Web API
      │
      ↓
Browser 내부 기능
```

이라고 이해하는 것이 더 좋습니다.

`window` 객체 자체가 브라우저 전체를 구현하고 있는 것은 아닙니다.

# 16. `window` 객체와 브라우저 창은 완전히 같은 말인가?

이것도 조금 조심해야 합니다.

초급 단계에서는:

> window = 브라우저 창

이라고 설명하기도 합니다.

직관적으로는 도움이 되지만 정확하게는 부족합니다.

더 정확하게는:

> `Window` 객체는 브라우저의 **브라우징 컨텍스트에 노출되는 전역 객체**이며, 문서와 브라우저 기능에 접근할 수 있는 인터페이스를 제공한다.

라고 보는 것이 좋습니다.

그래서 한 브라우저에 탭이 여러 개 있다면 각 페이지의 JavaScript 실행 환경도 서로 분리되어 있습니다.

```text
Browser
│
├── Tab A
│    └── Window
│         └── Document A
│
├── Tab B
│    └── Window
│         └── Document B
│
└── Tab C
     └── Window
          └── Document C
```

iframe까지 들어가면 각각 별도의 browsing context와 `Window`가 존재할 수 있습니다.

# 17. 전체 구조를 한 번에 정리하면

웹 개발 입문 수업에서는 다음 그림이 가장 중요합니다.

```text
┌──────────────────────────────────────────┐
│               WEB BROWSER                │
│                                          │
│   ┌──────────────────────────────────┐   │
│   │             window               │   │
│   │       Global Object 역할          │   │
│   │                                  │   │
│   │  ┌─────────────┐                 │   │
│   │  │  document   │                 │   │
│   │  └──────┬──────┘                 │   │
│   │         ↓                        │   │
│   │      DOM Tree                    │   │
│   │         │                        │   │
│   │     html                         │   │
│   │     ├─ head                      │   │
│   │     └─ body                      │   │
│   │         ├─ div                   │   │
│   │         └─ button                │   │
│   │                                  │   │
│   │  location     history            │   │
│   │  navigator    screen             │   │
│   │                                  │   │
│   │  setTimeout()                    │   │
│   │  setInterval()                   │   │
│   │  fetch()                         │   │
│   │  addEventListener()              │   │
│   │  alert()                         │   │
│   └──────────────────────────────────┘   │
│                                          │
└──────────────────────────────────────────┘
```

핵심은 **`window → document → DOM`이라는 계층 관계**와, `document` 이외에도 `window`를 통해 브라우저 환경의 다양한 기능에 접근한다는 것입니다.

---

> **`window` 객체는 브라우저에서 웹페이지의 JavaScript가 실행될 때 제공되는 전역 객체로, 현재 문서(`document`)와 URL(`location`), 방문 기록(`history`), 타이머(`setTimeout`), 네트워크 요청(`fetch`) 등 브라우저가 제공하는 다양한 Web API에 접근할 수 있게 해주는 최상위 객체이다.**

그리고 세 줄로 압축하면:

```text
window
   ├── document → DOM → HTML 요소
   ├── location / history / navigator ...
   └── setTimeout / fetch / alert ...
```
