
서버사이드 렌더링(SSR: Server Side Rendering)은 현대 웹 개발에서 **성능 향상**과 \*\*검색 엔진 최적화(SEO)\*\*를 위해 자주 사용되는 중요한 개념입니다.
React, Vue 등 **SPA(단일 페이지 애플리케이션)** 프레임워크와 함께 등장하면서 \*\*CSR(클라이언트 사이드 렌더링)\*\*과 SSR의 차이는 반드시 이해해야 할 주제입니다.

---

## ✅ 서버사이드 렌더링(SSR)이란?

> \*\*SSR(Server Side Rendering)\*\*이란, 웹 페이지의 HTML을 **브라우저가 아니라 서버에서 먼저 생성**해서 클라이언트(브라우저)로 전달하는 방식입니다.

즉,

```
[브라우저 요청] ──→ [서버가 HTML 생성] ──→ [브라우저에 HTML 전달 및 렌더링]
```

---

## ✅ 반대 개념: 클라이언트사이드 렌더링(CSR)

> CSR은 HTML, JS, CSS를 먼저 받은 뒤, 브라우저가 **JS로 화면을 렌더링**합니다.

```
[브라우저 요청] ──→ [서버는 빈 HTML + JS 전달] ──→ [브라우저가 JS 실행하여 화면 구성]
```

---

## ✅ 예시 비교

### 🔸 클라이언트 사이드 렌더링 (CSR)

```html
<!-- index.html -->
<html>
  <body>
    <div id="root"></div> <!-- 비어 있음 -->
    <script src="bundle.js"></script> <!-- JS가 이 div에 컴포넌트 삽입 -->
  </body>
</html>
```

* 화면이 보이기까지 시간이 걸림
* JS가 꺼져 있으면 아무것도 보이지 않음
* 검색엔진이 내용을 읽기 어려움

---

### 🔹 서버 사이드 렌더링 (SSR)

```html
<!-- 서버에서 생성한 HTML -->
<html>
  <body>
    <div id="root">
      <h1>안녕하세요, 사용자님!</h1>
    </div>
    <script src="bundle.js"></script> <!-- 이후 JS가 활성화됨 -->
  </body>
</html>
```

* 서버가 렌더링한 HTML을 브라우저에 즉시 전달
* **초기 로딩 속도 개선**
* **SEO에 유리**

---

## ✅ SSR의 장점

| 장점               | 설명                                |
| ---------------- | --------------------------------- |
| ⏱️ 초기 로딩 속도 개선   | 사용자가 기다리지 않고 바로 HTML 콘텐츠 확인 가능    |
| 🔍 SEO 최적화       | 크롤러가 정적인 HTML을 읽을 수 있음 (검색 노출 향상) |
| 🧑‍💻 콘텐츠 가시성 향상 | JS가 꺼진 환경에서도 기본 콘텐츠 제공 가능         |

---

## ✅ SSR의 단점

| 단점             | 설명                                |
| -------------- | --------------------------------- |
| 🖥️ 서버 부하 증가   | 모든 요청에 대해 서버가 HTML을 생성하므로 부담 ↑    |
| ⚙️ 구현 복잡도 ↑    | 클라이언트와 서버 모두에서 React 코드 실행 필요     |
| 📦 초기 JS 번들 지연 | Hydration 필요 (JS 활성화)까지 약간의 지연 가능 |

---

## ✅ SSR을 사용하는 대표 프레임워크

| 프레임워크                    | 설명                              |
| ------------------------ | ------------------------------- |
| **Next.js (React 기반)**   | 가장 널리 쓰이는 SSR 프레임워크             |
| **Nuxt.js (Vue 기반)**     | Vue.js의 SSR 대응 프레임워크            |
| **Remix**                | React 기반. 최신 SSR + SPA 통합 프레임워크 |
| **Nest.js (서버)** + React | SSR을 수동 구성할 수도 있음               |

---

## ✅ SSR과 CSR 통합: Hydration

* SSR로 생성된 HTML은 **정적일 뿐, 이벤트 바인딩이 없음**
* React는 이후 `bundle.js`를 통해 이 HTML에 다시 **"생명을 불어넣음"** → 이를 **Hydration**이라 부릅니다.

```tsx
// 클라이언트에서 실행됨
ReactDOM.hydrate(<App />, document.getElementById('root'));
```

---

## ✅ SSR vs CSR vs SSG vs ISR

| 방식      | 설명                          | 대표 기술                      |
| ------- | --------------------------- | -------------------------- |
| **CSR** | JS로 브라우저에서 화면 구성            | CRA, Vite, React 등         |
| **SSR** | HTML을 서버에서 생성 후 전송          | Next.js                    |
| **SSG** | 미리 정적인 HTML을 빌드 시 생성        | Next.js (`getStaticProps`) |
| **ISR** | SSG + 동적 업데이트 (Incremental) | Next.js 12+                |

---

## ✅ 결론

> ✔️ **SSR은 React 등의 컴포넌트를 서버에서 HTML로 렌더링하여 브라우저에 보내는 방식**입니다.
> ✔️ 이를 통해 **초기 로딩 속도, SEO, 사용자 경험**을 크게 개선할 수 있습니다.
> ❗단, 구현 복잡도와 서버 부하에 대한 고려가 필요합니다.
